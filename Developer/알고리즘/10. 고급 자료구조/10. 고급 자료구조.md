# Summary

<summary>고급 자료구조는 특정 문제를 효율적으로 해결하기 위한 전문화된 도구입니다. 세그먼트 트리(구간 쿼리 O(log N)), 펜윅 트리(누적 합 O(log N)), 트라이(문자열 검색 O(M)), Union-Find(집합 관리 O(α(N))), 균형 이진 탐색 트리(동적 정렬 O(log N))가 있으며, 각각의 특성을 이해하고 상황에 맞게 선택하는 것이 중요합니다.</summary>

# Notes

<aside>세그먼트 트리</aside>

**Segment Tree** - 구간에 대한 쿼리를 효율적으로 처리하는 트리 구조

**기본 개념:**
- 배열의 구간을 트리 노드로 표현
- 각 노드는 특정 구간의 정보를 저장 (합, 최솟값, 최댓값 등)
- 리프 노드: 개별 원소
- 내부 노드: 자식들의 정보를 병합

**트리 구조:**
- 완전 이진 트리 형태
- 높이: ⌈log N⌉
- 노드 개수: 4N (넉넉하게)

**기본 연산:**

1. **Build (구축):** O(N)
   - 리프 노드부터 시작해 상향식으로 구축
   - 각 노드는 자식들의 값을 병합

2. **Query (구간 쿼리):** O(log N)
   - 구간 [L, R]의 값을 구함
   - 트리를 탐색하며 필요한 노드들만 방문
   - 최대 log N개의 노드 방문

3. **Update (값 갱신):** O(log N)
   - 특정 위치의 값을 변경
   - 리프부터 루트까지 경로의 모든 노드 갱신

**Lazy Propagation (지연 전파):**
- 구간 업데이트를 O(log N)에 처리
- 업데이트를 즉시 수행하지 않고 나중에 필요할 때 전파
- Lazy 배열에 미뤄진 업데이트 저장

**시간 복잡도:**
- Build: O(N)
- Query: O(log N)
- Update: O(log N)
- Range Update (Lazy): O(log N)

**공간 복잡도:** O(4N) = O(N)

**활용 사례:**
- 구간 합 쿼리 (Range Sum Query)
- 구간 최솟값/최댓값 쿼리 (RMQ)
- 구간 GCD/LCM
- 구간 업데이트 + 구간 쿼리

<aside>펜윅 트리</aside>

**Fenwick Tree (Binary Indexed Tree, BIT)** - 누적 합을 효율적으로 관리하는 자료구조

**기본 개념:**
- 세그먼트 트리의 경량화 버전
- 각 인덱스가 특정 구간의 합을 저장
- 이진수의 마지막 1비트를 활용

**핵심 아이디어:**
- 인덱스 i는 (i - (i & -i) + 1)부터 i까지의 구간 합 저장
- i & -i: 가장 오른쪽 1비트 추출 (lowbit)

**기본 연산:**

1. **Update (값 갱신):** O(log N)
   - 특정 위치에 값을 더함
   - 해당 위치와 관련된 모든 구간 갱신
   ```
   while (i <= N) {
       tree[i] += val;
       i += (i & -i);
   }
   ```

2. **Query (prefix sum):** O(log N)
   - 1부터 i까지의 누적 합
   ```
   while (i > 0) {
       sum += tree[i];
       i -= (i & -i);
   }
   ```

3. **Range Query:** O(log N)
   - [L, R] 구간 합 = query(R) - query(L-1)

**시간 복잡도:**
- Update: O(log N)
- Query: O(log N)
- Build: O(N log N) 또는 O(N) (최적화 시)

**공간 복잡도:** O(N)

**세그먼트 트리 vs 펜윅 트리:**

**펜윅 트리 장점:**
- 구현이 매우 간단 (코드 10줄 내외)
- 메모리 효율적 (N개만 필요)
- 상수 계수가 작아 실전에서 빠름

**세그먼트 트리 장점:**
- 더 범용적 (최솟값, 최댓값, GCD 등)
- Lazy Propagation 가능
- 구간 업데이트 지원

**선택 기준:** 누적 합 문제면 펜윅, 그 외는 세그먼트 트리

<aside>트라이</aside>

**Trie (Prefix Tree)** - 문자열 집합을 효율적으로 저장하고 검색하는 트리

**기본 개념:**
- 각 노드가 하나의 문자를 나타냄
- 루트에서 특정 노드까지의 경로가 하나의 문자열
- 공통 접두사를 공유하는 문자열들이 같은 경로 사용

**노드 구조:**
- 자식 노드 포인터 배열 (알파벳 26개)
- 문자열의 끝을 나타내는 플래그
- 선택적: 해당 노드까지의 문자열 개수

**기본 연산:**

1. **Insert (삽입):** O(M)
   - M: 문자열 길이
   - 문자를 하나씩 따라가며 노드 생성

2. **Search (검색):** O(M)
   - 문자를 하나씩 따라가며 존재 확인
   - 끝 플래그 확인

3. **StartsWith (접두사 검색):** O(M)
   - 해당 접두사로 시작하는 문자열 존재 여부

4. **Delete (삭제):** O(M)
   - 역순으로 탐색하며 필요 없는 노드 제거

**시간 복잡도:**
- Insert/Search/Delete: O(M)
- M: 문자열 길이, N과 무관!

**공간 복잡도:** O(ALPHABET_SIZE × N × M)
- 최악의 경우 매우 큼
- 압축 트라이(Compressed Trie)로 최적화 가능

**활용 사례:**
- 자동 완성 (Auto-complete)
- 철자 검사 (Spell Checker)
- IP 라우팅 테이블
- 사전 구현
- 문자열 집합에서 XOR 최댓값 찾기

**변형:**
- **Compressed Trie (Radix Tree):** 단일 자식만 있는 노드들을 압축
- **Suffix Trie:** 모든 접미사를 저장
- **Ternary Search Tree:** 메모리 최적화 버전

<aside>Union-Find</aside>

**Disjoint Set Union (DSU)** - 서로소 집합을 효율적으로 관리

**기본 개념:**
- 원소들을 여러 개의 분리된 집합으로 관리
- 각 집합은 대표 원소(root)로 식별
- 트리 구조로 구현

**핵심 연산:**

1. **Make-Set:** O(1)
   - 새로운 집합 생성
   - 자기 자신이 부모

2. **Find:** O(α(N))
   - 원소가 속한 집합의 대표 찾기
   - 경로 압축으로 최적화

3. **Union:** O(α(N))
   - 두 집합을 하나로 합침
   - Union by Rank/Size로 최적화

**최적화 기법:**

**1. 경로 압축 (Path Compression)**
```cpp
int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]); // 재귀적으로 압축
    return parent[x];
}
```
- Find 수행 시 경로상 모든 노드를 루트에 직접 연결
- 트리 높이 감소

**2. Union by Rank**
```cpp
void union(int x, int y) {
    x = find(x);
    y = find(y);
    if (rank[x] < rank[y]) swap(x, y);
    parent[y] = x;
    if (rank[x] == rank[y]) rank[x]++;
}
```
- Rank(높이)가 작은 트리를 큰 트리 아래에 합침
- 트리의 균형 유지

**3. Union by Size**
- 크기가 작은 트리를 큰 트리 아래에 합침
- Rank 대신 Size 사용

**시간 복잡도:**
- 두 최적화를 함께 사용: O(α(N))
- α(N): 아커만 함수의 역함수, 실질적으로 상수
- N ≤ 10^600 일 때도 α(N) ≤ 4

**활용 사례:**
- 크루스칼 MST 알고리즘
- 네트워크 연결성 판단
- 동적 그래프의 연결 요소
- 이미지 처리 (연결된 컴포넌트)

<aside>균형 이진 탐색 트리</aside>

**Self-Balancing BST** - 삽입/삭제 후에도 균형을 유지하는 이진 탐색 트리

### AVL 트리

**균형 조건:**
- 모든 노드의 왼쪽/오른쪽 서브트리 높이 차이 ≤ 1
- Balance Factor = 왼쪽 높이 - 오른쪽 높이 ∈ {-1, 0, 1}

**회전 연산:**
1. **LL 회전 (Right Rotation)**
2. **RR 회전 (Left Rotation)**
3. **LR 회전 (Left-Right)**
4. **RL 회전 (Right-Left)**

**시간 복잡도:**
- Search/Insert/Delete: O(log N) 보장
- 높이: 1.44 log N

**특징:**
- 엄격한 균형 유지
- 검색이 매우 빠름
- 삽입/삭제 시 회전이 많을 수 있음

### Red-Black 트리

**균형 조건:**
1. 모든 노드는 빨강 또는 검정
2. 루트는 검정
3. 모든 리프(NIL)는 검정
4. 빨강 노드의 자식은 모두 검정
5. 모든 리프까지의 검정 노드 수가 동일

**시간 복잡도:**
- Search/Insert/Delete: O(log N)
- 높이: 2 log N

**특징:**
- AVL보다 느슨한 균형
- 삽입/삭제가 AVL보다 빠름
- C++ STL의 map, set에서 사용

**AVL vs Red-Black:**
- AVL: 검색 중심 (읽기가 많음)
- Red-Black: 삽입/삭제 중심 (쓰기가 많음)

### B-Tree

**특징:**
- 각 노드가 여러 개의 키를 가짐
- 디스크 기반 데이터베이스에 적합
- 모든 리프가 같은 레벨

**활용:**
- 데이터베이스 인덱스
- 파일 시스템

<aside>실전 선택 가이드</aside>

**문제 유형별 자료구조 선택:**

1. **구간 합 쿼리 + 값 업데이트**
   → 펜윅 트리 (간단하고 빠름)

2. **구간 최솟값/최댓값 + 값 업데이트**
   → 세그먼트 트리

3. **구간 업데이트 + 구간 쿼리**
   → 세그먼트 트리 with Lazy Propagation

4. **문자열 검색, 자동 완성**
   → 트라이

5. **집합 합치기, 연결성 판단**
   → Union-Find

6. **동적 정렬, 순서 통계**
   → 균형 이진 탐색 트리 또는 C++ multiset

**구현 난이도:**
1. 펜윅 트리 (가장 쉬움)
2. Union-Find
3. 트라이
4. 세그먼트 트리
5. 균형 이진 탐색 트리 (가장 어려움)

**팁:**
- 코딩 테스트에서는 STL 활용 권장
- 펜윅 트리는 반드시 손코딩 가능하게
- 세그먼트 트리 템플릿 준비 필수
- Union-Find는 외워서 빠르게 작성

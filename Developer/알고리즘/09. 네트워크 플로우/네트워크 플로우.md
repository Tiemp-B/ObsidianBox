# Summary

<summary>네트워크 플로우는 용량이 있는 방향 그래프에서 출발점에서 도착점으로 보낼 수 있는 최대 유량을 구하는 문제입니다. 포드-풀커슨(기본), 에드몬드-카프(BFS), 디닉(레벨 그래프) 알고리즘으로 해결하며, 이분 매칭 문제로 변환 가능합니다. 최대 유량 = 최소 컷 정리가 핵심입니다.</summary>

# Notes

<aside>네트워크 플로우 기본 개념</aside>

**네트워크 플로우(Network Flow)**는 방향 그래프에서 각 간선에 용량(capacity)이 있을 때, 출발점(source)에서 도착점(sink)으로 보낼 수 있는 최대 유량(flow)을 구하는 문제입니다.

**핵심 용어:**
- **용량(Capacity) c(u,v):** 간선 (u,v)에 흐를 수 있는 최대 유량
- **유량(Flow) f(u,v):** 실제로 흐르고 있는 양
- **잔여 용량(Residual Capacity):** c(u,v) - f(u,v)
- **증가 경로(Augmenting Path):** source에서 sink까지 잔여 용량이 양수인 경로
- **역간선(Backward Edge):** 유량을 취소할 수 있도록 하는 가상의 간선

**유량 네트워크의 제약 조건:**

1. **용량 제약:** 0 ≤ f(u,v) ≤ c(u,v)
2. **유량 보존:** source와 sink를 제외한 모든 정점에서 들어오는 유량 = 나가는 유량
3. **대칭성:** f(u,v) = -f(v,u)

<aside>포드-풀커슨 알고리즘</aside>

**Ford-Fulkerson Algorithm** - 증가 경로를 반복적으로 찾는 기본 알고리즘

**알고리즘 과정:**
1. 모든 간선의 유량을 0으로 초기화
2. 증가 경로를 찾음 (DFS 또는 BFS)
3. 증가 경로가 존재하면:
   - 경로상의 최소 잔여 용량을 계산
   - 해당 경로의 모든 간선에 유량 추가
   - 역간선에 음의 유량 추가 (취소 가능하게)
4. 더 이상 증가 경로가 없을 때까지 2-3 반복

**역간선의 중요성:**
- 이미 보낸 유량을 취소할 수 있게 해줌
- 최적해를 찾는 데 필수적
- 실제 그래프에는 없지만 알고리즘 상에서 관리

**시간 복잡도:** O(E × |f*|)
- E: 간선 수, |f*|: 최대 유량 값
- 유량 값에 의존하므로 실수 가중치에서는 종료 보장 안됨
- 정수 용량이면 종료 보장

**단점:**
- 증가 경로를 비효율적으로 선택하면 느려짐
- 최악의 경우 매우 작은 유량씩 증가

<aside>에드몬드-카프 알고리즘</aside>

**Edmonds-Karp Algorithm** - BFS로 최단 증가 경로를 찾는 개선 버전

**핵심 개선:**
- DFS 대신 BFS를 사용하여 간선 수가 최소인 증가 경로 선택
- 유량 값에 무관한 시간 복잡도 보장

**알고리즘 과정:**
1. BFS로 source에서 sink까지의 최단 경로 탐색
2. 경로가 존재하면 병목 용량만큼 유량 증가
3. 경로가 없을 때까지 반복

**시간 복잡도:** O(VE²)
- 증가 경로는 최대 O(VE)번 찾음
- 각 BFS: O(E)
- 유량 값과 무관하게 다항 시간 보장

**장점:**
- 정수 용량뿐만 아니라 실수 용량에서도 작동
- 구현이 비교적 간단
- 안정적인 성능 보장

<aside>디닉 알고리즘</aside>

**Dinic's Algorithm** - 레벨 그래프를 활용한 고속 알고리즘

**핵심 아이디어:**
1. **레벨 그래프(Level Graph):** BFS로 각 정점까지의 최단 거리 계산
2. **블로킹 플로우(Blocking Flow):** 레벨 그래프에서 더 이상 증가 경로를 찾을 수 없을 때까지 유량 전송

**알고리즘 과정:**
1. BFS로 레벨 그래프 구축
2. 레벨 그래프에서 DFS로 블로킹 플로우 찾기
3. 블로킹 플로우를 찾으면 유량 증가
4. 레벨 그래프가 더 이상 만들어지지 않을 때까지 반복

**최적화 기법:**
- **현재 간선 포인터:** 각 정점에서 이미 확인한 간선은 다시 확인하지 않음
- **레벨 제약:** 레벨이 정확히 1 증가하는 간선만 사용

**시간 복잡도:** O(V²E)
- 일반 그래프: O(V²E)
- 단위 용량 네트워크: O(E × min(V^(2/3), E^(1/2)))
- 이분 그래프: O(E√V)

**장점:**
- 실전에서 가장 빠른 성능
- 특수한 경우 더 나은 복잡도
- 현대적 구현에서 선호됨

<aside>이분 매칭</aside>

**Bipartite Matching** - 이분 그래프에서 최대 매칭을 찾는 문제

**이분 그래프:**
- 정점을 두 그룹으로 나눌 수 있음
- 같은 그룹 내의 정점끼리는 간선이 없음

**매칭:**
- 간선들의 집합으로, 어떤 두 간선도 정점을 공유하지 않음
- 최대 매칭: 간선 개수가 최대인 매칭

**최대 유량으로 변환:**
1. Source를 왼쪽 그룹의 모든 정점에 연결 (용량 1)
2. 오른쪽 그룹의 모든 정점을 Sink에 연결 (용량 1)
3. 원래 간선들의 용량을 1로 설정
4. 최대 유량 = 최대 매칭의 크기

**호프크로프트-카프(Hopcroft-Karp) 알고리즘:**
- 이분 매칭 전용 최적화 알고리즘
- 시간 복잡도: O(E√V)

**실전 응용:**
- 구직자-회사 매칭
- 학생-프로젝트 할당
- 택시-승객 배정

<aside>최대 유량 - 최소 컷 정리</aside>

**Max-Flow Min-Cut Theorem** - 네트워크 플로우의 핵심 정리

**컷(Cut):**
- 그래프의 정점을 source 그룹과 sink 그룹으로 분할
- 컷의 용량: source 그룹에서 sink 그룹으로 가는 간선 용량의 합

**정리 내용:**
**최대 유량의 값 = 최소 컷의 용량**

**증명 아이디어:**
1. 최대 유량 ≤ 최소 컷 (유량은 컷을 넘을 수 없음)
2. 최대 유량을 구한 후 잔여 그래프에서 source로부터 도달 가능한 정점들로 컷 구성
3. 이 컷의 용량 = 최대 유량

**실전 활용:**
- 네트워크 병목 구간 찾기
- 최소 비용으로 네트워크 분리
- 이미지 분할 (Graph Cut)

<aside>실전 활용 및 변형</aside>

**전형적인 문제 유형:**

**1. 기본 최대 유량**
- 파이프 네트워크, 통신 네트워크
- 예: 백준 6086번 - 최대 유량

**2. 이분 매칭**
- 직원 배치, 자원 할당
- 예: 백준 11375번 - 열혈강호

**3. 최소 컷 응용**
- 네트워크 분할, 클러스터링
- 예: 이미지 세그멘테이션

**4. 최소 비용 최대 유량 (MCMF)**
- 비용이 있는 간선에서 최대 유량을 최소 비용으로
- SPFA, 벨만-포드 활용

**5. 상한/하한이 있는 유량**
- 최소 유량 제약이 있는 경우
- Circulation 문제

**구현 팁:**
- 인접 리스트 + 구조체로 간선 관리
- 역간선은 짝수/홀수 인덱스로 관리 (XOR 1)
- 방문 배열은 매 반복마다 초기화 필요

**최적화:**
- 다중 source/sink는 가상의 super source/sink 추가
- 정점 용량 제약은 정점을 둘로 분할
- 양방향 간선은 각 방향으로 별도 간선 생성

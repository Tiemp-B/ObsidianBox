# Summary
이진 탐색(Binary Search)은 **정렬된 배열에서 중간값을 기준으로 탐색 범위를 절반씩 줄여가며**  
목표 값을 찾는 효율적인 탐색 알고리즘이다.  
시간 복잡도는 `O(log n)`이며, **정렬된 데이터**에서만 사용할 수 있다.

# Notes

이진 탐색은 “절반씩 줄이기(divide by two)” 원리를 이용해 빠른 탐색을 수행한다.  
탐색 대상이 정렬되어 있다는 가정이 필수적이다.

<aside>정의</aside>

이진 탐색(Binary Search)은 정렬된 리스트에서  
탐색 구간의 **중앙값(mid)** 을 기준으로 비교하여  
탐색 범위를 왼쪽 또는 오른쪽 절반으로 줄이는 알고리즘이다.

---

<aside>동작 과정</aside>

1. 배열의 **중간 인덱스(mid)** 를 계산한다.  
2. 찾는 값(target)이 중간값보다 작으면 왼쪽 구간으로,  
   크면 오른쪽 구간으로 탐색 범위를 이동한다.  
3. 범위를 반복적으로 절반으로 줄이다가  
   중간값이 목표 값과 같으면 탐색 성공,  
   범위가 소진되면 탐색 실패로 종료한다.

---

<aside>특징</aside>

- **전제 조건:** 데이터가 **오름차순 또는 내림차순으로 정렬**되어 있어야 함.  
- **탐색 범위 절반 축소:** 한 번 비교할 때마다 탐색 공간이 `1/2`로 줄어듦.  
- **시간 복잡도:** `O(log n)`  
- **공간 복잡도:** 반복문 방식 `O(1)`, 재귀 방식 `O(log n)`  
- **비교 기반 탐색 알고리즘**

---

<aside>변형 형태</aside>

- **Lower Bound:** 주어진 값 이상이 처음 나타나는 위치 탐색  
- **Upper Bound:** 주어진 값보다 큰 값이 처음 나타나는 위치 탐색  
- **이진 탐색 트리(Binary Search Tree)** 에서 노드 비교 구조로 확장 가능  

---

<aside>장점</aside>

- 매우 빠른 탐색 속도 (`O(log n)`)  
- 비교 횟수가 적어 대규모 데이터에서도 효율적  
- 구현이 간단하고 반복적 구조로 최적화 가능  

---

<aside>단점</aside>

- 반드시 **정렬된 데이터**여야 함  
- 데이터 삽입·삭제 시 정렬 유지 비용 발생 (`O(n)`)  
- 연결 리스트(Linked List) 구조에는 비효율적  

---

<aside>응용 분야</aside>

- **탐색 최적화:** 사전, 데이터베이스 인덱스, 정렬된 로그 검색  
- **결정 문제 해결:** “특정 조건을 만족하는 최소/최대값 찾기” 문제  
- **알고리즘 설계 패턴:** “이분 탐색(Binary Search on Answer)” 기법  
  → 예: 매개변수 탐색, 최적화 문제 (e.g., 최소 예산, 최대 거리 계산 등)

---

<aside>핵심 목표</aside>

이진 탐색의 핵심은 **“탐색 공간을 절반씩 줄여 최소한의 비교로 목표를 찾는 것”**이다.  
즉, 정렬된 데이터에서 **로그 시간 복잡도(logarithmic time)** 를 달성하는 대표 탐색 알고리즘이다.

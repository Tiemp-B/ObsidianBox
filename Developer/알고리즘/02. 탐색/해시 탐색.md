# Summary
해시 탐색(Hash Search)은 **해시 함수(Hash Function)** 를 사용해  
데이터의 키(Key)를 해시 테이블의 인덱스로 직접 변환하여 검색하는 방식이다.  
탐색 평균 시간 복잡도는 `O(1)`이며, 충돌(Collision)을 처리하기 위한 별도의 기법이 필요하다.

# Notes

해시 탐색은 키를 이용해 데이터를 거의 즉시 찾을 수 있도록 설계된 탐색 알고리즘이다.  
배열 기반의 **해시 테이블(Hash Table)** 자료구조에 데이터를 저장하고 검색한다.

<aside>정의</aside>

해시 탐색(Hash Search)은 키 값(Key)을 **해시 함수(Hash Function)** 에 입력하여  
테이블의 인덱스(Index)로 변환하고, 그 위치에서 데이터를 직접 찾는 탐색 방식이다.  
즉, 키 → 인덱스 → 데이터 의 단계를 통해 빠른 접근을 구현한다.

---

<aside>동작 원리</aside>

1. 해시 함수 `h(key)`를 이용해 키를 테이블의 인덱스로 변환한다.  
2. 해당 인덱스 위치에 데이터를 저장하거나 검색한다.  
3. 동일한 인덱스가 여러 키에 대응하는 경우(충돌 발생)에는  
   별도의 **충돌 해결(Collision Resolution)** 기법을 사용한다.  

---

<aside>해시 함수(Hash Function)</aside>

- 입력된 키를 특정 크기의 테이블 인덱스로 변환하는 함수.  
- 예시:  
  - 나눗셈법(Division Method): `h(key) = key mod m`  
  - 곱셈법(Multiplication Method): `h(key) = floor(m * (key * A mod 1))`  
  - 문자열 해시: 각 문자의 ASCII 값을 조합하여 계산.  
- 이상적인 해시 함수는 키들을 **균등하게 분포**시켜 충돌을 최소화한다.

---

<aside>충돌(Collision)과 해결 방법</aside>

해시 탐색에서 가장 중요한 문제는 서로 다른 키가 같은 인덱스로 매핑되는 충돌이다.  
이를 해결하는 대표적인 방법은 다음과 같다.

1. **체이닝(Chaining)**  
   - 같은 인덱스에 여러 개의 데이터를 **연결 리스트(Linked List)** 로 저장.  
   - 탐색 시 해당 버킷 내에서 선형 탐색 수행 (`O(k)`).

2. **개방 주소법(Open Addressing)**  
   - 충돌 발생 시 테이블 내의 다른 비어 있는 슬롯을 찾음.  
   - 종류:  
     - **선형 탐사(Linear Probing):** `h(key) + i`  
     - **이차 탐사(Quadratic Probing):** `h(key) + i²`  
     - **이중 해싱(Double Hashing):** `h1(key) + i * h2(key)`

---

<aside>시간 복잡도</aside>

| 경우 | 복잡도 |
|------|--------|
| 평균 | O(1) |
| 최악 | O(n) (충돌이 심한 경우) |

공간 복잡도: `O(n)`  
충돌이 최소화된 이상적인 환경에서는 탐색 속도가 상수 시간에 가까움.

---

<aside>특징</aside>

- **비교 기반 탐색이 아님** — 키를 직접 인덱스로 변환.  
- **데이터 정렬이 필요 없음.**  
- **탐색, 삽입, 삭제 모두 평균 O(1)** 성능.  
- **충돌 관리가 성능의 핵심 요인.**  
- **테이블 크기(m)** 와 **부하율(Load Factor)** 이 성능에 직접 영향.  

---

<aside>응용 분야</aside>

- **데이터베이스 인덱스**  
- **컴파일러 심볼 테이블(Symbol Table)**  
- **캐시(Cache) 시스템**  
- **해시 맵(HashMap), 딕셔너리(Dictionary)** 구조 구현  

---

<aside>장점</aside>

- 평균적으로 가장 빠른 탐색 성능(`O(1)`)  
- 데이터 정렬 불필요, 삽입/삭제도 빠름  
- 큰 데이터셋에서도 높은 효율성 유지  

---

<aside>단점</aside>

- 충돌 관리가 복잡하며, 성능 저하 가능  
- 메모리 낭비 발생 가능 (공간 효율성 ↓)  
- 해시 함수 설계에 따라 성능 편차 큼  
- 순서가 유지되지 않음 (정렬 불가)

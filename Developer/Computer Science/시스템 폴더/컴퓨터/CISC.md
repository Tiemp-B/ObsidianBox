# Summary
CISC(Complex Instruction Set Computer)는 다양한 복잡한 명령어를 제공하여  
하나의 명령으로 여러 연산을 수행할 수 있게 하는 CPU 설계 방식이다.  
명령어의 수가 많고 구조가 복잡하지만, 코드 길이를 줄이고 고급 언어와의 대응이 용이하다.  
대표 예시는 **Intel x86 아키텍처**다.

# Notes

CISC는 하드웨어 중심의 설계 철학으로,  
복잡한 명령어를 통해 소프트웨어 부담을 줄이는 것을 목표로 한다.  
즉, “적은 코드로 많은 일을 수행하는 CPU 구조”이다.

<aside>정의</aside>

CISC(Complex Instruction Set Computer)는  
**한 개의 명령어로 다단계 연산을 수행할 수 있는 복잡한 명령어 집합 구조(ISA)** 를 갖는 컴퓨터 구조다.  
명령어의 길이, 실행 시간, 피연산자 수가 가변적이며,  
하드웨어가 많은 기능을 직접 처리한다.

---

<aside>특징</aside>

- **명령어 수가 많고 복잡함** — 수백 개 이상의 다양한 명령어 지원.  
- **가변 길이 명령어 (Variable-length Instruction)** — 각 명령의 길이가 다름.  
- **다양한 주소 지정 방식 지원** — 직접, 간접, 인덱스, 베이스 등 복잡한 메모리 접근 가능.  
- **마이크로코드(Microcode) 기반 제어** — 하드웨어 내부에서 복잡한 명령을 단계별로 처리.  
- **한 명령어로 여러 연산 수행 가능** — 예: 메모리 접근 + 산술 연산 + 저장.  
- **명령어 수 감소로 코드 밀도(Code Density) 향상** — 동일 연산을 적은 코드로 표현.  

---

<aside>장점</aside>

1. **프로그래밍 단순화** — 복잡한 연산을 단일 명령으로 수행 가능.  
2. **메모리 효율성** — 명령어 개수가 적어 코드 크기 감소.  
3. **고급 언어(High-level Language)와의 대응 용이성** — 컴파일러 구현이 간단.  
4. **레거시 호환성** — 하위 버전과의 명령어 호환성이 유지되어 지속적인 확장 가능.

---

<aside>단점</aside>

1. **하드웨어 복잡도 증가** — 명령어 디코딩과 실행 제어 회로가 복잡함.  
2. **파이프라이닝 효율 저하** — 명령 길이와 실행 시간이 일정하지 않아 병렬 처리 어려움.  
3. **불균일한 명령 실행 시간** — 단순 명령과 복잡 명령의 실행 시간이 크게 다름.  
4. **성능 예측 어려움** — 명령어별 실행 사이클 차이로 인한 최적화 한계.

---

<aside>예시 아키텍처</aside>

- **Intel x86 / x86-64** — 대표적인 CISC 구조.  
- **VAX (DEC)** — 고전적인 완전형 CISC CPU.  
- **Motorola 68000** — 1980년대 범용 CISC 프로세서.

---

<aside>현대적 관점</aside>

- 현대 CPU는 CISC 구조(x86 계열)이지만,  
  **내부적으로는 RISC형 마이크로옵(micro-op)** 으로 변환하여 실행한다.  
  → 즉, “겉은 CISC, 속은 RISC” 구조(Hybrid Architecture).  
- 이는 **CISC의 명령어 호환성과 RISC의 효율성**을 동시에 확보하기 위한 설계이다.

---

<aside>핵심 목표</aside>

CISC의 목표는 **복잡한 명령어로 소프트웨어의 구현 부담을 줄이고,  
메모리 공간을 절약하며, 코드 효율성을 극대화하는 것**이다.

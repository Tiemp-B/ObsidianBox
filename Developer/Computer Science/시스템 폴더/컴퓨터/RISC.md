# Summary
RISC(Reduced Instruction Set Computer)는 단순하고 규칙적인 명령어 집합을 사용해  
하드웨어의 효율성과 실행 속도를 극대화하는 CPU 설계 방식이다.  
모든 명령어를 일정한 크기와 실행 시간으로 통일하여 파이프라이닝에 최적화되어 있다.  
대표 예시는 **ARM, MIPS, RISC-V** 구조다.

# Notes

RISC는 “단순한 명령어를 빠르게 실행하자”는 철학으로,  
CISC의 복잡한 명령어 구조를 단순화하여 **고성능·고효율 CPU 설계**를 실현한다.

<aside>정의</aside>

RISC(Reduced Instruction Set Computer)는  
**명령어를 단순화하고, 일정한 형식으로 구성해 하드웨어 실행 효율을 높인 CPU 구조**다.  
모든 명령이 **한 클럭 주기 내에 실행되도록** 설계되어 파이프라인 효율이 높다.

---

<aside>특징</aside>

- **단순하고 규칙적인 명령어 구조 (Fixed-Length Instruction)**  
  → 명령어 해석이 빠르고 예측 가능함.  
- **Load/Store 구조**  
  → 메모리 접근은 LOAD/STORE 명령만 허용, 나머지는 레지스터 간 연산.  
- **한 클럭 당 한 명령 실행 (1 CPI 구조)**  
  → 파이프라이닝 효율 극대화.  
- **레지스터 중심 설계**  
  → 연산 대부분을 레지스터 내부에서 수행.  
- **하드웨어 단순화**  
  → 제어 회로가 단순하고, 명령어 디코딩이 빠름.  
- **컴파일러 친화적 설계**  
  → 명령어 구조가 단순해 최적화된 코드 생성이 용이함.

---

<aside>장점</aside>

1. **파이프라이닝 효율 향상** — 명령어 길이와 실행 시간이 일정함.  
2. **하드웨어 단순화** — 명령 해석 및 제어 회로 복잡도 감소.  
3. **고속 처리 가능** — 단순 연산으로 클럭 주파수 상승 용이.  
4. **전력 효율 높음** — 모바일 및 임베디드 시스템에 적합.  
5. **예측 가능한 실행 시간** — 실시간 시스템 설계에 유리.

---

<aside>단점</aside>

1. **명령어 개수 증가** — 동일한 작업 수행에 더 많은 명령 필요.  
2. **코드 길이 증가** — CISC보다 프로그램 크기가 큼.  
3. **메모리 접근 빈도 증가** — LOAD/STORE 구조로 인한 메모리 연산 분리.  
4. **복잡한 명령은 소프트웨어로 처리해야 함** — 하드웨어 부담 감소 대신 컴파일러 부담 증가.

---

<aside>예시 아키텍처</aside>

- **ARM (Advanced RISC Machine)** — 모바일, 임베디드 시장의 대표 RISC 아키텍처.  
- **MIPS (Microprocessor without Interlocked Pipeline Stages)** — 학습 및 네트워크 장비용.  
- **RISC-V** — 오픈소스 RISC 구조, 확장성과 연구·산업적 활용이 활발.  
- **SPARC, PowerPC** — 서버 및 워크스테이션용 고전적 RISC 구조.

---

<aside>현대적 발전 방향</aside>

- 현대 CPU는 **RISC 기반의 내부 마이크로아키텍처**를 채택함.  
  (예: Intel x86도 내부적으로 RISC형 micro-op으로 변환 후 실행)  
- RISC 구조는 **파이프라이닝·병렬 처리·저전력 설계**에 최적화되어  
  스마트폰, 임베디드 시스템, AI 프로세서 등에서 표준이 되었다.  

---

<aside>핵심 목표</aside>

RISC의 목표는 **명령어 구조를 단순화하여 실행 효율을 극대화하고,  
파이프라이닝과 병렬 처리 성능을 향상시키는 것**이다.

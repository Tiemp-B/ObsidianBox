# Summary

RSA는 공개키 암호 방식의 대표 알고리즘으로, 큰 소수의 곱인 N의 인수분해가 어려운 점을 기반으로 한다.  
키 교환, 전자서명, 인증서 기반 통신(TLS 등)에서 널리 활용되며, 공개키와 개인키를 사용해 암호화·복호화 또는 서명·검증을 수행한다.

# Notes

<aside>RSA 개요</aside>  

RSA는 Rivest, Shamir, Adleman이 1977년 개발한 **비대칭키(공개키) 암호 알고리즘**이다.  
보안성은 **큰 수의 소인수분해(Factoring)** 가 계산적으로 어려운 문제에 기반한다.  
핵심 개념: 공개키는 누구나 알 수 있지만, 개인키는 비밀로 유지된다.

<aside>키 생성 과정</aside>  

RSA 키는 다음 절차로 생성된다.  
1. 큰 소수 p, q 선택  
2. N = p × q 계산  
3. 오일러 피함수 φ(N) = (p − 1)(q − 1) 계산  
4. 공개 지수 e 선택 (일반적으로 65537 사용)  
5. e × d ≡ 1 mod φ(N) 을 만족하는 d 계산  
6. **공개키 (e, N)**, **개인키 (d, N)** 생성  

N은 모듈러스이며, 키 길이는 일반적으로 2048~4096bit가 사용된다.

<aside>암호화와 복호화</aside>  

RSA는 비대칭 구조로 동작한다.

- **암호화**:  
  C = M^e mod N  
- **복호화**:  
  M = C^d mod N  

단, 실제 데이터 암호화에는 느리므로,  
대칭키 교환(예: TLS 1.2의 RSA 키 교환)에 주로 사용된다.

<aside>전자 서명</aside>  

RSA는 서명·검증에도 사용된다.

- **서명**: S = H(M)^d mod N  
- **검증**: H(M) ?= S^e mod N  

이를 통해 데이터 위변조 방지와 송신자 인증이 가능하다.  
디지털 인증서(X.509)에서도 RSA 공개키가 사용된다.

<aside>PADDING (중요)</aside>  

보안 강화를 위해 RSA는 패딩 방식이 필수다.  
- PKCS#1 v1.5  
- OAEP (가장 안전한 현대적 방식)  
- PSS (서명용 패딩)  

패딩 없이 RSA를 사용하면 공격에 매우 취약하다.

<aside>보안성</aside>  

RSA의 안전성은  
- 소수 p, q의 크기  
- N의 인수분해 난이도  
에 달려 있다.

현재 권장:  
- 2048bit RSA: 실용적 보안  
- 3072~4096bit: 장기 보안  

양자컴퓨터 등장 시 Shor 알고리즘으로 취약하므로  
**포스트 양자 암호(PQC)** 로의 전환이 진행 중이다.

<aside>사용 사례</aside>  

- TLS/HTTPS 인증서  
- SSH 키  
- 전자 서명  
- 코드 서명  
- 보안 토큰, PKI 시스템  

<aside>핵심 정리</aside>  

- RSA는 소인수분해 문제 기반 공개키 암호 방식  
- 암호화·복호화, 서명·검증 모두 가능  
- 패딩(OAEP, PSS)이 필수  
- TLS, 인증서, 보안 프로토콜에서 광범위하게 사용  
- 양자 시대에는 PQC로 전환 필요

# Summary

  

C++ 스마트 포인터(Smart Pointer)는 `<memory>` 헤더에 정의된 **RAII 기반 포인터 래퍼 클래스**다. 원시 포인터(raw pointer)를 감싸 동적 메모리의 수명을 자동으로 관리하며, 메모리 누수·댕글링 포인터·이중 해제 등 고전적 메모리 버그를 구조적으로 방지한다. C++11에서 `unique_ptr`, `shared_ptr`, `weak_ptr` 세 가지가 표준으로 도입되었고, 기존의 `auto_ptr`은 C++17에서 완전히 제거되었다.

# Notes

<aside>도입 배경 — 왜 필요한가</aside>

C++에서 `new`로 할당한 메모리는 반드시 `delete`로 해제해야 한다. 이 수동 관리 방식은 다음과 같은 버그를 유발한다.

| 문제 | 설명 |
|------|------|
| **메모리 누수** | `delete` 호출을 빠뜨려 메모리가 해제되지 않음 |
| **댕글링 포인터** | 이미 해제된 메모리를 가리키는 포인터 사용 |
| **이중 해제** | 같은 포인터에 `delete`를 두 번 호출 |
| **예외 안전성 부재** | 예외 발생 시 `delete`가 건너뛰어져 누수 발생 |

  
스마트 포인터는 스코프를 벗어날 때 자동으로 소멸자를 호출해 이 문제를 **구조적으로** 해결한다.

  

---

  

<aside>unique_ptr — 단독 소유권</aside>

  

하나의 `unique_ptr`만이 객체를 소유할 수 있다. 스코프를 벗어나면 자동으로 삭제된다.

  

**핵심 특성:**

- 복사 불가 (copy constructor 삭제됨)

- `std::move()`로 소유권 이전 가능

- **오버헤드 없음**: raw pointer와 동일한 크기(8 bytes), 동일한 성능 → **Zero-cost abstraction**

  

```cpp

// 생성 (make_unique 권장, C++14~)
auto ptr = std::make_unique<MyClass>(args);

// 소유권 이전
auto ptr2 = std::move(ptr); // ptr은 nullptr이 됨
  
// 소유권 해제 및 재설정
ptr2.reset();        // 메모리 즉시 해제
ptr2.reset(new MyClass()); // 새 객체로 교체

```


**사용 시기:** 객체의 소유자가 단 하나인 경우 (가장 일반적인 케이스)

---

<aside>shared_ptr — 공유 소유권</aside>

여러 `shared_ptr`이 동일 객체를 공유 소유할 수 있다. 내부적으로 **참조 카운팅(Reference Counting)**을 사용한다.

**핵심 특성:**
- 참조 카운트가 0이 되면 자동 삭제
- `use_count()`로 현재 참조 수 확인 가능
- **오버헤드 있음**: 포인터 2개 크기(객체 포인터 + 컨트롤 블록 포인터), 원자적(atomic) 참조 카운트 연산으로 멀티스레드 안전


```cpp

// 생성 (make_shared 권장 — 메모리 할당 1회로 최적화)
auto p1 = std::make_shared<MyClass>();
auto p2 = p1;               // 참조 카운트: 2
std::cout << p1.use_count(); // 2 출력

// p1, p2 소멸 시 참조 카운트 0 → 자동 삭제

```

**컨트롤 블록(Control Block):** shared_ptr 소유 수(shared count), weak_ptr 수(weak count), 커스텀 삭제자 등을 저장하는 힙 구조체

**사용 시기:** 여러 곳에서 동시에 객체를 소유해야 할 때 (캐시, 이벤트 시스템 등)

---

<aside>weak_ptr — 비소유 참조</aside>

`shared_ptr`이 관리하는 객체를 **소유권 없이** 참조한다. 참조 카운트를 증가시키지 않는다.

**핵심 특성:**
- 단독으로 역참조 불가 → 반드시 `lock()`으로 `shared_ptr`로 변환 후 사용
- `lock()` 호출 시 객체가 이미 소멸되었으면 `nullptr` 반환
- **순환 참조(Circular Reference) 방지**에 핵심적으로 사용

```cpp

auto sp = std::make_shared<MyClass>();
std::weak_ptr<MyClass> wp = sp;

if (auto locked = wp.lock()) { // 객체가 살아있는지 확인
    locked->doSomething();
} // locked 소멸 시 참조 카운트 복원

```


**순환 참조 문제와 해결:**
```
// 문제: A → B → A (서로 shared_ptr로 참조 → 참조 카운트 절대 0이 안 됨 → 메모리 누수)
struct A { std::shared_ptr<B> b_ptr; };
struct B { std::shared_ptr<A> a_ptr; }; // ❌ 순환 참조

// 해결: 한쪽을 weak_ptr로 변경
struct B { std::weak_ptr<A> a_ptr; };   // ✅
```

---

<aside>세 가지 비교 요약</aside>

| 구분 | `unique_ptr` | `shared_ptr` | `weak_ptr` |
|------|-------------|-------------|------------|
| 소유권 | 단독 | 공유 | 없음(비소유) |
| 복사 | ❌ 불가 | ✅ 가능 | ✅ 가능 |
| 이동 | ✅ 가능 | ✅ 가능 | ✅ 가능 |
| 참조 카운트 | 없음 | 있음(shared) | 있음(weak only) |
| 메모리 크기 | 포인터 1개 | 포인터 2개 | 포인터 2개 |
| 오버헤드 | **없음** | atomic 연산 | lock() 시 atomic |
| 주 용도 | 일반적 단일 소유 | 공유 소유 | 순환 참조 방지, 관찰자 패턴 |

---

<aside>auto_ptr — 구버전 (사용 금지)</aside>

C++03에서 도입된 최초의 스마트 포인터. **C++11에서 deprecated, C++17에서 완전 제거.**

문제점: 복사 시 소유권이 이전되어 원본이 `nullptr`이 되는 **불안전한 복사 의미론** → STL 컨테이너에서 사용 시 심각한 버그 유발 가능

<aside>사용 권고사항</aside>

  

1. **`unique_ptr` 우선**: 공유 소유가 필요 없다면 항상 `unique_ptr` 사용. `shared_ptr`보다 가볍다

2. **`make_unique` / `make_shared` 사용**: `new` 직접 호출보다 안전하고 효율적

3. **같은 raw pointer로 두 개의 `shared_ptr` 초기화 금지** → 이중 해제 발생

4. **`auto_ptr` 절대 사용 금지**: 이미 표준에서 제거됨

5. **`weak_ptr`로 순환 참조 차단**: 양방향 참조 구조에서 한쪽은 반드시 `weak_ptr`

6. **`weak_ptr` 역참조 전 반드시 `lock()` 확인**: 객체 소멸 여부 체크 필수

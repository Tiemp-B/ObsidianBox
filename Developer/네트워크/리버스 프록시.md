# Summary

리버스 프록시는 클라이언트 요청을 대신 받아 **백엔드 서버로 전달하고 응답을 반환하는 중간 서버**이다.  
로드 밸런싱, 보안, 캐싱, 서버 은닉 등 다양한 역할을 수행하며 Nginx, Apache, HAProxy 등이 대표적인 구현체다.

# Notes

<aside>리버스 프록시 개념</aside>  

리버스 프록시는 클라이언트가 직접 백엔드 서버에 접근하지 않고,  
대신 프록시 서버가 요청을 받아 내부 서버로 전달하는 구조다.  
사용자는 실제 백엔드 IP·구조를 알 필요 없이 프록시만 바라본다.  
웹 서비스, 마이크로서비스, 보안 게이트웨이에서 필수적으로 사용된다.

<aside>리버스 프록시의 동작 방식</aside>  

1. 사용자가 리버스 프록시(예: Nginx)에 요청  
2. 프록시가 라우팅 규칙에 따라 내부 서버 선택  
3. 백엔드 서버가 처리 후 프록시로 응답 반환  
4. 프록시가 응답을 클라이언트에 전달  

이 과정에서 SSL 종료, 캐싱, 인증, 헤더 추가 등 다양한 기능을 수행할 수 있다.

<aside>주요 기능</aside>  

- **로드 밸런싱**  
  Round-robin, least connections 등 알고리즘으로 트래픽 분산  

- **보안 강화**  
  - 백엔드 IP 숨김  
  - DDoS 완화  
  - Web Application Firewall(WAF) 적용 가능  

- **캐싱**  
  정적 자원 캐싱으로 서버 부하 감소  

- **SSL/TLS 종료(Termination)**  
  프록시에서 암호화/복호화 처리  

- **압축, 헤더 조작**  
  요청/응답 최적화 및 공통 정책 적용  

<aside>리버스 프록시 vs 포워드 프록시</aside>  

| 구분 | 리버스 프록시 | 포워드 프록시 |
|------|----------------|----------------|
| 목적 | 서버 보호·로드관리 | 클라이언트 보호·익명성 |
| 배치 위치 | 서버 앞 | 클라이언트 앞 |
| 사용 예 | Nginx, HAProxy | 회사 내부 프록시, VPN |

리버스 프록시는 서버 중심,  
포워드 프록시는 클라이언트 중심 사용을 목적으로 한다.

<aside>대표 구현체</aside>  

- **Nginx** — 정적 파일 처리, 로드 밸런싱, SSL 처리에 최적화  
- **HAProxy** — 고성능 로드 밸런서  
- **Apache httpd** — 모듈 기반 확장성  
- **Traefik** — Docker/Kubernetes 친화적  
- **Envoy Proxy** — 서비스 메시(Service Mesh) 기반 현대적 프록시  

<aside>사용 사례</aside>  

- 웹 서버 앞단의 트래픽 관리  
- Docker Compose 또는 Kubernetes에서 서비스 라우팅  
- 하나의 IP로 여러 서비스(도메인) 운영  
- HTTPS termination (SSL offloading)  
- CDN처럼 캐싱을 통한 고속 응답 제공  

<aside>핵심 정리</aside>  

리버스 프록시는 **서버의 전면 게이트웨이** 역할을 수행하며  
보안, 성능, 확장성을 동시에 확보할 수 있는 핵심 구성 요소다.  
현대적 웹 아키텍처에서 프론트 게이트 역할로 반드시 사용된다.

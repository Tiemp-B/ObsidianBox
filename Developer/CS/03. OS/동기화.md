# Summary

동기화(Synchronization)는 **공유 자원 접근 시 실행 순서와 데이터 일관성을 보장하는 기법**이며,  
교착상태(Deadlock)는 **두 개 이상의 프로세스가 서로 자원을 점유한 채 대기하여 더 이상 진행되지 않는 상태**이다.  
즉, 잘못된 동기화 관리로 인해 교착상태가 발생할 수 있다.

| 구분 | 동기화 | 교착상태 |
|------|---------|----------|
| 목적 | 공유 자원의 안전한 접근 | 자원 대기 무한 정체 방지 |
| 문제 | 경쟁 상태(Race Condition) | 자원 순환 대기 |
| 원인 | 병렬 실행 중 접근 충돌 | 락의 잘못된 사용 |
| 해결 | 세마포어, 뮤텍스, 모니터 | 예방, 회피, 탐지, 복구 |
| 관계 | 올바른 동기화는 교착상태를 방지 | 잘못된 동기화는 교착상태 유발 |

# Notes

<aside>동기화의 개념</aside>

동기화는 여러 프로세스나 스레드가 **공유 자원(변수, 파일, 메모리 등)에 접근할 때 발생할 수 있는 경쟁 상태를 방지**하기 위한 기법이다.  
임계 구역(Critical Section)을 정의하고, **상호 배제(Mutual Exclusion)** 를 통해 한 번에 하나의 실행 단위만 접근하도록 제어한다.

동기화의 목표는 다음과 같다.  
1. **상호 배제:** 한 시점에 하나의 실행 단위만 자원 접근  
2. **진행:** 자원이 비어 있을 경우 대기 없이 접근 가능  
3. **한정 대기:** 특정 프로세스가 무한히 대기하지 않도록 보장  

<aside>동기화의 구현 기법</aside>

- **하드웨어 기반:** Test-and-Set, Compare-and-Swap  
- **운영체제 기반:**  
  - **세마포어(Semaphore):** 카운터를 이용한 접근 제어 (P, V 연산)  
  - **뮤텍스(Mutex):** 하나의 스레드만 자원 접근 허용  
  - **모니터(Monitor):** 자원과 제어 로직을 함께 캡슐화  

이러한 동기화 기법은 자원의 안전한 접근을 보장하지만,  
동시에 잘못 사용하면 **교착상태**를 초래할 수 있다.

<aside>교착상태의 개념</aside>

교착상태(Deadlock)는 **두 개 이상의 프로세스가 서로 자원을 점유한 채,  
상대방이 점유한 자원을 기다리면서 무한히 대기하는 상황**이다.  
즉, 시스템이 더 이상 진행되지 않고 정체되는 상태이다.

예시:  
- 프로세스 A가 자원 X를 점유하고 자원 Y를 기다림  
- 프로세스 B가 자원 Y를 점유하고 자원 X를 기다림  
→ 두 프로세스 모두 영원히 대기 상태에 머무름  

<aside>교착상태 발생 조건 (Coffman의 네 가지 조건)</aside>

1. **상호 배제(Mutual Exclusion):**  
   한 자원은 한 번에 하나의 프로세스만 점유 가능  

2. **점유와 대기(Hold and Wait):**  
   자원을 가진 프로세스가 다른 자원을 기다림  

3. **비선점(No Preemption):**  
   자원을 강제로 회수할 수 없음  

4. **순환 대기(Circular Wait):**  
   여러 프로세스가 서로의 자원을 기다리는 순환 대기 형성  

이 네 조건이 모두 만족될 때 교착상태가 발생할 수 있다.  

<aside>교착상태의 해결 방법</aside>

1. **예방(Prevention):**  
   교착상태 발생 조건 중 하나 이상을 제거  
   - 자원 순환 대기 금지  
   - 자원 선점 허용  
   - 프로세스 시작 전 모든 자원 요청  

2. **회피(Avoidance):**  
   교착상태가 발생하지 않도록 시스템 상태를 동적으로 검사  
   - 대표적 알고리즘: **Banker’s Algorithm (은행원 알고리즘)**  

3. **탐지(Detection):**  
   교착상태 발생 후 이를 감지하고 해결  
   - 자원 할당 그래프(Resource Allocation Graph) 사용  

4. **복구(Recovery):**  
   교착상태 감지 후 프로세스 종료 또는 자원 회수  
   - 프로세스 강제 종료  
   - 자원 선점 후 재실행  

<aside>자원 할당 그래프(Resource Allocation Graph)</aside>

- 노드: 프로세스(P), 자원(R)  
- 간선: 요청(Request), 점유(Allocation)  
- 순환(Cycle)이 존재하면 교착상태 가능성이 있음  

<aside>동기화와 교착상태의 관계</aside>

동기화는 데이터의 정확성과 일관성을 보장하기 위해 필요하지만,  
잘못된 락(lock) 설계는 교착상태를 유발한다.  

예시:  
1. 프로세스 A가 락1을 획득하고 락2를 요청  
2. 프로세스 B가 락2를 획득하고 락1을 요청  
→ 서로의 락을 기다리며 교착상태 발생  

해결 방법:  
- 락의 획득 순서를 일관되게 유지  
- 타임아웃(time-out) 설정  
- 락 해제 순서 제어  

<aside>교착상태 예방을 위한 프로그래밍 습관</aside>

- 락 획득 순서를 전역적으로 일관되게 유지  
- 가능하면 락 범위를 최소화  
- 중첩 락(Nested Lock) 회피  
- 타임아웃 기반 락 사용  
- 교착상태 탐지 로깅 활성화

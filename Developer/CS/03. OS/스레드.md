# Summary

스레드(Thread)는 **프로세스 내에서 실행되는 최소 단위의 실행 흐름**이다.  
하나의 프로세스가 여러 스레드를 통해 병렬로 작업을 수행할 수 있으며,  
공유 메모리를 통해 빠르게 통신할 수 있지만 동기화 문제가 발생할 수 있다.

# Notes

<aside>스레드의 개념</aside>

스레드는 프로세스 내에서 **명령어를 순차적으로 실행하는 단일 실행 흐름**이다.  
프로세스가 자원(CPU 시간, 메모리 등)을 소유한다면,  
스레드는 그 자원을 이용하여 실제로 작업을 수행한다.  
즉, 하나의 프로세스 안에서 여러 스레드가 동시에 실행될 수 있다.

- **프로세스:** 자원 할당의 단위 (메모리, 파일 등)  
- **스레드:** CPU 실행의 단위 (명령어 흐름)  
- 한 프로세스 내의 스레드들은 **코드, 데이터, 힙을 공유**하지만 **스택은 독립적**이다.

---

<aside>스레드의 구성</aside>

스레드는 다음 정보를 포함한다.  
- **스레드 ID (TID)**  
- **프로그램 카운터 (PC)**  
- **레지스터 집합**  
- **스택(Stack)**  
- **상태(State):** 실행(Running), 준비(Ready), 대기(Waiting)  
- **공유 자원:** 코드(Code), 데이터(Data), 힙(Heap)

---

<aside>스레드의 장점</aside>

1. **응답성 향상:**  
   - 한 스레드가 대기 중일 때, 다른 스레드가 실행 가능  
2. **자원 절약:**  
   - 프로세스보다 생성/전환 비용이 낮음  
3. **효율적인 자원 공유:**  
   - 동일 프로세스 내 메모리 공간 공유  
4. **병렬 처리:**  
   - 멀티코어 환경에서 실제 병렬 수행 가능  

---

<aside>스레드의 단점</aside>

1. **동기화 문제:**  
   - 공유 자원 접근 시 경쟁 조건(Race Condition) 발생 가능  
2. **디버깅 어려움:**  
   - 실행 순서가 매번 달라 예측 불가  
3. **안정성 저하:**  
   - 하나의 스레드 오류가 전체 프로세스에 영향을 줄 수 있음  

---

<aside>스레드의 종류</aside>

- **커널 수준 스레드 (Kernel-Level Thread, KLT):**  
  - 운영체제 커널이 직접 관리  
  - 스케줄링과 관리가 독립적이지만 전환 비용이 큼  
- **사용자 수준 스레드 (User-Level Thread, ULT):**  
  - 사용자 영역의 라이브러리에서 관리  
  - 빠르지만 커널은 스레드 개별 인식 불가  
- **하이브리드 모델:**  
  - ULT와 KLT의 장점을 결합 (ex: 1:N, M:N 모델)

<aside>스레드 생성 및 동작</aside>

- **POSIX Threads (pthread):** UNIX 기반 표준 API  
  - `pthread_create()` : 스레드 생성  
  - `pthread_join()` : 스레드 종료 대기  
  - `pthread_exit()` : 스레드 종료  
- **Java Threads:**  
  - `Thread` 클래스 상속 또는 `Runnable` 인터페이스 구현  
  - `start()`, `run()`, `join()` 메서드 사용  

<aside>스레드 동기화(Synchronization)</aside>

다중 스레드 환경에서 공유 자원을 동시에 접근할 경우 충돌을 방지해야 한다.  
- **뮤텍스(Mutex):** 한 번에 하나의 스레드만 자원 접근 허용  
- **세마포어(Semaphore):** 동시 접근 가능한 스레드 수 제한  
- **모니터(Monitor):** 객체 단위의 동기화 기법 (Java `synchronized`)  
- **Critical Section:** 상호 배제가 필요한 코드 영역  

<aside>스레드 스케줄링</aside>

운영체제는 스레드 수준에서도 CPU를 효율적으로 분배한다.  
- **선점형(Preemptive):** 타 스레드가 실행 중이라도 높은 우선순위 스레드로 교체 가능  
- **비선점형(Non-Preemptive):** 실행 중인 스레드가 스스로 CPU를 양보해야 함  
- **스케줄링 기준:** 우선순위, 실행 시간, 입출력 대기 여부  

<aside>멀티스레딩(Multi-threading)</aside>

하나의 프로세스가 여러 스레드를 병렬로 실행하는 방식이다.  
- **모델:**  
  - **Many-to-One:** 여러 사용자 스레드 → 하나의 커널 스레드  
  - **One-to-One:** 하나의 사용자 스레드 ↔ 하나의 커널 스레드  
  - **Many-to-Many:** 여러 사용자 스레드 ↔ 여러 커널 스레드  
- **예시:**  
  - 웹 브라우저: UI, 렌더링, 네트워크 스레드 분리  
  - 서버: 클라이언트 요청마다 스레드 생성  

<aside>프로세스 vs 스레드</aside>

| 구분 | 프로세스 | 스레드 |
|------|-----------|---------|
| 정의 | 실행 중인 프로그램 | 프로세스 내 실행 흐름 단위 |
| 메모리 | 독립된 주소 공간 | 코드·데이터·힙 공유, 스택만 독립 |
| 생성 비용 | 높음 | 낮음 |
| 통신 | IPC 필요 | 공유 메모리로 직접 접근 |
| 안정성 | 높음 (격리 보장) | 낮음 (공유로 인한 영향) |

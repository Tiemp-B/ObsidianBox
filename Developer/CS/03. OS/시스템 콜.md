# Summary

시스템 콜(System Call)은 **사용자 프로그램이 운영체제의 서비스를 요청하기 위한 인터페이스**다.  
사용자 모드에서 실행되는 응용 프로그램은 직접 하드웨어에 접근할 수 없기 때문에,  
시스템 콜을 통해 [[커널]] 모드로 전환되어 자원 접근 및 제어를 수행한다.

# Notes

<aside>시스템 콜의 개념</aside>

시스템 콜은 **운영체제 커널과 사용자 프로그램 간의 통신 창구**다.  
프로그램이 CPU, 메모리, 파일, 네트워크 자원을 사용하기 위해서는 운영체제의 허락이 필요하며,  
이때 시스템 콜을 통해 커널 기능을 요청한다.  
트랩(Trap) 명령을 통해 커널 모드로 전환되고, 작업 수행 후 다시 사용자 모드로 복귀한다.

<aside>시스템 콜의 동작 과정</aside>

1. 사용자 프로그램이 라이브러리 함수를 호출 (예: read(), write())  
2. 라이브러리 함수가 시스템 콜 번호(System Call Number)를 커널에 전달  
3. CPU가 트랩 명령 실행 → 커널 모드로 전환  
4. 커널이 요청된 기능 수행 (예: 파일 열기, 데이터 읽기 등)  
5. 실행 결과를 사용자 모드로 반환  

<aside>시스템 콜의 주요 분류</aside>

- **프로세스 제어:** fork(), exec(), exit(), wait()  
  → 프로세스 생성, 실행, 종료 제어  
- **파일 조작:** open(), read(), write(), close()  
  → 파일 입출력 및 접근 권한 관리  
- **디바이스 관리:** ioctl(), read(), write()  
  → 입출력 장치 제어 및 버퍼 관리  
- **정보 유지:** getpid(), uname(), gettimeofday()  
  → 시스템 및 프로세스 정보 조회  
- **통신:** socket(), send(), recv(), pipe()  
  → 프로세스 간 통신 및 네트워크 통신 지원  
- **메모리 관리:** brk(), mmap()  
  → 동적 메모리 할당 및 가상 메모리 매핑  

<aside>시스템 콜과 라이브러리 함수의 차이</aside>

| 구분 | 시스템 콜 | 라이브러리 함수 |
|------|-------------|----------------|
| 정의 | 커널에 직접 요청 | 시스템 콜을 감싸는 사용자 인터페이스 |
| 실행 모드 | 커널 모드 | 사용자 모드 |
| 예시 | write(fd, buf, size) | printf() |
| 속도 | 느림 (모드 전환 발생) | 빠름 (일부 캐싱 가능) |

<aside>시스템 콜 호출 방식</aside>

- **소프트웨어 인터럽트 방식:** x86 아키텍처에서 `int 0x80` 명령 사용  
- **시스템 콜 명령어 방식:** 현대 리눅스에서 syscall 명령 사용  
- **시스템 콜 테이블:** 커널 내부의 시스템 콜 번호와 함수 포인터 목록  

<aside>리눅스에서의 예시</aside>

| 기능 | 시스템 콜 | 설명 |
|------|-------------|------|
| 파일 열기 | open() | 파일 디스크립터 반환 |
| 파일 읽기 | read() | 버퍼에 데이터 읽기 |
| 파일 쓰기 | write() | 데이터 출력 |
| 프로세스 생성 | fork() | 부모 프로세스 복제 |
| 프로그램 실행 | execve() | 새로운 프로그램 실행 |
| 종료 | exit() | 프로세스 종료 |
| 대기 | wait() | 자식 프로세스 종료 대기 |

<aside>시스템 콜의 역할과 중요성</aside>

- **자원 보호:** 사용자 프로그램의 비정상적인 자원 접근 차단  
- **표준화된 인터페이스 제공:** 하드웨어 구조와 무관한 통일된 접근 방식 제공  
- **안정성 확보:** 커널 모드와 사용자 모드의 명확한 분리  
- **추상화:** 복잡한 하드웨어 제어를 단순 명령으로 대체  

<aside>응용 및 활용 예시</aside>

- **파일 I/O:** 텍스트 편집기, 로그 시스템  
- **프로세스 관리:** 쉘, 백그라운드 프로세스  
- **네트워크 통신:** 웹 서버, 소켓 기반 애플리케이션  
- **시스템 관리:** 리소스 모니터링, 사용자 권한 제어

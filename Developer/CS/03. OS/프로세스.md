# Summary

프로세스(Process)는 **실행 중인 프로그램(Program in Execution)** 으로,  
운영체제가 CPU·메모리·입출력 자원을 할당하여 독립적으로 실행하는 단위다.  
프로세스는 코드, 데이터, 스택, 힙으로 구성되며, 상태 전이와 스케줄링을 통해 관리된다.

# Notes

<aside>프로세스의 개념</aside>

프로세스는 메모리에 적재되어 실행 중인 프로그램을 의미한다.  
각 프로세스는 독립된 주소 공간과 실행 문맥(Context)을 가지며,  
운영체제가 이를 관리하여 다중 작업 환경(Multitasking)을 가능하게 한다.  
즉, 프로세스는 **실행 단위의 기본 형태**로 CPU 자원을 직접 사용하는 존재이다.

---

<aside>프로세스의 구성 요소</aside>

- **코드(Code):** 실행할 명령어 집합  
- **데이터(Data):** 전역 변수, 정적 변수  
- **스택(Stack):** 함수 호출, 지역 변수 저장  
- **힙(Heap):** 동적 메모리 할당 영역  
- **PCB(Process Control Block):**  
  - 운영체제가 프로세스를 관리하기 위해 유지하는 정보 블록  
  - 내용: PID, 상태, 프로그램 카운터(PC), 레지스터 값, 스케줄링 정보 등

<aside>프로세스의 상태(State)</aside>

프로세스는 실행 중 상태에 따라 전이된다.  
1. **생성(New):** 생성 중  
2. **준비(Ready):** 실행 대기 중  
3. **실행(Running):** CPU에서 실행 중  
4. **대기(Waiting/Blocked):** I/O 등 이벤트 대기 중  
5. **종료(Terminated):** 실행 완료 후 소멸  
6. **지연(Suspended)**: 

상태 전이는 **스케줄러(Scheduler)** 와 **디스패처(Dispatcher)** 에 의해 제어된다.

---

<aside>프로세스 제어 블록(PCB)</aside>

운영체제가 각 프로세스를 추적·관리하기 위한 자료 구조이다.  
- **저장 정보:**  
  - PID (Process ID)  
  - 상태 정보 (State)  
  - 프로그램 카운터(PC)  
  - 레지스터 집합  
  - 메모리 관리 정보  
  - CPU 스케줄링 정보  
- 프로세스 전환(Context Switching) 시 PCB가 핵심 역할을 수행한다.

---

<aside>프로세스 스케줄링</aside>

운영체제는 다수의 프로세스가 동시에 실행되는 환경에서 CPU를 효율적으로 분배한다.  
- **장기 스케줄러(Long-term):** 프로세스를 메모리에 적재할지 결정  
- **단기 스케줄러(Short-term):** 다음 실행 프로세스 선택  
- **중기 스케줄러(Mid-term):** 프로세스를 일시 중단(Swap)할지 결정  
- **스케줄링 알고리즘:**  
  - FCFS, SJF, Priority, Round Robin, Multilevel Queue  

---

<aside>프로세스 계층 구조</aside>

- **부모 프로세스(Parent Process):** 새로운 프로세스를 생성한 주체  
- **자식 프로세스(Child Process):** 부모에 의해 fork()로 생성된 프로세스  
- **프로세스 생성 방식:**  
  - `fork()`: 복제 기반 생성 (UNIX/Linux)  
  - `exec()`: 새로운 프로그램으로 교체  
  - `wait()`: 자식 프로세스 종료 대기  

---

<aside>프로세스 간 통신(IPC)</aside>

프로세스는 독립적인 메모리 공간을 가지므로, 데이터 교환을 위해 별도의 통신이 필요하다.  
- **공유 메모리(Shared Memory):** 빠르지만 동기화 필요  
- **메시지 큐(Message Queue):** 커널 기반 메시지 교환  
- **파이프(Pipe):** 단방향 통신 (부모-자식 간)  
- **소켓(Socket):** 네트워크를 통한 통신  

---

<aside>컨텍스트 스위칭(Context Switching)</aside>

CPU가 한 프로세스에서 다른 프로세스로 전환될 때 발생하는 과정이다.  
- **저장:** 현재 프로세스의 PCB에 레지스터, PC, 상태 저장  
- **복원:** 다음 프로세스의 PCB에서 정보 복원  
- **오버헤드 발생:** 빈번한 전환은 시스템 성능 저하를 유발  

---

<aside>프로세스와 스레드의 차이</aside>

| 구분  | 프로세스                                | 스레드                 |
| --- | ----------------------------------- | ------------------- |
| 정의  | 실행 중인 프로그램                          | 프로세스 내의 실행 단위       |
| 메모리 | 독립적 주소 공간                           | 코드·데이터·힙 공유         |
| 통신  | IPC(Inter-Process Communication) 필요 | 공유 메모리로 빠름          |
| 안정성 | 한 프로세스 오류는 다른 프로세스에 영향 없음           | 한 스레드 오류가 전체에 영향 가능 |

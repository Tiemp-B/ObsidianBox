# Summary

메모리(Memory)는 **프로세스가 실행되는 동안 필요한 명령어와 데이터를 저장하는 공간**이다.  
운영체제는 메모리를 효율적으로 분배하고 보호하여 여러 프로세스가 동시에 안정적으로 실행되도록 관리한다.  
대표적인 기능은 주소 변환, 메모리 할당, 가상 메모리 관리, 페이지 교체 등이다.

| 구분 | 주요 기술 | 목적 |
|------|-------------|-------|
| 주소 변환 | MMU, 페이지 테이블 | 논리 ↔ 물리 주소 변환 |
| 메모리 할당 | 페이징, 세그멘테이션 | 효율적 공간 사용 |
| 가상 메모리 | 페이지 교체 알고리즘 | 메모리 확장성 확보 |
| 캐시 | LRU, FIFO | 접근 시간 단축 |
| 보호 | Base/Limit, 권한 비트 | 프로세스 간 격리 |

# Notes

<aside>메모리의 개념</aside>

메모리는 CPU가 직접 접근 가능한 주 기억장치(Main Memory)로,  
프로세스 실행에 필요한 프로그램 코드와 데이터를 임시로 저장한다.  
운영체제는 메모리 자원을 효율적으로 관리하여 **프로세스 간 간섭을 방지하고 자원을 최적화**한다.

- **주기억장치:** RAM (휘발성), ROM (비휘발성)  
- **보조기억장치:** HDD, SSD  
- **캐시(Cache):** CPU와 메모리 간의 속도 차이를 보완하는 고속 저장장치  

---

<aside>주소(Address)와 주소 변환</aside>

프로세스는 논리 주소(Logical Address)를 사용하고,  
운영체제가 이를 물리 주소(Physical Address)로 변환한다.  
이 과정은 **MMU(Memory Management Unit)** 에 의해 수행된다.

- **논리 주소:** 프로그램 관점의 주소 (0부터 시작)  
- **물리 주소:** 실제 메모리 상의 위치  
- **주소 변환 방식:**  
  - 베이스(Base) 레지스터 + 한계(Limit) 레지스터  
  - 동적 재배치(Dynamic Relocation): 실행 시 물리 주소 계산  

<aside>메모리 할당 방식</aside>

1. **연속 메모리 할당(Contiguous Allocation)**  
   - 프로세스에 연속된 메모리 공간을 할당  
   - **고정 분할:** 미리 나눈 영역에 배치 (내부 단편화 발생)  
   - **가변 분할:** 필요한 만큼 동적 할당 (외부 단편화 발생)  
   - **할당 전략:** 최초적합(First Fit), 최적적합(Best Fit), 최악적합(Worst Fit)

2. **비연속 메모리 할당(Non-Contiguous Allocation)**  
   - 프로세스를 여러 블록으로 나누어 흩어 저장  
   - **페이징(Paging):** 고정 크기 블록 단위 관리  
   - **세그멘테이션(Segmentation):** 논리적 단위(함수, 배열 등)로 구분  
   - **혼합 방식:** 세그먼트 + 페이징 결합  

<aside>가상 메모리(Virtual Memory)</aside>

가상 메모리는 실제 메모리보다 큰 논리적 공간을 제공하여  
프로세스가 전체 프로그램을 한 번에 메모리에 올리지 않고 실행할 수 있게 한다.  

- **페이지(Page):** 논리적 단위 (일정 크기, 예: 4KB)  
- **프레임(Frame):** 물리적 단위 (페이지와 동일 크기)  
- **페이지 테이블:** 페이지 ↔ 프레임 매핑 정보 저장  
- **TLB(Translation Lookaside Buffer):** 주소 변환 속도 향상용 캐시  
- **장점:** 메모리 효율성 증가, 다중 프로세스 실행 가능  

<aside>페이지 교체 알고리즘</aside>

가상 메모리에서 필요한 페이지가 없을 때(페이지 폴트 발생),  
운영체제는 새로운 페이지를 메모리에 올리기 위해 기존 페이지를 교체한다.

- **FIFO:** 가장 먼저 들어온 페이지 교체 (간단하지만 비효율적)  
- **LRU (Least Recently Used):** 가장 오랫동안 사용되지 않은 페이지 교체  
- **LFU (Least Frequently Used):** 사용 빈도가 가장 낮은 페이지 교체  
- **Optimal:** 앞으로 가장 오래 사용되지 않을 페이지 교체 (이론적 기준)  

<aside>단편화(Fragmentation)</aside>

- **내부 단편화:** 고정 분할 시, 프로세스보다 큰 블록이 할당되어 남는 공간  
- **외부 단편화:** 가변 분할 시, 여러 빈 공간이 흩어져 있어 전체는 충분하지만 연속 공간 부족  
- **해결 방법:** 압축(Compaction), 페이징(Paging), 세그멘테이션(Segmentation)  

<aside>캐시 메모리(Cache Memory)</aside>

CPU와 메모리 속도 차이를 보완하기 위한 임시 저장 장치이다.  
- **구조:** L1, L2, L3 캐시  
- **매핑 방식:** 직접 매핑(Direct), 완전 연관(Fully Associative), 집합 연관(Set Associative)  
- **교체 정책:** LRU, FIFO, Random  
- **효과:** 메모리 접근 시간 단축, CPU 효율 향상  

<aside>스와핑(Swapping)</aside>

메모리 부족 시, 일부 프로세스를 보조기억장치로 옮기고 필요 시 다시 불러오는 기법이다.  
- **Swap-in / Swap-out:** 메모리 ↔ 디스크 간 프로세스 교환  
- **장점:** 다중 프로세스 실행 가능  
- **단점:** 디스크 I/O로 인한 오버헤드 증가  

<aside>메모리 보호와 접근 제어</aside>

운영체제는 각 프로세스가 다른 프로세스의 메모리를 침범하지 않도록 보호한다.  
- **Base/Limit Register**를 이용해 접근 범위 제한  
- **페이지 보호 비트:** 읽기/쓰기/실행 권한 제어  
- **커널 모드와 사용자 모드 분리:** 시스템 안정성 확보

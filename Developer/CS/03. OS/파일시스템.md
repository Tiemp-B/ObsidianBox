# Summary

파일 시스템(File System)은 **데이터를 저장장치(HDD, SSD 등)에 구조적으로 저장하고 접근할 수 있도록 관리하는 운영체제의 핵심 구성 요소**다.  
파일의 생성, 삭제, 접근, 권한 관리, 디렉터리 구조 유지 등을 담당하며,  
저장 효율과 데이터 무결성을 보장하는 것이 주요 목적이다.

# Notes

<aside>파일 시스템의 개념</aside>

파일 시스템은 **운영체제가 저장장치에 데이터를 저장·관리하는 방식**이다.  
파일은 이름(name), 속성(attribute), 데이터(data)로 구성되며,  
운영체제는 이를 블록 단위로 나누어 저장하고 접근한다.  

- **파일(File):** 사용자나 프로그램이 다루는 논리적 데이터 단위  
- **디렉터리(Directory):** 파일을 체계적으로 분류하고 관리하는 구조  
- **경로(Path):** 파일의 위치를 나타내는 문자열 (절대경로 / 상대경로)

---

<aside>파일 시스템의 주요 기능</aside>

1. **파일 관리:** 생성, 삭제, 열기, 닫기, 읽기, 쓰기  
2. **저장 공간 관리:** 빈 공간(Free Space) 관리, 블록 할당 및 회수  
3. **디렉터리 구조 관리:** 파일의 계층적 관리 및 탐색 기능 제공  
4. **보안 및 접근 제어:** 사용자 권한 및 접근 권한(읽기, 쓰기, 실행) 관리  
5. **데이터 무결성 보장:** 시스템 오류 시 복구(Journaling) 지원  

---

<aside>파일 속성과 접근 권한</aside>

파일에는 다양한 속성이 포함된다.  
- **이름(Name):** 파일 식별자  
- **유형(Type):** 텍스트, 실행 파일 등  
- **크기(Size):** 파일의 바이트 단위 크기  
- **소유자(Owner):** 파일의 관리자 정보  
- **접근 권한(Permission):**  
  - `r`: 읽기(Read)  
  - `w`: 쓰기(Write)  
  - `x`: 실행(Execute)  

---

<aside>파일 할당 방법</aside>

저장장치의 블록을 어떻게 파일에 연결하느냐에 따라 세 가지 방식으로 구분된다.  

1. **연속 할당(Contiguous Allocation):**  
   - 파일이 연속된 블록에 저장  
   - 장점: 빠른 접근 속도  
   - 단점: 외부 단편화 발생  

2. **연결 할당(Linked Allocation):**  
   - 각 파일 블록이 다음 블록의 포인터를 포함  
   - 장점: 단편화 문제 해결  
   - 단점: 임의 접근(Random Access)이 느림  

3. **색인 할당(Indexed Allocation):**  
   - 별도의 인덱스 블록을 통해 블록 위치를 관리  
   - 장점: 빠른 접근, 효율적인 관리  
   - 단점: 인덱스 블록의 추가 공간 필요  

---

<aside>디렉터리 구조</aside>

- **단일 레벨(Single-level):** 모든 파일이 하나의 디렉터리에 존재  
- **2단계(Two-level):** 사용자별 디렉터리 분리  
- **트리 구조(Tree-structured):** 계층적 구조, 현대 OS의 표준  
- **비순환 그래프 구조(Acyclic Graph):** 여러 디렉터리에서 동일 파일 참조 가능 (Hard/Soft Link)  

---

<aside>파일 접근 방식</aside>

1. **순차 접근 (Sequential Access):** 파일을 처음부터 차례로 읽고 쓰는 방식 (ex. 텍스트 파일)
2. **직접 접근 (Direct Access):** 파일의 임의 위치를 바로 접근 (ex. DB, 실행 파일)  
3. **인덱스 접근 (Indexed Access):** 인덱스를 이용해 빠르게 특정 위치 접근  

---

<aside>저장 공간 관리</aside>

운영체제는 사용되지 않은 블록을 관리하기 위해 **Free Space List**를 유지한다.  
- **비트맵(Bitmap):** 각 블록의 사용 여부를 비트로 표시  
- **연결 리스트(Linked List):** 빈 블록을 포인터로 연결  
- **그룹핑(Grouping):** 여러 빈 블록을 묶어서 관리  

---

<aside>저널링(Journaling)과 복구</aside>

시스템 오류나 전원 장애 시 파일 시스템의 일관성을 보장하기 위해  
**저널링(Journaling)** 기능을 사용한다.  
- **개념:** 변경 사항을 실제 반영 전에 로그(Journal)에 기록  
- **복구 방법:**  
  1. 시스템 재시작 시 저널 확인  
  2. 완료되지 않은 작업 롤백(Rollback) 또는 재실행(Redo)  

---

<aside>대표적인 파일 시스템 종류</aside>

| 파일 시스템 | 주요 사용 OS | 특징 |
|--------------|---------------|------|
| FAT32 | Windows, 임베디드 | 간단, 속도 빠름, 대용량 비효율 |
| NTFS | Windows | 접근 제어, 저널링, 대용량 지원 |
| ext4 | Linux | 저널링, 고성능, 대용량 파일 지원 |
| HFS+ / APFS | macOS | 스냅샷, 암호화, SSD 최적화 |
| XFS | Linux 서버 | 대규모 병렬 입출력에 최적 |
| exFAT | 교차 플랫폼 | FAT32와 NTFS의 절충형 |

---

<aside>가상 파일 시스템(VFS)</aside>

운영체제는 여러 파일 시스템을 공통 인터페이스로 관리하기 위해  
**VFS (Virtual File System)** 구조를 사용한다.  
- 다양한 파일 시스템을 통합 관리 (ex. ext4, FAT32, NTFS)  
- 공통 API 제공 (open, read, write, close)  
- 파일 시스템 간 호환성 향상  

---

<aside>파일 시스템의 발전 방향</aside>

- SSD 기반 저지연 파일 구조 (ex. F2FS, NVMe)  
- 로그 구조 파일 시스템(Log-Structured FS)  
- 분산 파일 시스템 (HDFS, Ceph, NFS)  
- 스냅샷 및 버전 관리 기능 강화  
- 암호화 및 무결성 검증 내장

# Summary

스케줄링(Scheduling)은 **운영체제가 여러 프로세스나 스레드에게 CPU를 효율적으로 배분하는 작업**이다.  
CPU 사용률을 극대화하고 응답 시간, 대기 시간, 처리량 등을 최적화하는 것이 목표이다.  
운영체제는 스케줄러를 통해 프로세스의 실행 순서를 결정한다.

# Notes

<aside>스케줄링의 개념</aside>

스케줄링은 다중 프로그래밍 환경에서 **CPU 자원을 경쟁하는 프로세스 간에 공정하고 효율적인 실행 순서를 결정하는 과정**이다.  
운영체제는 스케줄러(Scheduler)를 통해 프로세스의 상태(준비, 실행, 대기)에 따라 CPU를 분배한다.

스케줄링의 주요 목표는 다음과 같다.
- CPU 이용률 최대화 (Utilization)
- 처리량 향상 (Throughput)
- 대기 시간 최소화 (Waiting Time)
- 응답 시간 최소화 (Response Time)
- 공정성 유지 (Fairness)

<aside>스케줄러의 종류</aside>

1. **장기 스케줄러 (Long-term Scheduler)**  
   - 어떤 프로세스를 메모리에 적재할지 결정  
   - 작업(job)을 ready queue로 이동시킴  
   - 입출력/CPU 집중형 프로세스 비율을 조절함  

2. **단기 스케줄러 (Short-term Scheduler)**  
   - CPU를 어떤 프로세스에 할당할지 결정  
   - Ready Queue 내에서 선택된 프로세스 실행  
   - 실행 전환이 자주 발생 (밀리초 단위)  

3. **중기 스케줄러 (Medium-term Scheduler)**  
   - 메모리 부족 시 프로세스를 일시 중단(Suspend)시킴  
   - Swapping 기법을 통해 CPU 부하 조절  

<aside>프로세스 상태 전이와 스케줄링</aside>

스케줄링은 프로세스 상태 변화와 밀접한 관계가 있다.  

- **Ready → Running:** 디스패처(Dispatcher)에 의해 선택되어 CPU 할당  
- **Running → Waiting:** I/O 요청 등으로 CPU 반납  
- **Waiting → Ready:** 이벤트 완료 시 다시 실행 대기  
- **Running → Ready:** 우선순위가 높은 프로세스가 나타날 때 (선점형)

<aside>스케줄링의 분류</aside>

- **비선점형 (Non-preemptive):**  
  - 실행 중인 프로세스가 완료되거나 자발적으로 CPU를 반납해야 함  
  - 예: FCFS, SJF, HRN, Priority
- **선점형 (Preemptive):**  
  - 운영체제가 강제로 CPU를 회수 가능  
  - 예: Round Robin, Priority Scheduling, SRT, 다단계 피드백 큐

<aside>비선점 스케줄링 알고리즘</aside>

1. **FCFS (First Come, First Served)**  
   - 도착 순서대로 처리  
   - 우선도 낮은 작업에 처리로 인해 중요 작업의 대기 시간이 길어지는 ‘Convoy Effect’ 발생  

2. **SJF (Shortest Job First)**  
   - CPU 버스트가 짧은 프로세스 우선 실행  
   - 평균 대기 시간 최소화  
   - Convoy 현상을 완화할 수 있으나 긴 작업이 무한 대기(Starvation)하는 현상 발생 

3. **HRN (Highest Response ratio Next)** 
   - 우선순위를 대기 큐에서 대기한 시간까지 반영하는 aging 기법 사용

4. **Priority Scheduling**  
   - 우선순위가 높은 프로세스부터 실행  
   - 선점형 / 비선점형 모두 가능  
   - 단점: 낮은 우선순위 프로세스가 계속 대기할 수 있음 (Aging 기법으로 해결)  

<aside>선점 스케줄링 알고리즘</aside>

1. **Round Robin (RR)**  
   - 각 프로세스에 동일한 시간 할당(Time Quantum)  
   - 일정 시간이 지나면 다음 프로세스로 교체  
   - 응답 시간이 짧아 대화형 시스템에 적합  
   - Time Quantum이 너무 짧으면 오버헤드 증가  

1. **Multi-level Queue Scheduling**  
   - 프로세스 우선순위별로 여러 큐를 구성  
   - 예: 시스템 프로세스, 대화형, 배치 작업 등  
   - 큐 간 이동이 제한적 (고정형)  

3. **Multilevel Feedback Queue Scheduling**  
   - 실행 시간에 따라 큐 간 이동 가능  
   - CPU를 많이 사용하는 프로세스는 낮은 우선순위로 이동  
   - 가장 유연하고 현대 운영체제에서 널리 사용  

4. **SRT (Shortest Remaining Time)**
   - SJF 방식을 선점 스케줄링 방식으로 변경
   - 처리 시간이 짧은 프로세스가 대기 큐에 들어와 CPU를 점유할 수 있다.
   - 평균 대기 시간이 가장 짧지만 잦은 Context Switching이 발생하여 오버헤드가 커진다.
   - Starvation 현상 역시 크다
   - 처리 시간의 예측 불가로 실제 사용이 불가하다.


<aside>스케줄링 성능 척도</aside>

- **CPU 이용률 (Utilization):** CPU가 일한 비율  
- **처리량 (Throughput):** 단위 시간당 처리된 프로세스 수  
- **대기 시간 (Waiting Time):** Ready Queue에서 대기한 시간  
- **응답 시간 (Response Time):** 요청 후 첫 응답까지 걸린 시간  
- **Turnaround Time:** 프로세스 시작부터 종료까지 총 소요 시간

# Notes

<aside>보안 프로토콜 개요</aside>

보안 프로토콜은 네트워크 통신에서 기밀성·무결성·인증을 제공하며, 동작하는 계층에 따라 구분한다.

- **네트워크 계층**: IPSec
- **전송 계층**: SSL/TLS
- **응용 계층**: SSH, PGP, S/MIME, SET, S-HTTP

---

<aside>IPSec</aside>

IPSec(IP Security)은 **네트워크 계층(IP)** 에서 패킷 단위로 인증과 암호화를 제공하는 프로토콜 집합이다. VPN 구축의 핵심 기술이다.

두 가지 보안 프로토콜로 구성된다.

- **AH(Authentication Header)**: 인증과 무결성을 제공(발신지 인증, 변조 탐지). 암호화는 하지 않음
- **ESP(Encapsulating Security Payload)**: 암호화(기밀성) + 인증·무결성을 함께 제공

두 가지 동작 모드가 있다.

- **전송 모드(Transport Mode)**: IP 헤더는 그대로 두고 **페이로드(데이터)만** 보호. 호스트 간 통신에 사용
- **터널 모드(Tunnel Mode)**: 원본 IP 패킷 **전체를 암호화**하고 새 IP 헤더를 추가. 게이트웨이 간 VPN에 사용

키 교환은 **IKE(Internet Key Exchange)** 를 통해 수행하며, 보안 연결 정보는 **SA(Security Association)** 로 관리한다.

---

<aside>SSL / TLS</aside>

**전송 계층**에서 동작하며, 인증서 기반으로 서버(및 클라이언트)를 인증하고 데이터를 암호화한다. HTTPS의 기반이다.

- 핸드셰이크는 비대칭키로 세션 키를 교환하고, 이후 데이터는 대칭키로 암호화
- SSL은 취약점으로 폐기되었고 현재 표준은 TLS(1.2, 1.3)

> 세부 내용은 [[SSL]], [[TLS]] 노트 참고. HTTPS 관계는 [[HTTP, HTTPS]] 참고.

---

<aside>SSH (Secure Shell)</aside>

**응용 계층**의 원격 접속 프로토콜로, 평문으로 통신하던 Telnet·rlogin을 대체한다.

- 원격 로그인·명령 실행·파일 전송(SCP/SFTP)을 암호화된 채널로 수행
- 공개키 기반 인증, 대칭키 기반 데이터 암호화, 무결성 검증 제공
- 기본 포트 22, 포트 포워딩(터널링)에도 활용

---

<aside>PGP와 S/MIME</aside>

**이메일 보안** 프로토콜로, 메일 본문을 암호화하고 전자서명한다.

- **PGP(Pretty Good Privacy)**: 공개키 방식으로 기밀성·무결성·인증·부인방지를 제공. 신뢰의 웹(Web of Trust) 기반으로 사용자 간 키를 상호 신뢰
- **S/MIME(Secure MIME)**: MIME 형식 메일에 보안을 적용. **CA가 발급한 인증서(X.509)** 기반으로 신뢰를 검증한다는 점이 PGP와 다름

---

<aside>SET (Secure Electronic Transaction)</aside>

인터넷 **전자상거래의 신용카드 결제**를 안전하게 처리하기 위한 프로토콜이다.

- 참여자: 고객, 상점, 지불 게이트웨이, 인증기관(CA)
- **이중 서명(Dual Signature)**: 주문 정보는 상점만, 결제 정보는 은행(PG)만 볼 수 있게 분리하여, 상점이 카드정보를, 은행이 주문내역을 알 수 없게 함
- 기밀성·무결성·인증·부인방지를 제공

---

<aside>기타 프로토콜</aside>

- **S-HTTP(Secure HTTP)**: 개별 HTTP 메시지 단위를 암호화(HTTPS는 연결 전체를 TLS로 보호 — 서로 다름)
- **Kerberos**: 대칭키·티켓 기반의 네트워크 인증 프로토콜(SSO)
- **WPA2 / WPA3**: 무선랜(Wi-Fi) 보안 프로토콜

# Notes

<aside>SQL Injection</aside>

입력값에 악의적인 SQL 구문을 삽입하여 데이터베이스를 조작하는 공격이다. 입력값이 쿼리에 그대로 결합될 때 발생한다.

- **인증 우회**: 패스워드 자리에 `' OR '1'='1` 을 넣으면 조건이 항상 참이 되어 로그인 통과
- **Union 기반**: `UNION SELECT`로 다른 테이블 데이터를 조회
- **Blind SQL Injection**: 참/거짓 응답 차이나 시간 지연(`SLEEP`)으로 데이터를 한 비트씩 추론
- **Error 기반**: DB 에러 메시지에 정보가 노출되는 것을 악용

**대응**: 입력값 검증, **Prepared Statement(파라미터 바인딩)** 사용, 저장 프로시저, DB 계정 최소 권한 부여, 상세 에러 메시지 노출 차단

---

<aside>XSS (Cross-Site Scripting)</aside>

게시글·입력 폼 등에 악성 스크립트를 삽입하여, 그 페이지를 보는 다른 사용자의 브라우저에서 실행시키는 공격이다. 쿠키·세션 탈취, 화면 변조 등에 악용된다.

- **저장형(Stored)**: 스크립트가 서버 DB에 저장되어 열람하는 모든 사용자에게 실행 (예: 게시판)
- **반사형(Reflected)**: 요청 파라미터에 담긴 스크립트가 응답에 그대로 반사되어 실행 (악성 링크 유도)
- **DOM 기반**: 서버를 거치지 않고 클라이언트 측 스크립트가 DOM을 조작하며 실행

**대응**: 입력·**출력값 인코딩(이스케이프)**, 입력 검증(화이트리스트), CSP(Content Security Policy) 적용, 쿠키에 HttpOnly 속성

---

<aside>CSRF (Cross-Site Request Forgery)</aside>

이미 인증된(로그인된) 사용자의 권한을 도용하여, 사용자가 의도하지 않은 요청(송금·정보변경 등)을 서버로 보내게 만드는 공격이다.

- 사용자가 공격자가 심어둔 링크·이미지를 클릭하면, 브라우저에 저장된 인증 쿠키가 자동 첨부되어 정상 요청처럼 처리됨
- XSS는 스크립트 실행, CSRF는 인증정보를 이용한 요청 위조라는 점에서 다름

**대응**: **CSRF 토큰**(요청마다 검증), Referer/Origin 헤더 검증, **SameSite 쿠키** 속성, 중요 작업 시 재인증

---

<aside>파일 업로드 취약점</aside>

서버가 업로드 파일을 검증하지 않을 때, 공격자가 서버 명령을 실행할 수 있는 **웹쉘(Web Shell)** 등을 올려 서버를 장악하는 공격이다.

**대응**: 확장자·MIME 타입 화이트리스트 검증, 업로드 디렉터리의 실행 권한 제거, 저장 경로를 웹 루트 밖으로 분리, 파일명 난수화

---

<aside>디렉터리 트래버설 / 기타</aside>

- **디렉터리 트래버설(Path Traversal)**: `../` 등 상대 경로를 삽입해 허가되지 않은 상위 디렉터리의 파일에 접근 → 경로 정규화, 입력값 필터링, 접근 권한 제한
- **명령어 삽입(Command Injection)**: 입력값에 OS 명령을 삽입해 서버에서 실행 → 입력 검증, 셸 호출 최소화
- **세션/쿠키 변조**: 클라이언트 저장 값 위조 → 서버 측 검증, 세션 무결성 확인

# Notes

<aside>DoS / DDoS</aside>

DoS(Denial of Service)는 대상 시스템에 과도한 부하를 유발해 정상 서비스를 마비시키는 공격이다. DDoS는 다수의 좀비 PC(봇넷)를 이용한 분산 형태이다.

- **SYN Flooding**: TCP 3-way handshake의 SYN 요청만 대량 전송해 연결 대기 큐를 고갈시킴
- **Smurf**: 출발지를 피해자 IP로 위조한 ICMP 요청을 브로드캐스트 → 대량 응답이 피해자에게 몰림
- **Ping of Death**: 규격을 초과한 큰 ICMP 패킷을 보내 시스템 오류 유발
- **Teardrop**: 조각화된 패킷의 offset을 조작해 재조립 오류 유발
- **Land**: 출발지·목적지 IP를 동일하게 위조해 시스템을 무한 루프에 빠뜨림

**대응**: 방화벽·IPS, 트래픽 임계치 설정, **CDN·DDoS 스크러빙 서비스**, 대역폭 확보, SYN 쿠키

---

<aside>슬로우 DoS (Slow HTTP DoS)</aside>

대량 트래픽 대신 **연결을 비정상적으로 느리게 유지**하여, 적은 대역폭으로 서버의 동시 연결 자원(스레드·커넥션 풀)을 고갈시키는 응용 계층(L7) 공격이다. 트래픽량이 적어 일반적인 대역폭 기반 탐지로는 잡기 어렵다.

- **Slowloris**: 다수의 HTTP 연결을 열고 **불완전한 요청 헤더**를 아주 조금씩 계속 흘려보내 연결을 끝내지 않고 오래 점유(Slow Headers)
- **RUDY (R-U-Dead-Yet)**: HTTP POST의 `Content-Length`를 크게 지정한 뒤 **본문(Body)을 극도로 느리게** 전송해 연결을 붙잡음(Slow Body)
- **Slow Read**: 서버 응답을 아주 느린 속도로 읽어 들여 서버의 송신 버퍼·연결을 점유
- 세 가지는 각각 헤더/본문/응답 지연을 노리며, 통칭하여 Slow HTTP Attack이라 한다.

**대응**: 연결·요청 **타임아웃 단축**, 최소 데이터 전송률(수신 속도) 강제, IP당 동시 연결 수 제한, 리버스 프록시(nginx, Apache `mod_reqtimeout`) 도입, WAF 적용

---

<aside>스니핑 (Sniffing)</aside>

네트워크를 지나는 패킷을 도청하여 정보를 탈취하는 **수동적(passive)** 공격이다. 별도의 조작 없이 관찰만 하므로 탐지가 어렵다.

**대응**: **데이터 암호화(SSL/TLS)**, 스위칭 네트워크 환경 구성, 스니핑 탐지 도구(예: 무차별 모드 감지)

---

<aside>스푸핑 (Spoofing)</aside>

자신의 정보를 위조하여 신뢰된 대상으로 가장하는 공격이다.

- **IP Spoofing**: 출발지 IP를 신뢰 호스트로 위조해 접근 제어 우회
- **ARP Spoofing**: MAC 주소를 위조해 같은 네트워크 내 트래픽을 가로챔(스니핑·MITM의 기반)
- **DNS Spoofing**: DNS 응답을 위조해 가짜 사이트로 유도(파밍과 연결)

**대응**: ARP 정적(static) 설정, 패킷 필터링, **DNSSEC**, 상호 인증

---

<aside>이블 트윈 (Evil Twin)</aside>

정상 AP(무선 공유기)와 **동일한 SSID**로 위장한 악성 무선 AP를 설치해, 사용자가 무심코 접속하도록 유도하는 무선 네트워크 공격이다.

- 접속한 사용자의 트래픽을 스니핑·MITM으로 도청·변조하거나, 가짜 로그인 페이지로 인증정보를 탈취
- 신호가 더 강한 악성 AP를 세워 자동 접속을 유도하기도 함
- 공용 Wi-Fi 환경에서 특히 위협적

**대응**: 공용 Wi-Fi에서 **VPN 사용**, HTTPS·인증서 확인, 알 수 없는 AP 자동 접속 해제, 기업용 무선 인증(802.1X)·WPA3 적용

---

<aside>세션 하이재킹 (Session Hijacking)</aside>

정상적으로 인증이 완료된 세션(세션 ID·쿠키)을 가로채, 재인증 없이 피해자 권한으로 접근하는 공격이다. TCP 시퀀스 번호 추측이나 스니핑으로 세션 정보를 획득한다.

**대응**: 세션 정보 암호화, 세션 타임아웃 설정, 로그인 후 **세션 ID 재발급**, IP·User-Agent 검증

---

<aside>중간자 공격 (MITM)</aside>

Man-In-The-Middle. 통신하는 두 대상 사이에 끼어들어 트래픽을 도청·변조·중계하는 공격이다. ARP 스푸핑 등으로 경로를 가로채 수행한다.

**대응**: 상호 인증서 검증, **TLS 적용**, HSTS, 공개키 고정(Pinning)

---

<aside>스캐닝 (Scanning)</aside>

본격적인 공격 전 대상의 열린 포트·서비스·취약점을 탐색하는 정찰 단계이다(예: 포트 스캔).

**대응**: 방화벽·IPS로 스캔 트래픽 탐지·차단, 불필요한 포트·서비스 폐쇄

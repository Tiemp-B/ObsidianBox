# Notes

<aside>DB 암호화 방식 개요</aside>

데이터베이스의 민감 정보를 보호하기 위해 저장 데이터를 암호화한다. 암호화 모듈을 어느 계층에 두느냐에 따라 방식이 나뉜다.

---

<aside>API 방식</aside>

응용프로그램(Application) 레벨에서 암호화 API를 호출하여 데이터를 암·복호화하는 방식이다.

- 애플리케이션 소스 수정이 필요함
- 암호화 연산을 앱 서버가 담당하므로 DB 서버의 부하는 적음

---

<aside>Plug-in 방식</aside>

DB 서버에 암호화 모듈(플러그인)을 설치하여 처리하는 방식이다.

- 애플리케이션 수정이 최소화됨
- 암호화 연산을 DB 서버가 담당하므로 DB 서버에 부하가 발생

---

<aside>TDE 방식</aside>

TDE(Transparent Data Encryption)는 DBMS 엔진 자체가 데이터를 자동으로 암·복호화하는 방식이다.

- 응용프로그램 입장에서 암호화 과정이 보이지 않아(투명, Transparent) 소스 수정이 필요 없음
- 주로 컬럼·테이블스페이스(블록) 단위로 적용

---

<aside>Hybrid 방식</aside>

API 방식과 Plug-in 방식을 혼합하여 각 방식의 장점을 취하는 방식이다.

---

<aside>암호화 알고리즘</aside>

- **대칭키(양방향)**: 암호화·복호화에 같은 키 사용. 빠름 — DES, AES, SEED, ARIA, IDEA
- **비대칭키(양방향)**: 공개키·개인키 쌍 사용. 키 분배 안전 — RSA, ECC
- **해시(단방향)**: 복호화 불가, 무결성·비밀번호 저장에 사용 — SHA, MD5, HAS-160

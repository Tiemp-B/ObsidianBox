# Notes

<aside>정규화란</aside>

정규화(Normalization)는 데이터 중복과 이상현상(Anomaly)을 제거하기 위해 릴레이션을 분해해 나가는 과정이다. 함수적 종속성을 기준으로 단계적으로 진행한다.

---

<aside>이상현상 (Anomaly)</aside>

정규화가 필요한 이유이며, 중복 저장 때문에 발생한다.

- **삽입 이상(Insertion)**: 불필요한 데이터 없이는 새 데이터를 삽입할 수 없음
- **삭제 이상(Deletion)**: 한 데이터를 삭제하면 연관된 다른 정보까지 함께 손실됨
- **갱신 이상(Update)**: 중복된 값 중 일부만 수정되어 데이터 불일치가 발생함

---

<aside>함수적 종속 (FD)</aside>

정규화 단계를 판단하는 기준으로, 어떤 속성이 다른 속성값에 의해 결정되는 관계이다.

- **완전 함수 종속**: 기본키 전체에 종속 (기본키의 일부만으로는 결정 불가)
- **부분 함수 종속**: 기본키의 일부에만 종속
- **이행 함수 종속**: A→B, B→C일 때 A→C가 성립하는 종속

---

<aside>정규형 단계</aside>

암기: 도 · 부 · 이 · 결 · 다 · 조

- **1NF (제1정규형)**: 모든 속성의 도메인이 원자값으로만 구성
- **2NF (제2정규형)**: 부분 함수 종속을 제거 → 완전 함수 종속만 남김
- **3NF (제3정규형)**: 이행 함수 종속을 제거
- **BCNF (보이스-코드 정규형)**: 모든 결정자가 후보키가 되도록 함
- **4NF (제4정규형)**: 다치 종속(Multivalued Dependency)을 제거
- **5NF (제5정규형)**: 조인 종속(Join Dependency)을 제거

---

<aside>반정규화 (De-normalization)</aside>

정규화의 역과정으로, 시스템 성능 향상을 위해 의도적으로 중복을 허용하는 기법이다.

- 조인을 줄여 조회 성능이 향상됨
- 데이터 중복으로 인해 무결성 관리 부담과 저장 공간 비용이 증가함

예를 들어,  
`ADD R1, R2, R3` → R1 ← R2 + R3  
는 “R2와 R3를 더한 결과를 R1에 저장”하는 명령을 의미한다.

---

<aside>명령어의 종류</aside>

1. **데이터 이동 명령 (Data Transfer)**  
   - MOV, LOAD, STORE, PUSH, POP 등  
   - 메모리나 레지스터 간 데이터 전송 수행.  

2. **산술 연산 명령 (Arithmetic Operations)**  
   - ADD, SUB, MUL, DIV 등  
   - 기본적인 수학 연산 수행.  

3. **논리 연산 명령 (Logical Operations)**  
   - AND, OR, XOR, NOT, SHIFT 등  
   - 비트 단위 논리 연산 수행.  

4. **제어 명령 (Control Instructions)**  
   - JMP, CALL, RET, BEQ, BNE 등  
   - 프로그램 실행 흐름 제어 (분기, 반복, 함수 호출 등).  

5. **입출력 명령 (I/O Instructions)**  
   - IN, OUT  
   - 외부 장치와 데이터 교환 수행.  

6. **시스템 명령 (System Instructions)**  
   - 인터럽트, 상태 제어, 시스템 콜 등.  
   - 운영체제나 하드웨어 자원과 직접 상호작용.  

---

<aside>주소 지정 방식 (Addressing Modes)</aside>

| 방식 | 설명 | 예시 |
|------|------|------|
| 즉시 주소 지정 (Immediate) | 피연산자가 명령어에 직접 포함됨 | `MOV R1, #5` |
| 직접 주소 지정 (Direct) | 메모리 주소가 명령어에 직접 명시됨 | `LOAD R1, 1000` |
| 간접 주소 지정 (Indirect) | 명령어가 가리키는 주소에 실제 주소가 존재 | `LOAD R1, (R2)` |
| 레지스터 주소 지정 (Register) | 피연산자가 레지스터에 존재 | `ADD R1, R2` |
| 인덱스 주소 지정 (Indexed) | 기본 주소 + 오프셋 형태 | `LOAD R1, 1000(R2)` |

<aside>명령어 집합 구조 (ISA)</aside>

ISA(Instruction Set Architecture)는 CPU가 이해할 수 있는 명령어의 집합이며,  
하드웨어와 소프트웨어 사이의 **인터페이스 역할**을 한다.

- **[[CISC]] (Complex Instruction Set Computer)**  
  - 복잡하고 다양한 명령어 제공 (예: x86)  
  - 한 명령으로 여러 동작 수행  
  - 하드웨어 복잡도 ↑, 코드 길이 ↓
  - 명령어 크기가 명령어마다 다름 -> 명령어마다 처리 속도 다름

- **[[RISC]] (Reduced Instruction Set Computer)**  
  - 단순하고 빠른 명령어 중심 구조 (예: ARM, RISC-V)  
  - 고정된 명령어 길이, 파이프라이닝 효율 ↑  
  - 명령 수는 적지만 실행 속도 빠름  
  - 명령어 크기가 고정
  - CISC의 한 명령어가 RISC에서는 여러 단계의 명령어로 이루어질 수 있다

---

<aside>CISC vs RISC</aside>

| 구분 | CISC | RISC |
|------|------|------|
| 설계 철학 | 복잡한 명령어로 소프트웨어 부담 감소 | 단순 명령어로 하드웨어 효율 극대화 |
| 명령어 길이 | 가변 길이 | 고정 길이 |
| 실행 사이클 | 명령어당 여러 사이클 | 대부분 1사이클 |
| 파이프라이닝 | 어려움 | 용이 |
| 하드웨어 복잡도 | 높음 | 낮음 |
| 코드 길이 | 짧음 | 길음 |
| 대표 예시 | x86, VAX, 68000 | ARM, MIPS, RISC-V |

---

<aside>핵심 목표</aside>

명령어 체계의 설계 목표는  
- 하드웨어 구현이 효율적이고,  
- 소프트웨어가 간단하게 실행될 수 있으며,  
- 파이프라이닝 및 병렬 처리가 용이한 구조를 갖추는 것이다.

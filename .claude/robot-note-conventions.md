# 로봇 자격증 필기 노트 공통 규칙

이 문서는 `/home/ubuntu/box` (Obsidian 볼트, git repo `https://github.com/Tiemp-B/ObsidianBox.git`)에서
로봇 관련 국가기술자격(NCS 기반) 필기 대비 코넬노트를 작성할 때, **어느 자격증이든 공통으로 적용되는 규칙**을 담는다.

자격증별 세부 사항(정확한 폴더명, 문제은행 JSON 파일명 패턴, tags 문자열, progress log 위치, 특정 규칙의 적용 시점 등)은
각 자격증 전용 스킬에서 정의한다:

- `write-robot-note` — 로봇소프트웨어개발기사
- `write-robot-hw-note` — 로봇하드웨어개발기사

**자격증별 스킬을 실행하기 전에 이 문서를 먼저 읽는다.** 두 문서가 충돌하면 자격증별 스킬 쪽이 그 자격증에 한해 최신/우선이다.

## 0. 시작 전에 항상 확인할 것

- 그 자격증 전용 스킬이 지정하는 progress log 파일 — 최신 항목이 맨 위
- `/home/ubuntu/.claude/projects/-home-ubuntu-box/memory/` — 이 프로젝트의 축적된 메모리(세션 간 유지, 여러 자격증에 걸친 내용이 섞여 있을 수 있으니 어느 자격증에 해당하는 메모인지 확인)
- 작업하려는 세세항목의 문제은행 JSON(자격증별 스킬이 지정하는 경로/파일명 패턴)
- 그 자격증의 `자료/` 폴더 — NCS학습모듈 PDF와 공식 출제기준(필기/실기) PDF가 있다면 반드시 대조

## 1. 범위·깊이를 정하는 우선순위 (가장 중요)

**출제기준(세세항목 이름과 구조) > NCS 학습모듈의 "필요 지식" > 문제은행**. 이 순서를 반드시 지킨다.

1. 해당 자격증의 출제기준 PDF에서 그 세세항목이 어느 과목/주요항목/세부항목 아래 있는지, 정확한 이름을 확인한다. 세세항목 이름 자체가 범위의 1차 근거다.
2. NCS 학습모듈 중 그 세세항목(정확히는 NCS 능력단위요소)에 대응하는 학습모듈이 있는지 찾는다. 있다면 그 안의 **"필요 지식"** 섹션만 필기 범위로 채택한다.
   - **"수행 내용/수행 순서"(코드, 설치 명령어, 회로도, xml/공식 유도, 실제 소스 파일 구조, 조립·배선 절차 등)는 실기 영역이므로 절대 필기 페이지에 넣지 않는다.** 출제기준 PDF에 필기/실기가 별도 섹션으로 나뉘어 있으므로 실제로 대조해서 확인할 것.
   - 대응하는 NCS 학습모듈이 없는 세세항목은 문제은행 힌트 + 일반 도메인 지식으로 구성하고, progress log에 "NCS 모듈 대응 항목 없음"이라고 명시한다.
3. 문제은행은 **소재 힌트일 뿐, 범위의 상한이 아니다.** 문제은행에 없는 개념이라도 출제기준/NCS상 그 세세항목의 핵심이면 반드시 포함한다.
4. 이미 완료된 세세항목이라도, 나중에 관련 NCS 원자료를 새로 확인하게 되면 **다시 대조해서 누락을 찾아 보강한다.** 기존에 잘 쓰인 페이지들을 갈아엎지 말고, 빠진 개념만 새 aside나 새 페이지로 추가한다.

## 2. 새 세세항목 착수 절차 (2026-08-01 개정)

정보 수집·작성은 반드시 **① 자료 조사(정보덩어리 md) → ② NCS·문제은행으로 보완 → ③ 본문 설계 → ④ 본문 작성** 4단계로 진행한다. §1의 우선순위(출제기준 > NCS 필요지식 > 문제은행)는 그대로 유지되며, 이 4단계는 그 우선순위를 지키면서 **내용의 정확성(특히 구체적 수치·표준값)을 조사로 검증**하기 위한 절차다.

1. **자료 조사 — 정보덩어리 md 작성**: 세세항목 이름(및 출제기준상 위치)을 기준으로, 필요하면 웹 검색(WebSearch/WebFetch)까지 동원해 최대한 폭넓게 조사한다. 아직 페이지 분량·구성을 고려하지 말고, 조사한 내용을 정리·가공 없이 원자료 형태로 그 세부항목 폴더 안에 `조사 - <세세항목명>.md` 파일로 남긴다(문제은행 파일과 같은 위치, 같은 명명 패턴). 참고한 출처(URL, 문서명)를 함께 적어 나중에 근거를 추적할 수 있게 한다.
   - **특히 구체적 수치·표준값·프로토콜 세부 스펙**(예: 권장 비율, 통신 거리, 규격값)은 반드시 이 조사 단계에서 확인된 것만 쓴다 — 확인이 안 되면 그 수치를 페이지에 넣지 않고 정성적 서술로 대체한다. 정성적 개념 설명(원리, 정의, 개념 간 비교)은 도메인 지식으로 초안을 잡아도 되지만, 숫자는 근거 없이 단정하지 않는다.
2. **NCS·문제은행으로 보완**: `자료/` 폴더의 NCS 학습모듈 "필요 지식"과 문제은행을 대조해, 1번 조사에서 놓친 핵심 개념을 정보덩어리 md에 추가하고 범위를 벗어난 부분은 표시해 정리한다. 대응하는 NCS 모듈이 없으면 그 사실을 기록해 둔다.
3. **본문 설계**: 정리된 정보덩어리 md를 바탕으로 실제 페이지 수(대략 4~9페이지, 세세항목 여러 개면 그 합)와 각 페이지가 다룰 범위를 정한다. **자격증별 스킬이 지정하는 시점부터는 1번 페이지를 반드시 그 세세항목의 "개요" 페이지로 만든다** — 같은 세부항목 안 형제 세세항목들과 어떻게 초점이 다른지 표로 대비하고, 이후 페이지를 안내한다. 그 시점 이전에 이미 완료된 세부항목들에는 소급 적용하지 않는다.
4. **본문 작성**: 설계에 따라 실제 코넬노트 페이지를 작성한다. 이미 다른 세세항목/페이지에서 상세히 다룬 개념은 반복 서술하지 않고 위키링크로만 참조한다 — 개요 페이지에 "이미 다룬 내용과의 관계"를 명시한다. **같은 볼트 안 다른 자격증의 페이지라도 관련 개념이면 위키링크로 참조할 수 있다.**

사용자가 한 페이지씩 확인하며 진행하길 원하면 한 페이지씩, "계속 진행"처럼 명시적으로 지시하면 여러 페이지를 이어서 작성한다.

## 4. 본문 작성 세부 규칙

- **기출문제를 절대 그대로 인용하지 않는다.** `> 기출: "..."` 같은 블록 금지. 대신 오답으로 나올 법한 서술을 본문 안에 자연스럽게 녹여 "OO는 △△가 아니라 □□이다" / `"~라는 서술은 ~을 무시한/뒤바꾼 오답(함정)이다"` 형태의 정정 문장으로 다룬다.
- **표(table) 바로 위 줄은 반드시 빈 줄로 띄운다** — 안 그러면 Obsidian 읽기 모드에서 `|---|---|`가 raw 텍스트로 노출되는 렌더링 버그가 있다.
- 표 안에서 별칭이 있는 위키링크를 쓸 때는 파이프를 이스케이프한다: `[[문서명\|표시텍스트]]` (표의 열 구분자 `|`와 충돌 방지). 표 밖 일반 본문에서는 이스케이프하지 않는다.
- 표에 이미 있는 내용을 표 아래에서 불릿으로 다시 풀어 쓰지 않는다. 표에 없는 보충 정보(실무 팁, 트레이드오프, 결합 사용 사례)만 추가한다.
- 수식은 LaTeX(`$...$`, `$$...$$`)로 쓴다. 아래첨자/위첨자도 `$t_r$`처럼 LaTeX 문법으로.
- 이미 다른 페이지에서 다룬 개념은 반복 설명하지 말고 위키링크 참조로 대체한다(중복 금지) — 같은 자격증 안이든, 다른 자격증 페이지든 마찬가지다.
- 작성 후에는 파일 전체에 한자(漢字)가 실수로 섞여 들어가지 않았는지 확인한다(예: "고性能" 같은 오타가 실제 발생한 적 있음) — `grep -P '[一-鿿]'`로 점검 가능.
- **`<aside>` 닫는 태그 오타에 주의한다.** `</aside>`를 `</aden>`, `</aged>`, `</aige>`, `</aida>`, `</aha>` 등으로 잘못 쓰는 실수가 배치 작업 중 반복적으로 발생했다. 한 페이지(또는 여러 페이지 배치)를 다 쓴 직후 반드시 `grep -rlE '</a[a-z]{2,6}>' <대상 경로> | xargs grep -noE '</a[a-z]{2,6}>' | grep -v '</aside>'`로 점검하고, 발견 즉시 Edit로 고친다 — 커밋 전에 반드시 0건을 확인한다.

## 5. Box 용어 페이지 (`지식창고/Box/`)

- **`지식창고/Box/`는 모든 자격증이 공유하는 단일 용어 저장소다.** 로봇소프트웨어개발기사든 로봇하드웨어개발기사든, 새 용어가 나오면 먼저 이 폴더에 같은 이름의 파일이 이미 있는지 확인하고, 없을 때만 새로 만든다 — 다른 자격증 작업 중 이미 만들어진 용어라도 그대로 재사용·링크한다.
- Box 용어는 frontmatter만이 아니라 **본문 페이지 수준**(Summary+Notes asides+오답함정+핵심정리+관련노트)으로 작성한다(2026-08-01부로 확정된 방침 — 기존에는 frontmatter만 채우고 본문을 비웠지만 지금은 아니다).
  ```markdown
  ---
  cssclasses: cornell-note
  tags:
    - <분류1>
  ---

  # Summary
  (1~2문장. 핵심 정의를 **볼드**+위키링크로.)

  ---

  <div class="cues-header">Cues</div>

  # Notes

  <aside>핵심 개념/원리</aside>
  (설명. "~라는 서술은 ~을 뒤바꾼 오답이다" 형태의 정정 문장 포함)

  <aside>관련 개념과의 비교/구분</aside>
  (비슷한 용어와 헷갈리는 지점을 명확히 구분)

  ---

  <aside>핵심 정리</aside>
  - 불릿 요약

  ---

  <aside>관련 노트</aside>
  - 원 페이지: [[이 용어를 실제로 참조하는 본문 페이지]]
  - 관련: [[관련 Box 용어]]
  ```
  frontmatter의 `tags`에는 자격증명을 넣지 않는다(여러 자격증이 공유하므로) — 분류 태그만 붙인다.
- 파일명에 `/`는 쓸 수 없다 → 언더스코어 등으로 치환. 표시 텍스트가 파일명과 다르면 `[[파일명|표시텍스트]]`.
- **여러 용어를 한꺼번에(대량 배치로) 작성할 때**: 먼저 전체 지식창고를 스캔해 "각 Box 용어가 어느 본문 페이지에서 실제로 링크되는지" 매핑을 만들어두면(정규식으로 `[[용어]]` 참조를 수집하는 파이썬 스크립트 한 번으로 충분), 그 용어가 실제로 어떤 맥락에서 쓰였는지 확인하고 그 맥락에 맞게 내용을 쓸 수 있다 — 참조가 없는 용어는 세세항목명·일반 도메인 지식으로 작성한다. 14~15개 단위 배치로 나눠 각 배치를 병렬 Read → 병렬 Write → 오타/한자 grep 검증 → commit → fetch/diff → pull --rebase → push까지 매 배치 완결(다음 배치로 미루지 않는다).

## 6. 페이지 완성 후 워크플로 (매번 반복)

1. 자격증별 스킬이 지정하는 progress log 파일 맨 위에 새 날짜/회차 항목 추가 — 무엇을 작성했는지, 어떤 기출 문항을 커버했는지, 신규 Box 용어 목록, NCS 원자료 대조 결과(있었다면)를 적는다.
2. `git add`는 **방금 작업한 특정 파일만** 명시(절대 `-A`/`.` 금지) — 새 페이지들, 새/수정된 Box 용어 페이지들, progress log 파일.
3. 커밋 메시지는 한국어로, 무엇을 완료했는지 요약 + 필요시 세부 bullet, 마지막 줄에 `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
4. `git fetch origin main` 후 `git diff --numstat HEAD origin/main`로 원격이 앞서 있는지 확인.
   - `.obsidian/workspace.json`, `.makemd/*`, 플러그인 데이터 파일만 다르면 다른 기기의 Obsidian 자동 백업 커밋이므로 안전 — `git pull --rebase origin main` 후 `git push`.
   - 내가 방금 편집한 파일이 실제로 다르게 나오면(사용자가 다른 기기에서 같은 파일을 동시에 고친 경우), 그 diff를 읽고 실제 충돌인지 판단 — 진짜 충돌이면 rebase 중 conflict를 열어 두 변경을 합친다.
5. Git 커밋 author가 `Tiemp <bjh819819@naver.com>`이 아니게 자동 감지되면(푸시 전이라면) `git config user.name/user.email` 설정 후 `git commit --amend --reset-author`로 고친다.
6. 작업 완료 후 사용자에게 무엇을 했는지 간단히 요약 보고한다.

## 7. 기존 완료 세세항목을 새 자료로 재검토할 때

- 새로 발견/전달받은 NCS 원자료를 읽고, 이미 완료된 세세항목들의 실제 내용과 그 원자료의 "필요 지식" 절을 대조한다.
- 기존 페이지가 이미 잘 다루고 있는 개념은 건드리지 않는다.
- 원자료엔 있지만 기존 페이지 어디에도 없는 핵심 개념을 발견하면: 관련성이 높은 기존 페이지에 aside를 추가하거나(작은 보강), 완전히 새로운 관점이면 새 페이지 번호를 이어붙여 추가한다.
- 왜 그 내용이 빠져 있었는지 progress log에 정직하게 남긴다.
- 사용자가 "왜 그렇게 했는지" 물으면, 근거가 된 원자료의 구체적 위치(학습 번호, 섹션명)를 들어 설명한다.

## 8. 전체 검토(review) 시 체크리스트

과목 전체나 세부항목 단위로 리뷰를 요청받으면 아래를 스크립트로 자동 점검한다(내용을 전부 다시 읽기 전에 구조적 문제부터 걸러낸다):

- 위키링크 무결성: `[[...]]`, `[[...\|별칭]]`, `[[#헤딩]]` 전부 처리해서 실제 대상 파일(같은 자격증 안이든, `지식창고/Box/`든, 다른 자격증 페이지든)이 존재하는지 확인 — Box 용어 페이지 안의 링크도 검사 대상이다.
- frontmatter의 세부항목/세세항목이 실제 폴더 경로와 일치하는지
- 표 앞 빈 줄 누락 여부
- 한자 혼입 오타 (`[一-鿿]` 정규식)
- `</aside>` 오타 태그(`</aden>`, `</aged>`, `</aige>` 등) 잔존 여부
- **개요 규칙 준수**: 자격증별 스킬이 지정하는 적용 시점 이후로 개요 페이지가 없는 leaf 세세항목 폴더가 있는지 확인. 그 시점 이전 세부항목은 소급 적용 대상이 아니므로 결함으로 보고하지 않는다.
- (선택, 전체 재검토처럼 깊은 리뷰를 요청받았을 때) **문제은행 커버리지 스팟체크**: 각 과목 문제은행 JSON에서 `random.seed`를 고정해 문항을 일부 샘플링하고, 문항에서 키워드(괄호 안 영문 병기어, 대문자로 시작하는 영문 단어 등)를 정규식으로 추출한 뒤 해당 과목 전체 본문 텍스트에서 grep으로 존재 여부를 확인한다. "확인필요"로 걸린 항목은 곧바로 결함으로 보고하지 말고, 실제로 다른 페이지에 링크로만 연결되어 있는 정상 케이스(중복 금지 원칙 적용)인지, 진짜 커버리지 공백인지 원 페이지를 열어 직접 확인한 뒤 판단한다.

발견한 실제 결함만 고치고, 결과를 사용자에게 간단히 요약한다.

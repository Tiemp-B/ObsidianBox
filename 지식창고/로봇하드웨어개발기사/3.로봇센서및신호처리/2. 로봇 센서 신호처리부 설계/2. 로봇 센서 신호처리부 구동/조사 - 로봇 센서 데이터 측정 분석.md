# 조사 — 로봇 센서 데이터 측정 분석

## A. NCS 대조 결과

NCS 학습모듈 121/122 학습3 §2 "로봇 센서 신호처리부 구동" 필요지식(footer p.81~83)이 이 세세항목의 핵심 출처다. footer p.84 이후(Atmel Studio 실습, 인터럽트 예제 코드)는 수행내용(실기)이라 제외.

1. **로봇 센서의 출력 확인 — 4가지 분류 기준**:
   - 물리적 출력: **전압 출력형**(측정값을 전압으로 출력) / **전류 출력형**(측정값을 전류로 출력, 저항 연결해 전압으로 변경)
   - MCU 입력 신호 형태: **디지털 신호형**(측정값을 디지털로 출력) / **아날로그 신호형**(ADC로 디지털 변환) / **통신 신호형**(Fieldbus 등 정해진 디지털 통신 프로토콜, ISO 15735 국제표준. USART(RS-232)로 변환기 경유하거나 드라이브 회로로 직접 연결)
   - 값 확인 절차: **스탠바이형**(측정값이 항상 준비, MCU가 읽기만 함) / **요구-응답형**(MCU 요청 시 전송) / **주기 응답형**(정해진 주기마다 자동 전송) / **연속 스트림형**(측정 완료되는 대로 계속 전송)
2. **로봇 센서 신호의 확인 방식 — 폴링 vs 인터럽트**:

| 구분 | 폴링(Polling) | 인터럽트(Interrupt) |
|---|---|---|
| 방식 | MCU가 센서 신호를 **지속적으로 감시** | 신호 변경/요청 시에만 하던 일을 멈추고 ISR 실행 후 복귀 |
| 프로그램 이식성 | **높음**(하드웨어와 무관) | **낮음**(MCU별 인터럽트 종류·처리방법 차이, 타 MCU 이식 어려움) |
| 자원 효율 | 신호가 없어도 계속 리소스 소비, 폴링 간 지연 발생 | **시간 지연 없이 즉각 반응, 가장 빠른 대응 가능 → CPU 자원을 효율적으로 사용** |
| 요구 지식 | 간단 | MCU에 대한 상세한 이해 필요 |

- **인터럽트를 요청할 수 있는 내외 이벤트(interrupt source)**: RESET(리셋버튼·파워온·브라운아웃·watchdog·JTAG), 외부 인터럽트, TIMER COMP/OVF/CAPT, SPI/STC, TWI(I2C), USART RX/TX/UDRE, ADC 변환완료, EE READY, ANALOG COMP, SPM READY, FIFO FULL, TRAP(디버깅용), SWI(알 수 없는 명령어)
- 인터럽트는 **maskable**(개발자가 실행여부 설정 가능)와 **NMI**(non-maskable, 기억장치 심각한 오류·입력전압 강하 등 긴급상황에서 하드웨어로 발생)로 구분
- 여러 인터럽트 동시발생 시 **우선순위**가 정해져 있고, MCU는 인터럽트 벡터(interrupt vector)에 지정된 ISR을 실행

## B. Phase 1 — 초기 웹 조사 결과

문제은행 4문항 중 NCS 미대응 부분(FPGA 병렬처리, 표준편차)은 웹조사로 보완.

- **표준편차(Standard Deviation)**: 통계집단의 분산 정도·자료의 산포도를 나타내는 지표(분산의 음이 아닌 제곱근) — **목적은 측정값들이 평균을 중심으로 얼마나 퍼져 있는지(분산 정도)를 평가**하는 것(평균값 계산 자체·응답속도 측정·선형성 평가가 목적이 아님). — [표준 편차, 위키백과](https://ko.wikipedia.org/wiki/%ED%91%9C%EC%A4%80_%ED%8E%B8%EC%B0%A8)

## C. Phase 2 — 자체 검토

- FPGA가 "병렬 처리에 가장 적합"하다는 것은 컴퓨터구조 기초 상식(하드웨어 게이트 단위로 동시 동작 가능, CPU/DSP/MCU는 명령어를 순차 실행하는 폰노이만형 구조가 기본)이라 별도 검색 없이 도메인 지식으로 처리
- "실시간 처리를 위해 고려해야 할 가장 중요한 요소"(처리 알고리즘의 복잡도) 역시 실시간 시스템 기초 이론(복잡도가 높을수록 처리시간이 늘어나 데드라인을 놓칠 위험이 커짐)으로 판단, 추가 검색 불필요로 결론

## D. 결론(도메인 지식으로 보완)

- **센서 데이터 실시간 처리에서 가장 중요한 요소**: 센서의 정확도·가격·크기도 각각 의미 있는 스펙이지만, 실시간성 자체를 좌우하는 것은 **처리 알고리즘의 복잡도**(복잡할수록 처리시간이 늘어나 실시간 데드라인을 놓칠 위험 증가).
- **병렬 처리에 가장 적합한 하드웨어**: CPU·DSP·MCU는 명령어를 순차적으로 실행하는 구조가 기본인 반면, **FPGA는 하드웨어 게이트 배열 자체를 재구성해 여러 연산을 동시에(병렬로) 수행**할 수 있어 병렬 처리에 가장 적합.

# Summary

인터럽트는 필요할 때만 반응해 CPU 자원을 효율적으로 쓰지만 이식성이 낮고, 폴링은 반대로 이식성은 높지만 리소스를 계속 소비한다. 실시간 처리는 처리 알고리즘의 복잡도가 좌우하고, 병렬 처리는 FPGA가 유리하며, 표준편차는 측정값의 분산 정도를 나타낸다.

# Notes

<aside>폴링(Polling) vs 인터럽트(Interrupt)</aside>

| 구분 | 폴링 | 인터럽트 |
|---|---|---|
| 방식 | MCU가 센서 신호를 **지속적으로 감시** | 신호 변경/요청 시에만 하던 일을 멈추고 ISR 실행 후 복귀 |
| 이식성 | **높음**(하드웨어와 무관) | **낮음**(MCU별 인터럽트 종류·처리 차이) |
| 자원 효율 | 신호가 없어도 계속 리소스 소비, 폴링 간 지연 발생 | **시간 지연 없이 즉각 반응 → CPU 자원을 효율적으로 사용**(가장 빠른 대응) |
| 필요 지식 | 간단 | MCU에 대한 상세한 이해 필요 |

- **인터럽트 방식의 장점**: **CPU 자원을 효율적으로 사용한다**(프로그램 구조 간단·처리순서 예측 쉬움·디버깅 용이는 오히려 폴링 쪽 특성에 가까움)

<aside>인터럽트 소스와 우선순위</aside>

- **인터럽트 요청 이벤트 종류**: RESET(리셋버튼·파워온·브라운아웃·watchdog·JTAG), 외부 인터럽트, TIMER COMP/OVF/CAPT, SPI/STC, TWI(I2C), USART RX/TX/UDRE, ADC 변환완료, EE READY, ANALOG COMP, SPM READY, FIFO FULL, TRAP(디버깅용), SWI(알수없는명령어)
- **maskable interrupt**(개발자가 실행 여부 설정 가능) vs **NMI**(non-maskable, 기억장치 심각한 오류·입력전압 강하 등 긴급상황에서 하드웨어로 발생)
- 여러 인터럽트 동시 발생 시 **우선순위**가 정해져 있고, MCU는 **인터럽트 벡터(interrupt vector)**에 지정된 ISR을 실행

<aside>실시간 처리와 병렬 처리</aside>

- **센서 데이터 실시간 처리에서 가장 중요한 요소**: **처리 알고리즘의 복잡도**(복잡할수록 처리시간이 늘어나 실시간 데드라인을 놓칠 위험 증가 — 센서의 정확도·가격·크기는 실시간성 자체를 좌우하지 않음)
- **병렬 처리에 가장 적합한 하드웨어**: **FPGA** — 하드웨어 게이트 배열을 재구성해 여러 연산을 동시에 수행 가능(CPU·DSP·MCU는 명령어를 순차 실행하는 구조가 기본)

<aside>표준편차(Standard Deviation)</aside>

- 분산의 음이 아닌 제곱근, 자료의 산포도를 나타내는 지표
- **사용 목적**: **측정값들이 평균을 중심으로 얼마나 퍼져 있는지(분산 정도)를 평가**(평균값 계산 자체·응답속도 측정·선형성 평가가 목적이 아님)

---

<aside>핵심 정리</aside>

- 인터럽트=CPU자원 효율적 사용(이식성은 낮음), 인터럽트소스는 다양·우선순위·인터럽트벡터로 관리
- 실시간처리 핵심요소=알고리즘 복잡도, 병렬처리=FPGA, 표준편차=분산정도 평가

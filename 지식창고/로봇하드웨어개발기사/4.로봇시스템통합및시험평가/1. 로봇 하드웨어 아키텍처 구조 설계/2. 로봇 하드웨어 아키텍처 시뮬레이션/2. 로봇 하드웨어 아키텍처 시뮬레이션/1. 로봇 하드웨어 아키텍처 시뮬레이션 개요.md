# Summary

로봇 시뮬레이터는 실제 로봇 없이 개발 비용과 시간을 절약하는 도구이며, 3D CAD·해석·기구학·오프라인 프로그래밍 툴로 나뉜다. 이산사건 시뮬레이션은 불규칙한 이벤트 기반 시스템에, HIL은 실시간 검증에, 몬테카를로는 불확실성 하의 신뢰성 분석에, SystemC는 하드웨어·소프트웨어 동시설계에 쓰인다.

<aside>로봇 시뮬레이터(NCS)</aside>

- 실제 로봇에 의존하지 않고 응용 프로그램을 작성·검증하는 툴, 다양한 변수값을 설정해 **개발 비용과 시간을 절약**
- 제조업체 시뮬레이터는 작성 프로그램을 실제 로봇에 전송·재구성 가능
- 4가지 소프트웨어 유형: **3D CAD/드로잉**(CATIA, SolidWorks), **구조 해석**(ANSYS, RecurDyn), **기구학/역기구학**(MATLAB Robotics Toolbox, ROS Gazebo), **오프라인 프로그래밍**(제조사 제공, Siemens RobotExpert·Kawasaki KCONG 등)
- **아키텍처 시뮬레이션의 주요 목적**: **실제 제작 전 설계 검증**(마케팅 자료 제작·특허 출원 준비·경쟁사 분석이 목적이 아님)

<aside>이산사건 시뮬레이션(Discrete Event Simulation)</aside>

- 시뮬레이션 시계가 고정 간격이 아니라 사건(이벤트) 발생 시점 단위로 진행
- **선택하기 가장 적절한 경우**: **불규칙한 이벤트 기반 시스템 분석**(생산 계획·스케줄링, 대기열 관리 등) — 연속적 동작 제어·실시간 피드백 제어·아날로그 신호 처리에는 부적합

<aside>HIL(Hardware-In-the-Loop) 테스트</aside>

- 제어 유닛을 센서·액추에이터의 정밀 시뮬레이션과 전자적으로 연결해 임베디드 소프트웨어를 검증
- **FPGA를 활용한 HIL의 주된 장점**: 매우 빠른 루프 속도로 **실시간 동작 검증** 가능(단선·단락 등 전기적 고장, 통신 이상 진단도 실시간 수행)

<aside>몬테카를로(Monte Carlo) 시뮬레이션</aside>

- 난수를 이용해 다수의 시뮬레이션을 반복 실행하고 결과를 통계적으로 분석
- **주된 목적**: 복잡한 시스템의 잠재적 오류 지점을 식별하고 설계를 최적화하기 위한 **불확실성을 고려한 신뢰성 분석**(실시간 제어 성능 향상·기구학적 해석·에너지 효율성 최적화가 목적이 아님)

<aside>SystemC</aside>

- C++ 기반 오픈소스 시스템 설계 언어, 이벤트 기반 시뮬레이션 인터페이스 제공
- 고수준 시스템 아키텍처부터 저수준 하드웨어 세부사항까지 다양한 추상화 수준에서 모델링 가능
- **가장 큰 특징**: 소프트웨어 모듈과 하드웨어 모듈을 함께 시뮬레이션(코시뮬레이션) — **하드웨어와 소프트웨어의 동시 설계**(인터프리터 언어 기반·그래픽 기반 모델링·RTOS 지원이 핵심 특징이 아님)

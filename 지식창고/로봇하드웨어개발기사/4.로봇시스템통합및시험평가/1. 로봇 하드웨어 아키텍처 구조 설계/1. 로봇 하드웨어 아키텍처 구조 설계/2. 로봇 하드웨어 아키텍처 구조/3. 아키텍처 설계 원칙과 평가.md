# Summary

아키텍처 설계는 시스템 요구사항 분석에서 시작하고, RTOS는 결정론적 시간 응답성이 핵심이다. 성능 벤치마킹은 실행 시간을 산업표준·경쟁제품과 비교해 평가하며, 6자유도는 3차원 공간의 위치와 자세를 완전히 제어할 수 있게 한다.

# Notes

<aside>아키텍처 설계의 우선순위</aside>

- 제조비용 최소화·외관 디자인·마케팅 전략보다 **시스템 요구사항 분석**이 모든 설계의 출발점(요구사항이 정해져야 구조·사양이 결정됨)

<aside>RTOS(Real-Time Operating System)</aside>

- 멀티태스킹·GUI·파일시스템 관리는 RTOS 고유의 특징이 아님
- **가장 중요한 특징**: **결정론적 시간 응답성**(정해진 데드라인 안에 반드시 응답) — 과목2 D14에서 이미 검증된 내용

<aside>성능 벤치마킹</aside>

| 항목 | 내용 |
|---|---|
| 가장 중요한 지표 | **실행 시간**(코드크기·메모리사용량·전력효율성도 의미 있으나 성능을 직접 나타내는 것은 실행시간) |
| 비교 기준 | **산업 표준 및 경쟁 제품 사양**(개발자 개인취향·회사내부정치·무작위선택은 객관적 기준이 아님) |

<aside>버스 중재(Bus Arbitration) 방식</aside>

- 실제 표준 방식: **데이지 체인**(장치를 순차 연결), **중앙 중재**(하나의 중재기가 결정), **자체(분산) 중재**(각 마스터가 자체 중재기 보유)
- **"순차 접근 방식"은 표준적인 버스 중재 방식 명칭으로 확인되지 않음** — 가장 부적절한 선택지

<aside>자유도(DOF) 6</aside>

- 3자유도는 **위치**(Position, X·Y·Z), 나머지 3자유도는 **자세**(Orientation, Roll·Pitch·Yaw)
- 6축 수직다관절 로봇은 이 6-DOF로 **3차원 공간에서 위치와 자세를 완전히 제어**(J1~J3=위치 결정 주축, J4~J6=자세 결정 부축)

---

<aside>핵심 정리</aside>

- 아키텍처 설계 최우선=요구사항분석, RTOS=결정론적응답성, 벤치마킹=실행시간(산업표준·경쟁제품 기준), 버스중재 3방식(순차접근은 아님), DOF6=3차원 위치+자세 완전제어

# 액추에이터 통신방식 설계 — 조사 원자료 (정보덩어리)

## A. NCS 대조
학습2 필요지식엔 통신방식에 대한 상세 내용 없음 — 문제은행(14문항)+웹조사로 구성. 이전 작성분에서 근거 없이 단정했던 부분이라 이번엔 항목별로 출처를 명확히 확보.

## B. 웹 검색 결과 (2026-08-01)

### B1. CAN 비트레이트-통신거리
- **CAN 버스는 40m 이하 네트워크 길이에서 1Mbps까지 전송 가능** — 기존에 썼던 "1Mbps일 때 약 40m"와 정확히 일치, 확인됨
- 이론상 최대 속도는 1Mbps이나, 차량 배선 설계 자유도를 위해 실제로는 500kbps를 주로 사용해온 관행도 있음(참고 정보)
- 출처: [CAN 버스 (위키백과)](https://ko.wikipedia.org/wiki/CAN_%EB%B2%84%EC%8A%A4)

### B2. CAN 중재(Arbitration)와 우선순위
- Dominant bit(0, High전압)와 Recessive bit(1, Low전압)가 동시 전송되면 버스에는 **Dominant만 관찰**됨
- ID가 **더 많은 Dominant bit로 시작할수록(=ID 값이 작을수록) 우선순위가 높음** — 자신이 recessive(1)를 보내려는데 버스가 dominant(0)면 송신 중단(양보)
- 표준 CAN 11비트 ID 기준 최고 우선순위는 **0x000**(모든 비트가 dominant) — 기존 서술과 일치
- 출처: [CAN(통신) (나무위키)](https://namu.wiki/w/CAN(%ED%86%B5%EC%8B%A0)), [CAN 통신의 개념과 원리](https://www.gyuray.dev/can-bus-protocol)

### B3. CAN 비트 스터핑
- ISO 11898-1: **동일 비트가 5개 연속되면 반대 비트 1개를 강제 삽입**(기존 서술과 일치)
- 목적: (1) 동일 비트가 너무 길게 이어지면 수신측 클럭이 동기화되지 않을 수 있어 **동기화 유지**, (2) 프레임 경계(시작/끝)를 정확히 인식하게 함
- 출처: [CAN_K: 비트 스터핑 (Vector E-Learning)](https://elearning.vector.com/mod/page/view.php?id=1901)

### B4. RS-485 vs RS-232
- RS-485 이론적 최대 거리: **약 1200m**(4000ft) — 기존 서술("약 1.2km")과 일치
- RS-485 최대 장치수: 표준은 **32개**(유닛 로드 기준), 저부하 수신기(1/8 UL) 사용 시 이론상 최대 256개까지 가능(참고 정보, 기존 "최대 32개"는 표준 기준으로 여전히 맞음)
- RS-232는 단일(싱글엔드) 신호·단거리·1:1, RS-485는 차동 신호·장거리·멀티드롭 — 기존 서술과 일치
- 출처: [RS-485 (나무위키)](https://namu.wiki/w/RS-485), [RS485는 어떻게 배선되나요? (SenTec)](https://cdsentec.com/ko/docs/how-is-rs485-wired/)

### B5. EtherCAT
- Flying-through(온더플라이) 방식: 마스터가 프레임을 보내면 각 슬레이브 노드가 **차례로 프레임을 받아 즉시 처리하고 다음 노드로 전달**, 슬레이브당 처리 지연이 **1µs 미만** — 기존 서술("프레임이 각 노드를 순차적으로 통과하며 처리")과 일치
- 출처: [EtherCAT Protocol Explained](https://scadaprotocols.com/ethercat-protocol-explained/), [EtherCAT 통신의 개념과 원리](https://www.gyuray.dev/ethercat)

### B6. PROFIBUS-DP
- 마스터-슬레이브 구조, **마스터가 슬레이브를 주기적(순차적)으로 폴링**하며 데이터 교환(요청에 출력데이터, 응답에 입력데이터) — 기존 서술과 일치
- 폴링 주기는 통상 1~512ms 범위에서 설정 가능(참고 정보)
- 출처: [How does PROFIBUS DP work? (PI North America)](https://us.profinet.com/how-does-profibus-dp-work/)

### B7. CC-Link 사이클릭 전송
- 사이클릭 전송 = 지정 영역 데이터를 **정기적으로 자동 송신**(설정만 하면 별도 프로그래밍 없이 자동 반복) — "주기적" 특성이 핵심
- 컨트롤러·서보앰프의 제어주기와 동기화된 정주기 통신 가능
- 기존 서술("이벤트 발생 시 즉시 전송이 가능하다는 것은 사이클릭 전송의 특징이 아니다")과 부합 — 사이클릭은 주기적 자동전송이 본질이지 이벤트 기반이 아님
- 출처: [CC-Link IE 특징 (미쓰비시전기)](https://kr.mitsubishielectric.com/fa/ko/product.do?act=productList&cate_id=2&parent_id=537)

## C. 결론
- 이전 작성분의 CAN/RS-485/EtherCAT/PROFIBUS-DP/CC-Link 관련 수치·설명이 **전부 검색으로 확인됨**(정확했음) — 이번엔 각 항목에 출처를 명시해 신뢰도를 높임
- Modbus RTU CRC(오류검출), RS-232/RS-485 기본 차이는 매우 표준적인 지식이라 위 조사로 충분

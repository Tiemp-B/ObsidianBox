# Summary

CAN(Controller Area Network)은 **멀티마스터 방식**과 **메시지 ID 기반 비트 단위 중재**로 여러 노드가 하나의 버스를 공유하면서도 충돌 없이 통신할 수 있게 설계된 필드버스로, 로봇 관절 액추에이터 간 통신에 널리 쓰인다.

# Notes

<aside>멀티마스터와 버스 구조</aside>

CAN은 **멀티마스터 방식**(모든 노드가 버스 마스터가 될 수 있음)이며, 모든 노드가 버스에 병렬로 연결되는 **버스형 구조**로 통신한다 — "CAN은 점대점(point-to-point) 통신만 가능하다"는 서술은 버스형 멀티마스터 구조라는 핵심 특징을 뒤바꾼 오답(함정)이다.

<aside>메시지 중재(Arbitration)와 우선순위</aside>

여러 노드가 동시에 전송을 시도하면, **메시지 ID(Identifier) 필드**를 비트 단위로 비교해 중재한다.
- CAN은 **Dominant 비트(0)가 Recessive 비트(1)보다 우선**하는 와이어드-OR 방식이다 — 두 비트가 동시에 전송되면 버스에는 Dominant만 관찰되며, Recessive(1)를 보내려던 노드가 버스에서 Dominant(0)를 감지하면 즉시 송신을 중단(양보)한다
- 따라서 **ID 값이 작을수록(Dominant 비트로 시작할수록) 우선순위가 높다** — 표준 CAN(11비트 ID) 기준 가장 높은 우선순위 메시지 ID는 **0x000**이다
- 이는 이더넷의 CSMA/CD(충돌 감지 후 재전송)와 다르다 — CAN은 충돌이 나도 데이터를 잃지 않고 비트 단위로 즉시 중재해 낮은 우선순위 노드가 자동으로 양보한다

<aside>비트 스터핑과 오류 프레임</aside>

- **비트 스터핑(Bit Stuffing)**: ISO 11898-1 규정에 따라 동일한 값의 비트가 **5개 연속**되면 반대값 비트 1개를 강제로 삽입하는 기법으로, 목적은 (1) 동일 비트가 길게 이어져 수신 노드의 **클럭 동기화가 어긋나는 것을 방지**하고, (2) 프레임의 시작·끝 경계를 정확히 인식시키는 것이다
- **오류 프레임(Error Frame)**: 노드가 통신 중 **오류를 검출했을 때** 즉시 전송해 다른 모든 노드에 오류 발생을 알리는 프레임 — 정상 전송이나 버스 유휴 상태에서는 전송되지 않는다

<aside>물리적 특성: 비트레이트와 통신 거리</aside>

CAN은 **40m 이하의 네트워크 길이에서 1Mbps**까지 전송할 수 있다(비트레이트가 높을수록 신호 반사·지연 여유가 줄어 통신 가능 거리가 짧아지는 관계). 차량 배선 설계의 자유도를 위해 실제 현장에서는 이론상 최대 속도(1Mbps)보다 낮은 500kbps 등을 쓰는 경우도 많다.

---

<aside>핵심 정리</aside>

- CAN은 멀티마스터·버스형 구조, 점대점 통신이 아님
- 메시지 ID로 비트 단위 중재, **Dominant(0) 우선 → ID 작을수록 고우선순위**(0x000이 최고)
- 비트 스터핑(5비트 연속시 강제삽입)은 **동기화 유지+프레임 경계 인식**, 오류 프레임은 **오류 검출 시**에만 전송
- 1Mbps일 때 최대 통신거리는 약 40m

# Summary

CAN 외에도 저비용·장거리에는 **RS-485/Modbus RTU**, 초고속 동기 모션 제어에는 **EtherCAT**, 산업 현장의 마스터-슬레이브 구조에는 **CC-Link·PROFIBUS-DP**가 쓰인다. 각 프로토콜의 물리 신호 방식과 데이터 교환 방식을 구분하는 것이 핵심이다.

# Notes

<aside>RS-232 vs RS-485</aside>

| 구분 | RS-232 | RS-485 |
|---|---|---|
| 신호 방식 | 단일(싱글엔드) 신호 | 차동(differential) 신호 |
| 통신 거리 | 짧음(수 m) | 길음(최대 약 1.2km) |
| 노이즈 내성 | 낮음 | 높음(두 선의 전압 차만 보므로 공통 노이즈가 상쇄) |
| 다중 접속 | 1:1(포인트-투-포인트)만 | 최대 32개 장치까지 멀티드롭 가능 |

RS-485는 차동 신호 덕분에 **노이즈 내성이 우수**하고 **장거리 통신**이 가능하다는 것이 핵심 장점이다 — "RS-232는 차동신호, RS-485는 단일신호"라고 뒤바꿔 서술하는 것이 대표적인 오답(함정)이다.

<aside>Modbus RTU</aside>

Modbus RTU는 마스터-슬레이브 구조의 직렬 통신 프로토콜로, 프레임 끝에 **CRC(Cyclic Redundancy Check)** 필드를 붙인다. CRC의 역할은 **데이터 전송 중 발생한 오류를 검출**하는 것이며, 암호화나 속도 조절, 주소 지정과는 무관하다.

<aside>EtherCAT</aside>

EtherCAT은 이더넷 프레임이 **각 노드를 순차적으로 통과하며(flying-through)** 지나가는 노드에서 필요한 데이터만 즉시 읽고/쓰는 방식으로, 별도의 스위치 없이도 마이크로초 단위의 실시간 동기 제어가 가능하다 — 토큰 방식 버스 제어나 노드 수 32개 제한 같은 서술은 EtherCAT의 특징이 아니라 오답(함정)이다.

<aside>CC-Link의 사이클릭 전송</aside>

CC-Link의 **사이클릭 전송**은 정해진 시간 간격으로 주기적으로 데이터를 주고받아 마스터-슬레이브 간 동기화를 유지하는 실시간 제어용 통신 방식이다. **"이벤트 발생 시 즉시 전송이 가능하다"는 것은 사이클릭(주기적) 전송이 아니라 메시지(비주기적) 전송의 특징**이므로, 사이클릭 전송의 특징으로 보기에는 가장 부적절하다.

<aside>PROFIBUS-DP</aside>

PROFIBUS-DP는 하나의 **마스터가 여러 슬레이브를 순차적으로 폴링(polling)**하며 데이터를 교환하는 방식이 기본이다. 슬레이브끼리 직접 통신하거나 슬레이브가 자발적으로 데이터를 보내는 방식이 아니라는 점이 핵심이며, "토큰 패싱 방식만 사용한다"는 서술도 오답(함정)이다(토큰 패싱은 마스터 간 버스 권한 이양에 쓰이는 별도 메커니즘).

---

<aside>핵심 정리</aside>

- RS-485 = 차동신호·장거리·멀티드롭, RS-232 = 단일신호·단거리·1:1
- Modbus RTU의 CRC = **오류 검출**용
- EtherCAT = 프레임이 각 노드를 순차 통과하며 처리(flying-through)
- CC-Link 사이클릭 전송 = **주기적** 동기화(즉시 이벤트 전송은 아님)
- PROFIBUS-DP = 마스터가 슬레이브를 순차 **폴링**

# Summary

CAN 외에도 저비용·장거리에는 **RS-485/RS-422·Modbus RTU**, 초고속 동기 모션 제어에는 **EtherCAT**, 산업 현장의 마스터-슬레이브 구조에는 **CC-Link·PROFIBUS-DP**가 쓰인다. 각 프로토콜의 물리 신호 방식, 데이터 교환 방식, 그리고 속도·토폴로지·실시간성 급을 구분하는 것이 핵심이다.

# Notes

<aside>대표적 시리얼 통신 — RS-232·RS-485·RS-422</aside>

| 구분 | RS-232 | RS-485 | RS-422 |
|---|---|---|---|
| 신호 방식 | 단일(싱글엔드) 신호 | 차동(differential) 신호 | 차동(differential) 신호 |
| 배선 | 2선(TX/RX 분리) | 2선(공유 버스) | 4선(TX쌍/RX쌍 분리) |
| 통신방식 | 전이중(Full-duplex) — TX·RX 선이 분리되어 송수신 동시 가능 | 반이중(Half-duplex) — 하나의 선 쌍을 송신·수신이 번갈아 사용, 동시 송수신 불가 | 전이중(Full-duplex) — 송신용·수신용 선 쌍이 분리되어 동시 송수신 가능 |
| 통신 거리 | 짧음(수 m) | 길음(이론상 최대 약 1200m) | 길음(이론상 최대 약 1200m) |
| 노이즈 내성 | 낮음 | 높음(두 선의 전압 차만 보므로 공통 노이즈가 상쇄) | 높음(RS-485와 동일 원리) |
| 연결 구조 | 1:1(포인트-투-포인트)만 | 다중 송신기가 하나의 버스를 공유하는 멀티드롭(표준 32개, 저부하 수신기 사용 시 최대 256개까지) | **1개 송신기 : 최대 10개 수신기**의 단방향 점대다중점(point-to-multipoint) |

RS-485와 RS-422는 둘 다 차동 신호로 노이즈 내성·통신 거리가 우수하지만, 통신방식과 연결 구조에서 갈린다 — RS-485는 2선을 반이중으로 공유하며 여러 송신기가 한 버스에 올라가는 진정한 멀티드롭 구조이고, RS-422는 4선으로 송신·수신 경로를 분리해 전이중 통신하되 송신기는 하나만 둘 수 있다. RS-485는 공통모드 허용 범위(-7V~+12V)가 RS-422(±3V)보다 넓어, 여러 송신기가 뒤섞이는 가혹한 버스 환경에 더 적합하다.

<aside>Modbus</aside>

Modbus는 1:N 마스터-슬레이브 구조의 통신 프로토콜이다.
- Modbus RTU: 바이너리 데이터형 전송 방식(직렬, RS-232 또는 RS-485)
- Modbus ASCII: ASCII 문자를 사용하는 텍스트형 전송 방식(직렬)
- Modbus TCP/IP: RTU와 데이터 구조는 유사하나 TCP/IP 계층 위에서 동작

프레임 끝에 **CRC(Cyclic Redundancy Check)** 필드를 붙이며, 그 역할은 **데이터 전송 중 발생한 오류를 검출**하는 것이다(암호화·속도 조절·주소 지정과는 무관).

**Modbus 데이터 모델**은 읽기/쓰기 가능 여부와 비트/워드 단위로 4가지로 나뉜다.

| 유형 | 크기 | 접근 |
|---|---|---|
| Coils | 1비트 | 읽기/쓰기 |
| Discrete Inputs | 1비트 | 읽기 전용 |
| Input Registers | 16비트 | 읽기 전용 |
| Holding Registers | 16비트 | 읽기/쓰기 |

이름에 "Input"이 붙은 두 유형(Discrete Inputs, Input Registers)은 읽기 전용이라는 명명 규칙으로 구분하면 기억하기 쉽다.

<aside>EtherCAT</aside>

**[[EtherCAT]]**은 **flying-through(온더플라이) 방식**으로 각 슬레이브가 프레임 통과 순간에 즉시 데이터를 읽고 쓰는 초저지연(슬레이브당 1µs 미만) 실시간 이더넷이다. 다축 동기 제어를 위한 **분산 클록(Distributed Clock)** 기능도 갖추고 있다 — 상세 원리는 [[EtherCAT]] 참고(중복 서술 없음).

<aside>CC-Link의 사이클릭 전송</aside>

CC-Link의 **사이클릭 전송**은 지정된 데이터 영역을 **정기적으로 자동 송신**하는 방식으로(별도 프로그래밍 없이 설정만으로 반복 전송), 컨트롤러·서보앰프의 제어 주기와 동기한 정주기 통신이 가능하다. 이벤트 발생 시점에 비주기적으로 보내는 메시지(비사이클릭) 전송과는 구분되는 개념이다.

기존 CC-Link는 RS-485 기반의 ~10Mbps급 프로토콜이며, 차세대 규격인 **CC-Link IE**는 기가비트 이더넷 기반으로 옮겨간 버전이다(PROFIBUS가 PROFINET으로 세대교체된 것과 유사한 관계).

<aside>PROFIBUS-DP</aside>

PROFIBUS-DP는 하나의 **마스터가 여러 슬레이브를 순차적으로, 주기적으로 폴링(polling)**하며 데이터를 교환하는 방식이 기본이다(요청 메시지에 출력 데이터, 응답 메시지에 입력 데이터를 담아 교환). 다중 마스터 간에는 버스 권한을 순서대로 넘기는 토큰 패싱이 쓰이지만, 이는 마스터-슬레이브 간 폴링과는 별도의 메커니즘이다.

<aside>프로토콜 비교</aside>

| 프로토콜 | 최대 속도 | 토폴로지 | 실시간성 |
|---|---|---|---|
| CAN | ~1Mbps | 버스형 | 중재 기반 준실시간 |
| RS-485/Modbus RTU | 수십kbps~115.2kbps급 | 버스형(멀티드롭) | 소프트 실시간 |
| PROFIBUS-DP | ~12Mbps | 버스형+토큰패싱 | 하드 실시간 |
| CC-Link | ~10Mbps | 버스/데이지체인 | 토큰 기반 하드 실시간 |
| EtherCAT | 100Mbps | 논리적 링(물리적 데이지체인) | 하드 실시간(서브ms 주기) |

<aside>핵심 정리</aside>

- RS-485 = 2선식 반이중·다중송신기 멀티드롭 / RS-422 = 4선식 전이중·1송신기:10수신기 — 둘 다 차동신호·장거리(~1200m)
- Modbus RTU의 CRC = **오류 검출**용, 데이터 모델은 Coils/Discrete Inputs/Input Registers/Holding Registers 4종
- EtherCAT = flying-through(슬레이브당 지연 1µs 미만)와 분산 클록(전체 동기 정밀도 수백ns~1µs)은 별개 개념
- CC-Link 사이클릭 전송 = **주기적** 자동 동기화, CC-Link IE는 기가비트 이더넷 기반 차세대 규격
- PROFIBUS-DP = 마스터가 슬레이브를 순차·주기적으로 **폴링**
- 실시간성 등급: CAN·RS-485(소프트~준실시간) < PROFIBUS-DP·CC-Link(하드) < EtherCAT(가장 빠른 하드 실시간)

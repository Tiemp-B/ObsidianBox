# Summary

CAN 외에도 저비용·장거리에는 **RS-485/Modbus RTU**, 초고속 동기 모션 제어에는 **EtherCAT**, 산업 현장의 마스터-슬레이브 구조에는 **CC-Link·PROFIBUS-DP**가 쓰인다. 각 프로토콜의 물리 신호 방식과 데이터 교환 방식을 구분하는 것이 핵심이다.

# Notes

<aside>시리얼 통신 RS-232 vs RS-485</aside>

| 구분 | RS-232 | RS-485 |
|---|---|---|
| 신호 방식 | 단일(싱글엔드) 신호 | 차동(differential) 신호 |
| 통신 거리 | 짧음(수 m) | 길음(이론상 최대 약 1200m) |
| 노이즈 내성 | 낮음 | 높음(두 선의 전압 차만 보므로 공통 노이즈가 상쇄) |
| 다중 접속 | 1:1(포인트-투-포인트)만 | 표준 32개(저부하 수신기 사용 시 최대 256개까지) 멀티드롭 가능 |

RS-485는 차동 신호 덕분에 **노이즈 내성이 우수**하고 **장거리 통신**이 가능하다는 것이 핵심 장점이다.

<aside>Modbus</aside>

Modbus는 1:N 마스터-슬레이브 구조의 직렬(RS-232 또는 RS-485) 통신 프로토콜이다.
- Modbus RTU
- Modbus ASCII
- Modbus 
프레임 끝에 **CRC(Cyclic Redundancy Check)** 필드를 붙인다. CRC의 역할은 **데이터 전송 중 발생한 오류를 검출**하는 것이며, 암호화나 속도 조절, 주소 지정과는 무관하다.

<aside>EtherCAT</aside>

EtherCAT은 **flying-through(온더플라이) 방식**을 쓴다 — 마스터가 프레임을 네트워크에 보내면 앞쪽 슬레이브 노드부터 차례로 프레임을 받아, 자신에게 필요한 데이터를 읽고 자신의 출력 데이터를 프레임에 기록한 뒤 즉시 다음 노드로 넘긴다. 슬레이브당 처리 지연이 **1µs 미만**이라 별도 스위치 없이도 마이크로초 단위의 실시간 동기 제어가 가능하다.

<aside>CC-Link의 사이클릭 전송</aside>

CC-Link의 **사이클릭 전송**은 지정된 데이터 영역을 **정기적으로 자동 송신**하는 방식으로(별도 프로그래밍 없이 설정만으로 반복 전송), 컨트롤러·서보앰프의 제어 주기와 동기한 정주기 통신이 가능하다. **"이벤트 발생 시 즉시 전송이 가능하다"는 것은 사이클릭(주기적) 전송이 아니라 메시지(비주기적) 전송의 특징**이므로, 사이클릭 전송의 특징으로 보기에는 가장 부적절하다.

<aside>PROFIBUS-DP</aside>

PROFIBUS-DP는 하나의 **마스터가 여러 슬레이브를 순차적으로, 주기적으로 폴링(polling)**하며 데이터를 교환하는 방식이 기본이다(요청 메시지에 출력 데이터, 응답 메시지에 입력 데이터를 담아 교환). 슬레이브끼리 직접 통신하거나 슬레이브가 자발적으로 데이터를 보내는 방식이 아니라는 점이 핵심이다. 참고로 토큰 패싱은 다중 마스터 간 버스 권한 이양에 쓰이는 별도의 메커니즘이다.

<aside>핵심 정리</aside>

- RS-485 = 차동신호·장거리(~1200m)·표준 32대 멀티드롭, RS-232 = 단일신호·단거리·1:1
- Modbus RTU의 CRC = **오류 검출**용
- EtherCAT = flying-through 방식, 슬레이브당 처리지연 1µs 미만의 초저지연 실시간 통신
- CC-Link 사이클릭 전송 = **주기적** 자동 동기화(즉시 이벤트 전송은 메시지 전송의 특징)
- PROFIBUS-DP = 마스터가 슬레이브를 순차·주기적으로 **폴링**

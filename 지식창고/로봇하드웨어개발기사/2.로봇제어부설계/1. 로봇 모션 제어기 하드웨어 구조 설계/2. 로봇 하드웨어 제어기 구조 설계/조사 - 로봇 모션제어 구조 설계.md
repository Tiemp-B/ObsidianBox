# 조사 — 로봇 모션제어 구조 설계

## A. NCS 대조 결과

NCS 학습모듈 117/118에는 이 세세항목(백래시·역기구학·경로계획·RTOS·샘플링주파수·DH파라미터 등)에 대응하는 필요지식이 없다. 문제은행 14문항(전체 3위 규모) 전량을 웹 조사·도메인 지식으로 작성한다.

## B. 웹 검색 결과

1. **백래시(Backlash)와 예압(Preload)**: 기어의 백래시(치면 사이의 유격)를 줄이는 대표적 방법은 **예압(Preload)** — 맞물리는 같은 축의 기어에 스프링 등으로 토크를 걸어 치면 사이 유격을 제거하는 방식. 톱니 테이퍼링, 정밀 기어 사용 등도 보조적 방법. — [기어 백래시를 최소화하거나 없애는 방법?](https://motioncontrol.co.kr/technical-info?tpf=board/view&board_code=2&code=9017), [백래시(공학), 위키백과](https://ko.wikipedia.org/wiki/%EB%B0%B1%EB%9E%98%EC%8B%9C_(%EA%B3%B5%ED%95%99))
2. **역기구학(Inverse Kinematics)**: 로봇 관절의 각도들을 손끝(말단) 위치로 바꾸는 것이 **정기구학(Forward Kinematics)**, 그 반대로 **말단 위치(작업공간 좌표)를 관절 각도(관절공간 좌표)로 바꾸는 것이 역기구학**. 목적은 "목표 위치에서 필요한 관절 각도 계산". — [Inverse Kinematics(역기구학)란, T-Robotics](https://t-robotics.blogspot.com/2015/09/inverse-kinematics.html)
3. **관절공간(Joint Space) vs 작업공간(Task Space)**: 실제 작업이 이루어지는 x,y,z(+자세) 공간이 작업공간, 로봇이 제어되는 각 관절 각도(q₁...qₙ) 공간이 관절공간. 로봇은 작업공간 상의 목표 궤적을 관절공간 궤적으로 변환(역기구학)해 각 관절에 명령한다 — 두 공간의 차이는 **제어 대상 변수의 차이**(작업공간=말단 좌표, 관절공간=관절 각도). — [로봇이 움직이는 공간, Joint Space, T-Robotics](http://t-robotics.blogspot.com/2013/07/joint-space.html)
4. **A* 알고리즘**: 실제 경로 비용(g)과 목적지까지의 추정 비용(휴리스틱, h)을 합산(f=g+h)해 우선순위를 정하는 그래프 탐색 알고리즘. 휴리스틱이 admissible(목적지까지 남은 거리를 과대평가하지 않음)하면 **최적 경로(최단경로)가 보장**된다 — 이것이 A*를 사용하는 주된 이유. — [A* 알고리즘, 위키백과](https://ko.wikipedia.org/wiki/A*_%EC%95%8C%EA%B3%A0%EB%A6%AC%EC%A6%98)
5. **RTOS(실시간 운영체제)**: 응용 태스크의 처리 시간을 일관되게 유지하는 것이 핵심으로, **결정적 응답시간(Deterministic Response Time)**이 RTOS의 대표 특징(높은 처리량이나 복잡한 그래픽 처리가 목적이 아님). 데드라인을 결정론적으로 충족하면 경성 실시간(hard real-time) OS로 분류. — [실시간 운영체제, 위키백과](https://ko.wikipedia.org/wiki/%EC%8B%A4%EC%8B%9C%EA%B0%84_%EC%9A%B4%EC%98%81_%EC%B2%B4%EC%A0%9C)
6. **DH 파라미터(Denavit-Hartenberg)**: 인접 링크 간의 공간 관계를 기술하는 4개 파라미터 — **링크 길이(a)**, **링크 비틀림각(α)**, **링크 오프셋(d)**, **관절각(θ)**. "관성 모멘트(I)"는 이 4개 파라미터에 포함되지 않는다(동역학 파라미터이지 기구학 파라미터가 아님). — [DH parameters, Universal Robots](https://www.universal-robots.com/developer/hardware-and-motion/robot-motion-dh-parameters/)

## C. 결론(도메인 지식으로 보완, 검색 불필요한 기초 사실)

- **속도 제어 루프와 위치 제어 루프의 관계**: 캐스케이드(cascade) 구조로, **속도 루프가 위치 루프의 내부(하위) 루프**다 — 위치 제어기의 출력이 속도 지령이 되어 속도 루프에 입력되는 구조(D11의 "위치제어는 속도제어를 포함하는 상위 루프"와 동일한 내용).
- **엔코더의 주요 기능**: 모터/관절의 **위치 및 속도 피드백**을 제공하는 센서 — 전력 공급·모터 구동·통신 인터페이스는 엔코더의 기능이 아니다.
- **샘플링 주파수와 제어 대역폭의 관계**: 나이퀴스트 정리상 이론적 최소는 대역폭의 2배이지만, 실무에서는 위상 지연·이산화 오차를 고려해 **제어 대역폭의 10배 이상**의 샘플링 주파수를 확보하는 것이 표준적 설계 관행이다.
- **제어 주기(Control Loop Cycle Time) 설계 시 고려사항**: 모터 드라이버의 PWM 주파수, 센서의 샘플링 속도, 제어기의 연산 처리 시간, 시스템 응답성·안정성 요구사항 등 — "전원 공급기의 용량"이나 "로봇 외관 디자인"은 제어 주기 설계와 무관한 요소로, 오답 함정에 자주 쓰인다.
- **실시간성을 보장하는 방법으로 부적절한 것**: 인터럽트 우선순위 설정·멀티스레딩·RTOS 사용은 실시간성 보장에 유효하나, **"모든 태스크를 단일 스레드로 처리"는 오히려 우선순위 역전·응답 지연을 유발**해 실시간성 보장 방법으로 부적절하다.

# Summary

위치 제어는 속도 제어를 내부 루프로 포함하는 캐스케이드 구조이고, 엔코더가 그 피드백을 담당한다. 이 루프를 일정한 주기로 정확히 돌리려면 RTOS와 대역폭 대비 충분한 샘플링 주파수가 필요하며, 상위 경로계획에는 A* 같은 최적경로 탐색 알고리즘이 쓰인다.

# Notes

<aside>속도 제어 루프와 위치 제어 루프의 관계</aside>

- **캐스케이드(cascade) 구조**: 속도 루프가 위치 루프의 **내부(하위) 루프**
- 위치 제어기의 출력이 속도 지령이 되어 속도 루프에 입력되는 구조 (D11 "위치제어는 속도제어를 포함하는 상위 루프"와 동일 개념)

<aside>엔코더의 역할</aside>

- 모터/관절의 **위치 및 속도 피드백**을 제공하는 센서
- 전력 공급·모터 구동·통신 인터페이스는 엔코더의 기능이 아님

<aside>RTOS(실시간 운영체제)</aside>

- 핵심 특징: **결정적 응답시간(Deterministic Response Time)** — 태스크 처리 시간이 데드라인 안에서 일관되게 보장됨
- 높은 처리량이나 복잡한 그래픽 처리, 대용량 데이터 처리가 목적이 아님
- **실시간성을 보장하는 방법**: 인터럽트 우선순위 설정, 멀티스레딩, RTOS 사용 — 반대로 **"모든 태스크를 단일 스레드로 처리"는 우선순위 역전·응답 지연을 유발**해 부적절한 방법

<aside>샘플링 주파수와 제어 대역폭</aside>

- 나이퀴스트 정리상 이론적 최소는 대역폭의 2배
- 실무에서는 위상 지연·이산화 오차를 고려해 **제어 대역폭의 10배 이상**의 샘플링 주파수를 확보하는 것이 표준 설계 관행

<aside>제어 주기(Control Loop Cycle Time) 설계 시 고려사항</aside>

- 모터 드라이버의 PWM 주파수, 센서의 샘플링 속도, 제어기의 연산 처리 시간, 시스템 응답성·안정성 요구사항
- "전원 공급기의 용량", "로봇 외관 디자인"은 제어 주기 설계와 무관한 요소(오답 함정)

<aside>A* 경로계획 알고리즘</aside>

- 실제 경로 비용(g) + 목적지까지의 추정 비용(휴리스틱 h)을 합산(f=g+h)해 우선순위를 정하는 그래프 탐색
- 휴리스틱이 admissible(남은 거리를 과대평가하지 않음)하면 **최적 경로(최단경로)가 보장**됨 — 이것이 A*를 사용하는 주된 이유

---

<aside>핵심 정리</aside>

- 캐스케이드 루프: 속도루프가 위치루프의 내부 루프, 엔코더가 피드백 담당
- RTOS=결정적 응답시간, 샘플링 주파수는 대역폭의 10배 이상, A*는 admissible 휴리스틱으로 최적경로 보장

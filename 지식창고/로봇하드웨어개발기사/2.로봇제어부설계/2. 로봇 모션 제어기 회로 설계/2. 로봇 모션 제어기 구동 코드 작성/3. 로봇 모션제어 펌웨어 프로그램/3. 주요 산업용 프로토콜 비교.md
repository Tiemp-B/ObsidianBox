# Summary

Profibus는 폴링 기반 마스터-슬레이브, Modbus는 단순한 마스터-슬레이브 요청-응답, CANopen은 OD/SDO/PDO로 디바이스 기능을 기술하는 CAN 표준, EtherCAT은 응용계층에서 CANopen(CoE)을 그대로 활용하는 실시간 이더넷이다.

# Notes

<aside>Profibus</aside>

- 응용계층 종류에 따라 4가지: **FMS**(다양한 실시간 서비스, 대다수 생산시스템), **DP**(decentralized peripherals, 빠른 데이터 전송, 분산 필드기기 실시간 통신), **PA**(process automation, 전자기적 간섭 내성, 원자력발전소 등 특수환경), **PROFINET**(IRT=하드 실시간 1ms 이하 클럭동기 / RT=소프트·비실시간)
- Profibus-DP: **폴링(polling)** 방식(중앙 제어기가 요청프레임 전송→필드기기가 응답프레임 전송), OSI 1·2계층(PHY+FDL)만 사용, 전송매체 RS485, 속도 9.6Kbps~12Mbps
- 스테이션 구성: DPM1(폴링하는 마스터, PLC/산업용컴퓨터)·DPM2(모니터링/진단)·슬레이브
- 모노 마스터 구성: DPM1 하나만 사용, 폴링주기는 하드 리얼타임에서 통상 **10msec**

<aside>Modbus</aside>

- 1997년 Modicon(현재의 Schneider Electric) 개발, 시리얼 통신 프로토콜
- **마스터-슬레이브 구조**: 마스터가 요청을 보내고 응답을 기다림
- 1:1 통신 = **RS232**, 다수 장치 접속(1:N) = **RS485/422**
- 계층 구조: ADU(Application Data Unit: ASCII/RTU/TCP-IP) 안에 PDU(Protocol Data Unit: 함수 코드+데이터)가 포함

<aside>CANopen</aside>

- CAN 기반 시스템의 **벤더 종속성 문제**를 해결하기 위한 CiA 표준
- 11bit ID = **4bit function code + 7bit Node-ID** → 단일 네트워크에서 최대 **127개** 노드 접속
- 핵심 요소: **OD**(Object Dictionary, 디바이스 기능 서술) / **SDO**(Service Data Object, 8바이트 이상 대용량 데이터) / **PDO**(Process Data Object, 8바이트 실시간 교환)
- **노드 감시 프로토콜(Node Guarding)**: 일정 주기(node guard time)로 슬레이브 상태를 감시 — 에러 감지·신규 노드 등록·연결 해제 노드 정보 갱신에 사용

<aside>EtherCAT</aside>

- 2002년 독일 BECKHOFF사 개발, IEC/ISO 국제표준(IEC/PAS 62407, ISO15745-4)
- 뛰어난 Ethernet 호환성, 낮은 비용, 우수한 동기화 특성(분산 클럭 DC)
- **물리·데이터링크 계층에서 EtherCAT**을, **응용계층(AL)에서 CANopen**을 사용 — **CoE(CANopen over EtherCAT)**: EtherCAT이 CANopen의 OD/SDO/PDO 서비스 규격을 그대로 활용
- PDO는 매핑을 통해 프로세스 데이터로 고속 교환, SDO는 메일박스를 통해 대용량 데이터 전송

---

<aside>핵심 정리</aside>

- Profibus-DP=폴링, Modbus=단순 요청-응답, CANopen=OD/SDO/PDO+노드감시, EtherCAT=물리/DL은 자체+응용계층은 CANopen(CoE) 재사용
- 4개 프로토콜 모두 마스터가 통신을 주도하는 구조라는 공통점이 있음(Modbus/Profibus-DP는 명시적, CAN 계열은 노드 관리 차원에서)

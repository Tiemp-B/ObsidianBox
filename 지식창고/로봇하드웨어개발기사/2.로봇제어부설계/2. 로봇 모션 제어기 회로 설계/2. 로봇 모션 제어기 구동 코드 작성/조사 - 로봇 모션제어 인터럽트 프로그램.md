# 조사 — 로봇 모션제어 인터럽트 프로그램

## A. NCS 대조 결과

NCS 학습모듈 117/118의 **학습4 "로봇 모션 제어기 구동 코드 작성하기"**는 4-1 "로봇 모션 제어기 구동 코드 작성" 필요지식(footer p.78~86)이 있으나, 그 내용은 "모션 제어를 위한 산업용 네트워크"(필드버스·프로토콜)에 한정되어 인터럽트/ISR 작성 자체에 대한 필요지식은 없다. footer p.87 이후는 상용 소프트웨어 설치·라이브러리 코딩 등 수행내용(실기)이다. 이 세세항목은 문제은행 8문항(전체 4위 규모)을 웹조사·임베디드 시스템 도메인 지식으로 작성한다.

## B. 웹 검색 결과

1. **ISR 실행시간 최소화**: ISR 처리 시간은 인터럽트 주기의 10~20% 이하가 기본 원칙(예: 1ms 주기라면 100~200µs 이하). 초과 시 인터럽트 폭주, 저우선순위 인터럽트 지연, 메인 루프 실행 기회 감소 등의 문제 발생. **ISR 작성 시 가장 중요한 고려사항 = 실행 시간의 최소화**. — [인터럽트 핸들러, 위키백과](https://ko.wikipedia.org/wiki/%EC%9D%B8%ED%84%B0%EB%9F%BD%ED%8A%B8_%ED%95%B8%EB%93%A4%EB%9F%AC)
2. **네스티드 인터럽트(Nested Interrupt)**: 더 높은 우선순위의 인터럽트가 처리 중인 ISR을 다시 선점(재귀적 처리)하도록 허용하는 방식. 인터럽트가 겹겹이 쌓이면 각 ISR의 스택 프레임이 누적되어 **스택 오버플로우**를 유발할 수 있음 — 실제로 리눅스 커널에서도 중첩 IRQ 스택 오버플로우 방지를 위해 중첩 단계를 제한하는 패치가 논의됨. — [Prevent nested interrupts when the IRQ stack is near overflowing, LWN.net](https://lwn.net/Articles/380937/)
3. **인터럽트 지연시간(Interrupt Latency)의 구성**: 인터럽트 발생부터 ISR 첫 명령어 실행까지의 지연으로, 원인 지연시간·선택 지연시간·펀넬 지연시간(컨텍스트/RTOS/호출 오버헤드)으로 구성. **영향 요소**: 현재 실행 중인 명령어, 인터럽트 우선순위, ISR의 길이(길수록 더 높은 우선순위 인터럽트 처리 지연) — **메모리 용량은 지연시간에 직접 영향을 주는 요소가 아니다**. — [인터럽트, IT위키](https://itwiki.kr/w/%EC%9D%B8%ED%84%B0%EB%9F%BD%ED%8A%B8)

## C. 결론(도메인 지식으로 보완, 검색 불필요한 기초 사실)

- **인터럽트 우선순위 설정의 목적**: 여러 인터럽트가 동시에 발생했을 때 **중요한 인터럽트를 우선 처리**하기 위함(메모리 최적화·전력 감소·통신 속도 향상이 목적이 아님).
- **가장 높은 우선순위를 부여해야 할 대상**: **비상정지 신호(EMGN)** — 안전과 직결되는 인터럽트는 UART 통신·LCD 갱신·배터리 체크보다 항상 최우선으로 처리해야 함.
- **인터럽트의 장점이 아닌 것**: 실시간 응답 가능·CPU 효율성 향상(폴링 대비 불필요한 대기 제거)·이벤트 기반 처리는 인터럽트의 실제 장점이지만, **메모리 사용량 감소는 인터럽트 고유의 장점이 아니다**(오히려 ISR·스택으로 메모리를 추가로 사용).
- **ISR에서 피해야 할 작업**: 모터 제어값 갱신·엔코더 값 읽기·상태 플래그 설정은 짧고 결정적인 작업이라 ISR에 적합하지만, **긴 시간의 부동소수점 연산은 ISR 실행시간을 늘려 다른 인터럽트 처리를 지연시키므로 피해야 한다**.

## D. 페이지 구성 설계

1. 개요
2. ISR 작성 원칙과 인터럽트 우선순위 (실행시간 최소화, 비상정지 최우선, ISR에서 피할 작업)
3. 인터럽트의 특성과 지연시간 (장점/비장점, 네스티드 인터럽트와 스택 오버플로우, 지연시간 구성요소)

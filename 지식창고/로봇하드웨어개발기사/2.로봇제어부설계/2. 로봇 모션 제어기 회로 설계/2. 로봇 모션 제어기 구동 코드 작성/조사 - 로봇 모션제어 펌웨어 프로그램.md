# 조사 — 로봇 모션제어 펌웨어 프로그램

## A. NCS 대조 결과

NCS 학습모듈 117/118의 **학습4 "로봇 모션 제어기 구동 코드 작성하기" 4-1 필요지식**(footer p.78~86, "모션 제어를 위한 산업용 네트워크")이 이 세세항목에 대응한다. 모션 제어기 펌웨어가 상위/하위 장치와 통신하기 위해 구현해야 할 산업용 네트워크 프로토콜 스택 지식이며, 문제은행 0문항이라 NCS 원문 위주로 작성한다.

NCS 필요지식 핵심 내용:

1. **산업용 네트워크의 발전**: 1970년대 4-20mA 아날로그 일대일(point-to-point) 통신 → 1980년대 초 분산제어시스템(DCS) 도입, 그러나 업체별 독자 네트워크 모델로 인한 종속·고가의 프로토콜 변환장치 문제 → PNP 표준화 요구 → MAP/MiniMAP(1980년대 초, GM/IBM) → 실시간성 부족으로 1980년대 후반 **필드버스(fieldbus)** 개발 → 1999년 Profibus·Fieldbus Foundation·WorldFIP 등을 포함한 **IEC 61158**이 국제표준으로 제정.
2. **필드버스의 계층 구조**: 디바이스 계층(센서·액추에이터 간, EtherCAT·Mechatronlink·SERCOS 등 필드버스)/셀 계층(PLC·로봇 간)/플랜트 계층(산업용컴퓨터·DB 간, 주로 스위치드 이더넷) — 필드버스와 이더넷은 게이트웨이로 연결.
3. **필드버스의 매체접속제어(MAC) 방식 3종**:
   - **라운드로빈(round robin)**: 각 스테이션에 순차적으로 전송 기회 부여. 중앙집중형(WorldFIP, 스케줄링) / 분산형(Profibus, 토큰패싱)
   - **경쟁(contention)**: 스테이션들이 전송권을 경쟁 획득(DeviceNet·LonWorks, CSMA 변형)
   - **예약(reservation)**: 전송매체를 슬롯으로 나눠 예약 후 사용(Interbus 등)
4. **Profibus**: 응용계층 종류에 따라 FMS(다양한 실시간 서비스)/DP(decentralized peripherals, 빠른 데이터 전송, 분산 필드기기 간 실시간 통신)/PA(process automation, 전자기적 간섭 내성, 원자력발전소 등 특수환경)/PROFINET(IRT=하드 실시간 1ms 이하 클럭동기, RT=소프트/비실시간)으로 구분. Profibus-DP는 폴링(polling) 방식(요청프레임→응답프레임), OSI 1·2계층(PHY+FDL)만 사용, RS485, 9.6Kbps~12Mbps, 모노/멀티 마스터 구성 지원(모노는 DPM1 하나, 폴링주기가 하드리얼타임에서 통상 10msec).
5. **Modbus**: 1997년 Modicon(현재의 Schneider Electric)이 개발한 시리얼 통신 프로토콜, **마스터-슬레이브 구조**(마스터가 요청→슬레이브 응답 대기). 1:1은 RS232, 다수 장치 접속은 RS485/422(1:N). 계층: ADU(ASCII/RTU/TCP-IP) 안에 PDU(함수 코드+데이터)가 있는 구조.
6. **CANopen**: CAN 기반 응용 시스템의 벤더 종속성 문제를 해결하기 위한 CiA 표준. 11bit ID = 4bit function code + 7bit Node-ID(최대 127 노드). 핵심 요소는 OD(object dictionary)·SDO(대용량 데이터)·PDO(8바이트 실시간 교환). **노드 감시 프로토콜(node guarding)**로 슬레이브 노드의 에러·연결 상태를 주기적으로 감시.
7. **EtherCAT**: 2002년 독일 BECKHOFF사 개발, IEC/ISO 국제표준 프로토콜. 뛰어난 Ethernet 호환성·낮은 비용·우수한 동기화 특성. 물리/데이터링크 계층에서 EtherCAT을, 응용계층(AL)에서 CANopen(CoE, CANopen over EtherCAT)을 사용 — OD/PDO/SDO를 그대로 활용.

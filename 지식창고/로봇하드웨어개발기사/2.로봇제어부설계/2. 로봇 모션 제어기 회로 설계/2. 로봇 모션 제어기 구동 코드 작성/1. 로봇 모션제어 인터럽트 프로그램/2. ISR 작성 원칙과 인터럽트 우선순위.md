# Summary

ISR은 실행시간을 최소화하도록 작성해야 하며, 특히 긴 부동소수점 연산처럼 시간이 오래 걸리는 작업은 피해야 한다. 여러 인터럽트가 동시에 발생할 수 있는 로봇 제어에서는 비상정지 신호에 항상 최우선순위를 부여한다.

# Notes

<aside>ISR 실행시간 최소화</aside>

- ISR 처리 시간은 통상 **인터럽트 주기의 10~20% 이하**가 원칙(예: 1ms 주기 → 100~200µs 이하)
- 초과 시: 인터럽트 폭주, 저우선순위 인터럽트 지연, 메인 루프 실행 기회 감소
- **모터 제어 펌웨어 ISR 작성 시 가장 중요한 고려사항 = 실행 시간의 최소화**

<aside>ISR에서 피해야 할 작업</aside>

| 작업 | ISR에 적합한가 |
|---|---|
| 모터 제어값 갱신 | 적합(짧고 결정적) |
| 엔코더 값 읽기 | 적합(짧고 결정적) |
| 상태 플래그 설정 | 적합(짧고 결정적) |
| **긴 시간의 부동소수점 연산** | **피해야 함**(정수 연산보다 오래 걸려 ISR 실행시간 증가 → 다른 인터럽트 지연) |

<aside>인터럽트 우선순위</aside>

- **설정 목적**: 여러 인터럽트가 동시에 발생했을 때 **중요한 인터럽트를 우선 처리**하기 위함(메모리 최적화·전력 감소·통신 속도 향상이 목적이 아님)
- **가장 높은 우선순위를 부여해야 할 대상**: **비상정지(EMGN) 신호** — 안전과 직결되므로 UART 통신·타이머·ADC 변환완료·LCD 갱신·배터리 체크보다 항상 최우선

---

<aside>핵심 정리</aside>

- ISR 처리시간은 주기의 10~20% 이하, 부동소수점 같은 오래 걸리는 연산은 ISR 밖으로
- 우선순위 설정 목적 = 중요 인터럽트(비상정지 최상위) 우선 처리

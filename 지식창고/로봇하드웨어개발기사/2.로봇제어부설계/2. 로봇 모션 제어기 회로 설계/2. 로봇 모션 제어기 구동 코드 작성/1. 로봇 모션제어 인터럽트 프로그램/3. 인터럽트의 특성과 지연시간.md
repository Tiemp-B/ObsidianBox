# Summary

인터럽트는 실시간 응답성과 CPU 효율을 높이지만 메모리를 절약해주지는 않는다. 더 높은 우선순위 인터럽트가 현재 ISR을 다시 선점하는 네스티드 인터럽트는 스택 오버플로우를 유발할 수 있고, 인터럽트 지연시간은 현재 명령어·우선순위·ISR 길이에 좌우된다.

# Notes

<aside>인터럽트의 장점 — 아닌 것 구별</aside>

| 장점 | 실제 인터럽트의 장점인가 |
|---|---|
| 실시간 응답 가능 | O |
| CPU 효율성 향상(폴링 대비 불필요한 대기 제거) | O |
| 이벤트 기반 처리 | O |
| **메모리 사용량 감소** | **X — 인터럽트 고유의 장점이 아님**(ISR·스택으로 오히려 메모리 추가 사용) |

<aside>네스티드 인터럽트(Nested Interrupt)</aside>

- 더 높은 우선순위의 인터럽트가 현재 처리 중인 ISR을 **다시 선점(재귀적 처리)**하도록 허용하는 방식
- 인터럽트가 겹겹이 쌓이면 각 ISR의 스택 프레임이 누적 → **스택 오버플로우**를 유발할 수 있음(인터럽트 지연시간 감소·메모리 사용량 감소·전력 소비 감소는 네스티드 인터럽트의 문제점이 아님)

<aside>인터럽트 지연시간(Interrupt Latency)</aside>

- 정의: 인터럽트 발생부터 ISR 첫 명령어 실행까지의 지연
- 구성: 원인 지연시간, 선택 지연시간, 펀넬 지연시간(컨텍스트/RTOS/호출 오버헤드)
- **영향을 주는 요소**: 현재 실행 중인 명령어, 인터럽트 우선순위, ISR의 길이(길수록 더 높은 우선순위 인터럽트 처리가 지연됨)
- **영향을 주지 않는 요소**: 메모리 용량

---

<aside>핵심 정리</aside>

- 인터럽트 장점 = 실시간응답·CPU효율·이벤트기반, 메모리 절약은 아님
- 네스티드 인터럽트의 위험 = 스택 오버플로우
- 지연시간 영향요소 = 현재명령어·우선순위·ISR길이 (메모리 용량은 무관)

# Summary

SPI는 마스터가 클록·칩선택을 구동하는 전이중 통신으로 CPOL/CPHA 조합에 따라 4가지 모드가 있으며, 슬레이브끼리는 직접 데이터를 공유하지 않는다. I2C는 슬레이브가 클록을 붙잡아(클록 스트레칭) 처리 시간을 확보할 수 있다.

# Notes

<aside>SPI(Serial Peripheral Interface)</aside>

- **마스터-슬레이브 구조**: 마스터가 클록(SCK)·칩선택(SS/CS)을 구동
- 4개 신호선: **MOSI**(Master Out Slave In), **MISO**(Master In Slave Out), **SCK**, **SS**
- 데이터 선이 분리되어 있어 **전이중(full-duplex) 통신** 가능
- 슬레이브를 여러 개 연결 가능하나 슬레이브 수만큼 SS 선 필요
- **슬레이브는 마스터를 통해서만 통신 — 슬레이브 간 데이터를 직접 공유하지 않는다**(SPI 특징을 묻는 문제에서 "슬레이브 간 데이터 공유 가능"은 틀린 서술)

<aside>SPI의 CPOL/CPHA 모드</aside>

- **CPOL(Clock Polarity)**: 클록의 유휴 상태(0/1) — 2가지
- **CPHA(Clock Phase)**: 데이터 샘플링 시점(첫/두번째 엣지) — 2가지
- 조합: **2×2 = 4가지 모드(Mode 0~3)**

<aside>I2C(Inter-Integrated Circuit)의 클록 스트레칭</aside>

- 슬레이브가 데이터 전송 도중 **SCL 라인을 로우로 유지**해 마스터를 대기시키는 메커니즘
- 목적: **슬레이브가 데이터 처리(수신 데이터 저장, 다음 바이트 준비 등)에 필요한 시간을 확보**하기 위함
- 통신 속도 향상·전력 소비 감소·노이즈 감소가 목적이 아님

---

<aside>핵심 정리</aside>

- SPI = 전이중·4선·마스터경유(슬레이브간 직접공유 불가)·CPOL×CPHA=4모드
- I2C 클록 스트레칭 = 슬레이브의 "시간 벌기" 메커니즘

# Summary

CAN은 멀티마스터 구조에 SYNC 메시지로 분산 장치를 동기화하고, EtherCAT은 분산 클럭(DC)으로 서브나노초 수준의 동기화를 제공한다. 다축 협조 제어처럼 여러 관절이 동시에 움직여야 할 때 이런 동기화가 필요하며, 엔코더는 A/B상·Z상·4체배로 위치·속도를 피드백한다.

# Notes

<aside>CAN 통신</aside>

- **멀티마스터 구조**(과목1에서 확인: 임의 노드가 버스 점유 시도, 비트 단위 중재로 충돌 해결) — 마스터-슬레이브·점대점 전용·아날로그 신호 전송은 CAN의 특징이 아님
- **SYNC 메시지(CANopen)**: SYNC 생산자가 주기적으로 브로드캐스트하면 여러 SYNC 소비 노드가 이를 기준으로 입력 샘플링·출력 구동을 동시 수행 → 목적은 **분산 장치 간 동기 제어**

<aside>EtherCAT의 분산 클럭(Distributed Clock, DC)</aside>

- EtherCAT 슬레이브 컨트롤러(ESC)에 내장된 기능(NCS 원문 표에 64bit 폭으로 명시)
- 네트워크 전체 노드 간 **서브 나노초(sub-nanosecond) 수준의 동기화**를 제공 — 통신 대역폭 증가·패킷 손실 방지·전력 소비 감소가 목적이 아님

<aside>실시간 통신의 지터(Jitter) 최소화</aside>

| 방법 | 지터 최소화에 유효한가 |
|---|---|
| 우선순위 기반 스케줄링 | 유효 |
| 인터럽트 처리 시간 최소화 | 유효 |
| 결정론적 통신 프로토콜(EtherCAT 등) | 유효 |
| **버퍼 크기 최대화** | **부적절** — 지연시간(latency)만 늘어나 실시간 결정성을 해침 |

<aside>엔코더 신호 처리</aside>

- 표준 기법: **4체배 방식**, **A/B상 위상차 검출**, **Z상 기준점 검출**
- **PWM 신호 변조는 엔코더 신호(입력) 처리 방식이 아니다** — PWM은 모터 구동(출력) 방식

<aside>동기화가 필요한 경우</aside>

- 단일 축 제어: 다른 축과 맞출 필요 없음 → 동기화 불필요
- **다축 협조 제어**: 여러 관절이 하나의 궤적을 이루며 동시에 움직여야 함 → 축 간 시간 동기 필수

---

<aside>핵심 정리</aside>

- CAN=멀티마스터+SYNC메시지(동기제어), EtherCAT=분산클럭(서브나노초 동기)
- 지터 최소화는 스케줄링·인터럽트최소화·결정론적프로토콜로, 버퍼 확대는 역효과
- 엔코더 신호처리 3종(4체배/A·B상/Z상), PWM은 해당 없음

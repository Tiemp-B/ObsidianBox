# Summary

모션 제어기 회로는 마이크로컨트롤러의 버스 구조(어드레스·데이터·제어) 위에서 CPU·메모리·보조모듈이 동작하는 것을 기반으로 하며, 프로그램/데이터 메모리를 공유하는 폰 노이만 구조와 분리하는 하바드 구조 중 선택해 설계한다. NCS 필요지식(학습모듈 117/118 3-1, footer p.56~58)이 이 세세항목의 핵심 출처이며, 문제은행 대응 문항은 없다.

<aside>마이크로컨트롤러의 3가지 시스템 버스</aside>

| 버스 | 방향 | 역할 |
|---|---|---|
| **어드레스 버스** | 단방향 | 메모리·I/O 장치의 번지 지정. 신호선 수 = 최대 메모리 용량/I/O 수 결정 |
| **데이터 버스** | 양방향 | 데이터 전송. 신호선 수 = 워드 길이, 성능을 좌우 |
| **제어 버스** | 단방향 | 작업 종류·상태 통지, 동작 요구 신호 |

<aside>마이크로컨트롤러 내부 구조</aside>

- **메모리**: ROM(플래시/EEPROM) + RAM
- **CPU**: ALU(산술논리연산장치) + 레지스터 + 시프터
- **보조모듈**: 통신(SPI/USART/I2C), AD/DA 변환, 타이머
- 위 3부분이 버스로 연결되어 명령·데이터를 주고받음

<aside>폰 노이만 구조 vs 하바드 구조</aside>

| 구분 | 폰 노이만 | 하바드 |
|---|---|---|
| 메모리 | 프로그램·데이터 **공유**(단일 버스) | 프로그램·데이터 **분리**(각각 별도 버스) |
| 처리 | Fetch→Decode→Execute→Store 순차 | 파이프라이닝 용이 |
| 속도 | 상대적으로 느림 | **빠름** |
| 공간·복잡도 | 단순 | 공간을 더 차지, 회로 복잡 |

<aside>전기적 절연과 노이즈 강건성(실무 설계 원칙)</aside>

- 모션 제어 신호는 **포토커플러**로 전기적 절연
- 펄스 출력은 드라이버 측 입력 방식과 무관하게 동작하도록 **라인 드라이버** 사용
- → 외부 장비 구동 시 발생하는 전기적 노이즈에 강건하게 설계

<aside>핵심 정리</aside>

- 어드레스(단방향, 주소지정)·데이터(양방향, 전송)·제어(단방향, 상태/명령) 버스 3종
- 하바드 구조가 폰노이만보다 빠르지만 공간·복잡도에서 불리 — 모션 제어처럼 실시간성이 중요한 응용은 하바드 구조 기반 MCU/DSP를 선호하는 경향

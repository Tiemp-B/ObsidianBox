# Summary

MCU가 여러 센서·통신·모터 드라이버를 동시에 다룰 때는 다축 협조 제어와 같은 시간 동기, 인터럽트 우선순위 조율, RTOS 뮤텍스를 통한 자원 상호배제, DMA를 이용한 병렬 처리가 함께 작동한다. 문제은행 0문항이라 과목2에서 검증한 개념을 MCU-주변기기 관점으로 재구성했다.

<aside>다축 동기화(과목2 D16 재사용)</aside>

- 여러 관절이 하나의 궤적을 이루며 동시에 움직여야 하는 **다축 협조 제어**에서는 축 간 시간 동기가 필수
- MCU가 여러 모터 드라이버·엔코더를 동시에 제어할 때도 동일한 원리 적용

<aside>인터럽트 기반 동기화(과목2 D17 재사용)</aside>

- 여러 주변기기(센서·통신·타이머)가 각각 다른 시점에 이벤트를 발생시킬 때, **인터럽트 우선순위**로 어느 주변기기를 먼저 처리할지 조율

<aside>RTOS 동기화 객체(D29와 연결)</aside>

- 여러 태스크가 동일한 주변기기(예: 하나의 SPI 버스)에 동시 접근하려 할 때 **뮤텍스로 상호 배제**해 데이터 충돌 방지

<aside>DMA와 주변기기 동기화(과목2 D24 재사용)</aside>

- DMA 컨트롤러가 CPU 개입 없이 주변기기-메모리 간 데이터를 옮기는 동안, CPU는 다른 주변기기를 동기적으로 처리 가능 → 여러 주변기기를 병렬적으로 다루는 데 유리

---

<aside>핵심 정리</aside>

- 주변기기 동기화 = 시간 동기(다축협조)+이벤트 조율(인터럽트우선순위)+자원 상호배제(뮤텍스)+병렬처리(DMA)의 조합

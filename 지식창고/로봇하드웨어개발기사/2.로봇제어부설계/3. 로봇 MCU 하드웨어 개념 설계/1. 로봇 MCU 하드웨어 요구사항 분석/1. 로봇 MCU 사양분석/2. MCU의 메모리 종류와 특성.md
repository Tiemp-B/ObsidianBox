# Summary

EEPROM과 플래시는 둘 다 비휘발성이지만 쓰기 방식이 다르고, 캐시는 CPU-메모리 속도차를 메우는 장치이며, 스택 오버플로우는 스택 사용량 자체를 줄이는 방법으로 방지한다.

# Notes

<aside>EEPROM</aside>

- **바이트 단위 읽기/쓰기 가능**, **비휘발성**(전원 차단 시에도 데이터 보존)
- 쓰기/지우기 과정에 시간이 걸려 RAM보다 **쓰기 속도가 느림**, 쓰기 횟수에 한계(무제한 쓰기 불가)

<aside>플래시 메모리</aside>

- **비휘발성** 메모리, 읽기는 빠르지만 **쓰기는 느림**
- 쓰기가 느린 이유: 쓰기 전 반드시 **소거(erase) 과정**을 거쳐야 하기 때문(전압이 낮아서·물리적 거리·용량이 작아서가 아님)
- 쓰기 횟수에 한계(P/E cycle) 존재 → "무제한 쓰기 가능"은 틀린 설명

<aside>캐시 메모리(Cache Memory)</aside>

- 목적: CPU 연산 속도와 메인 메모리 접근 속도의 차이를 줄여 **메모리 접근 속도를 향상**
- 자주 쓰는 데이터를 캐시에 두어 메인 메모리 접근 횟수를 줄임(전력 감소·보안 강화·용량 확장이 목적이 아님)

<aside>스택(Stack) 오버플로우 방지</aside>

| 방법 | 스택 오버플로우 방지책인가 |
|---|---|
| 스택 크기 증가 | O |
| 재귀 함수 사용 최소화 | O |
| 지역 변수 사용 최소화 | O |
| **힙 메모리 사용 증가** | **X** — 힙은 스택과 별개 메모리 영역, 스택 사용량 자체를 줄이는 방법이 아님 |

---

<aside>핵심 정리</aside>

- EEPROM·플래시 모두 "비휘발성 + 느린 쓰기"가 공통 특징, 플래시가 느린 이유는 소거 과정
- 캐시 = 속도 향상 전용, 스택 오버플로우 방지는 스택 자체를 줄이는 방법(힙 증가는 해당 없음)

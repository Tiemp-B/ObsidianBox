# 조사 — 로봇 MCU와 주변기기간 신호처리

## A. NCS 대조 결과

NCS 필요지식(footer p.6~7) "통신 인터페이스의 활용"에서 UART·I2C·SPI·CAN·Ethernet의 정의를 간단히 다루나("UART는 비동기 직렬 통신", "I2C는 SDA/SCL 라인 사용", "SPI는 MOSI/MISO/SCK/SS 라인 사용, 고속 통신"), DMA·CRC·오류검출 등 문제은행이 실제로 묻는 세부 사항은 다루지 않는다. 문제은행 7문항을 웹조사·임베디드 통신 도메인 지식으로 보완한다.

## B. 웹 검색 결과

1. **UART의 특징**: 송신부와 수신부가 클록 신호를 공유하지 않는 **비동기식(asynchronous) 통신** — Baud Rate만 맞추면 되고 별도 클록 라인이 불필요(동기식 버전은 USART). — [UART, 위키백과](https://ko.wikipedia.org/wiki/UART)
2. **CRC(Cyclic Redundancy Check)의 용도**: 전송 데이터에 여유 부호를 붙여 수신측에서 오류 여부를 검사하는 기법으로, 단일 비트 오류부터 버스트(연집) 오류까지 검출 능력이 우수한 **데이터 무결성 검증** 기법(데이터 압축·암호화·정렬이 목적이 아님). Modbus·CAN 등 다수 프로토콜에서 사용. — [CRC, ktword](http://www.ktword.co.kr/test/view/view.php?no=603)

## C. 결론(도메인 지식으로 보완, 검색 불필요한 기초 사실)

- **SPI 통신의 특징**: 마스터-슬레이브 구조의 **동기식(synchronous) 통신**(클록 SCK 공유). MOSI/MISO/SCK/SS **4선식**이며(2선식 아님), 원칙적으로 **싱글 마스터**(멀티마스터 지원 아님), 클록을 함께 배선해야 하므로 **단거리 통신에 적합**(장거리 부적합) — 과목2 D16에서 이미 확인된 내용과 일치.
- **I2C 통신의 특징**: SDA(데이터)·SCL(클록) **2선식** 통신, 양방향(단방향 아님), 표준모드 기준 100kbps~400kbps로 SPI보다 저속(고속 통신 전용 아님).
- **DMA(Direct Memory Access)의 주요 기능·목적**: **CPU 개입 없이 메모리 간(또는 메모리-주변장치 간) 데이터를 직접 전송**하는 기능으로, 주된 목적은 **CPU 부하 감소**(CPU를 데이터 전송 작업에서 해방시켜 다른 연산에 집중시킴) — 메모리 용량 확장·통신 속도 증가 자체가 목적이 아님.
- **UART 수신 데이터 오류 감지 방법**: 프레임에 포함된 **패리티 비트(Parity Bit) 검사**로 1비트 오류를 감지하는 것이 UART의 표준적인 오류 검출 방법(클럭 주파수 확인·전송속도 변경·송신버퍼 초기화는 오류 감지 방법이 아님).

# Summary

서버는 데이터 정합성을 보장하기 위해 **[[트랜잭션(Transaction)|트랜잭션]]** 단위로 데이터베이스 작업을 처리하며, 트랜잭션은 **ACID(원자성·일관성·고립성·지속성)** 속성을 만족해야 한다. 이 중 여러 트랜잭션이 동시에 수행될 때 서로 영향을 주지 않도록 보장하는 속성이 **고립성(Isolation)**이다. 또한 서버는 매 요청마다 DB 연결을 새로 맺는 대신 **[[커넥션 풀(Connection Pool)|커넥션 풀]]**로 연결을 재사용해 성능을 확보한다.

# Notes

<aside>트랜잭션(Transaction) 개념</aside>

**[[트랜잭션(Transaction)|트랜잭션]]**은 데이터베이스의 상태를 변화시키는 하나의 논리적 작업 단위로, 그 안의 모든 연산이 전부 성공하거나 전부 실패해야 한다(all-or-nothing).

<aside>ACID 속성</aside>

| 속성 | 의미 |
|---|---|
| 원자성(Atomicity) | 트랜잭션 내 모든 연산이 전부 반영되거나 전부 반영되지 않음 |
| 일관성(Consistency) | 트랜잭션 전후로 데이터베이스가 제약조건을 만족하는 일관된 상태 유지 |
| 고립성(Isolation) | 동시에 수행되는 트랜잭션들이 서로의 중간 상태에 영향받지 않고 독립적으로 수행됨 |
| 지속성(Durability) | 커밋된 트랜잭션의 결과는 이후 시스템 장애가 발생해도 영구 보존됨 |

"여러 트랜잭션이 동시에 수행될 때 각각이 서로 영향을 받지 않고 독립적으로 수행되는 특성"은 이 중 **고립성(Isolation)**에 해당한다.

<aside>트랜잭션 격리 수준(Isolation Level)</aside>

고립성은 정도의 문제이며, 아래로 갈수록 정합성은 강해지지만 동시 처리 성능(동시성)은 낮아지는 트레이드오프가 있다.

| 격리 수준 | 특징 |
|---|---|
| Read Uncommitted | 가장 낮은 격리, 커밋 안 된 데이터도 읽힘(Dirty Read 허용) |
| Read Committed | 커밋된 데이터만 읽지만, 같은 쿼리를 반복하면 결과가 달라질 수 있음 |
| Repeatable Read | 트랜잭션 내에서 같은 행을 반복 조회해도 값이 동일함을 보장 |
| Serializable | 가장 높은 격리, 트랜잭션들을 순차 실행한 것과 동일한 결과 보장(성능 저하 큼) |

<aside>동시성 이상 현상</aside>

| 현상 | 설명 |
|---|---|
| Dirty Read | 다른 트랜잭션이 아직 커밋하지 않은 데이터를 읽어버림 |
| Non-repeatable Read | 같은 조건으로 두 번 조회했는데 그 사이 다른 트랜잭션의 커밋으로 결과가 달라짐 |
| Phantom Read | 범위 조회 시 그 사이 다른 트랜잭션이 추가한 행이 새로 나타남 |

격리 수준을 높일수록 이런 이상 현상들을 순서대로 방지할 수 있다.

<aside>데이터베이스 연결 풀(Connection Pool)</aside>

매 요청마다 DB 연결을 새로 생성하고 종료하면 연결 수립 자체의 비용(TCP 연결, 인증 등)이 반복적으로 발생한다. **[[커넥션 풀(Connection Pool)|커넥션 풀]]**은 미리 일정 수의 연결을 만들어 두고 요청이 올 때마다 빌려 쓰고 반환하는 방식으로, 다음을 이유로 사용한다.

- 연결 생성·해제 비용 절감
- 서버·DB 양쪽의 자원 사용 효율화
- 동시 연결 수를 제한해 DB 과부하 방지

<aside>커넥션 풀 크기 설정과 커넥션 누수</aside>

풀 크기를 너무 작게 잡으면 요청이 몰릴 때 연결을 기다리는 병목이 생기고, 너무 크게 잡으면 DB 측 자원을 불필요하게 소모한다. 사용 후 연결을 반환하지 않아 풀이 점점 고갈되는 **커넥션 누수(Connection Leak)**는 실무에서 흔히 발생하는 버그 유형이므로, 연결은 반드시 사용 후 반환하는 처리(예외 발생 시에도 반환 보장)가 필요하다.

<aside>예시 — 다수 로봇 상태 기록에서의 트랜잭션과 커넥션 풀</aside>

**예시**: 로봇의 위치와 배터리 잔량을 동시에 갱신해야 할 때, 이 두 값을 하나의 트랜잭션으로 묶지 않으면 위치만 갱신되고 배터리 값 갱신이 실패하는 식의 불일치(원자성 위반)가 생길 수 있다. 각 요청은 커넥션 풀에서 연결을 짧게 빌려와 트랜잭션을 처리한 뒤 즉시 반환해, 수십 대 로봇의 동시 상태 갱신 요청에도 DB 연결이 고갈되지 않도록 한다.

---

<aside>핵심 정리</aside>

- 트랜잭션은 ACID(원자성·일관성·고립성·지속성) 속성을 만족해야 하며, "동시 수행되는 트랜잭션이 서로 영향받지 않는 것"은 **고립성(Isolation)**
- 격리 수준이 높을수록 Dirty/Non-repeatable/Phantom Read를 막지만 동시성(성능)은 낮아지는 트레이드오프가 있음
- 커넥션 풀은 **연결 재사용으로 생성 비용을 줄이고 DB 과부하를 방지**하는 목적으로 사용하며, 커넥션 누수에 주의해야 함

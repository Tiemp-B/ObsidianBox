# Summary

**[[HMI(Human-Machine Interface)|HMI]]** (Human-Machine Interface)는 [[SCADA]] 구조의 최상위 계층으로, 수집된 데이터를 운영자가 한눈에 상태를 파악할 수 있는 그래픽 형태(게이지, 트렌드 그래프, 상태 인디케이터 등)로 변환해 보여준다. **[[알람(Alarm)|알람]]**은 이 HMI 위에서 임계값 이탈이나 이상 상태를 운영자에게 신속히 통보하는 기능으로, 그 목적은 **문제를 자동으로 해결하는 것이 아니라 운영자가 빠르게 인지하고 대응하도록 유도하는 것**이다.

# Notes

<aside>HMI의 역할</aside>

HMI는 [[3. SCADA 구조와 산업용 모니터링 시스템]]에서 설명한 SCADA 계층 구조의 최상단에 위치하며, 아래 두 방향의 상호작용을 담당한다.

- **표시(Display)**: 수집된 로봇/설비 상태를 시각적으로 표현
- **조작(Operation)**: 운영자가 시작/정지, 모드 전환 등 상위 명령을 입력하는 창구 ([[3. SCADA 구조와 산업용 모니터링 시스템]]의 "원격 명령" 기능과 연결)

<aside>주요 시각화 요소</aside>

| 요소 | 설명 | 적합한 용도 |
|---|---|---|
| 게이지/미터(Gauge) | 하나의 수치를 계기판 형태로 표시 | 배터리 잔량, 모터 온도처럼 "현재 값이 정상 범위 내인지"가 중요한 값 |
| 트렌드 그래프(Trend Graph) | 시간에 따른 값 변화를 선 그래프로 표시 | 관절 각도, 전류값처럼 시간 흐름에 따른 추이 파악이 필요한 값 |
| 상태 인디케이터 | 색상(녹색/노랑/빨강)으로 이산적인 상태를 표시 | 가동/정지/에러 등 몇 가지 상태로 나뉘는 값 |
| 프로세스 개요도(Mimic Diagram) | 설비 배치를 도식화하고 그 위에 실시간 값을 겹쳐 표시 | 여러 로봇 셀의 배치와 상태를 공간적으로 함께 파악할 필요가 있을 때 |

<aside>시각화 설계 원칙</aside>

- **상태-색상 규약 일관성**: 정상은 녹색, 경고는 노랑, 위험/정지는 빨강처럼 화면 전체에서 동일한 색상 의미를 유지해야 운영자의 순간적인 오판을 줄일 수 있다
- **정보 우선순위화**: 모든 수치를 동일한 크기로 나열하지 않고, 안전/가동 관련 핵심 지표를 시각적으로 두드러지게 배치한다
- **갱신 주기와 데이터 특성의 일치**: 빠르게 변하는 값(전류, 속도)은 트렌드 그래프로, 느리게 변하거나 이산적인 값(모드, 가동상태)은 인디케이터로 표현하는 것이 자연스럽다

<aside>데이터 시각화 방법으로 부적합한 사례</aside>

로봇 모니터링 화면에서 **가공되지 않은 원시 로그(raw text log)를 그대로 나열해 운영자가 실시간 상태를 파악하게 하는 방식은 적합한 시각화로 보기 어렵다.** 시각화의 목적은 다량의 수치 데이터를 사람이 즉각적으로 해석 가능한 그래픽 형태(게이지, 트렌드 그래프, 색상 인디케이터)로 요약해서 보여주는 것이며, 텍스트 로그 자체는 [[5. 데이터 로깅과 이상치 탐지]]에서 다루는 "기록·추후 분석"의 영역에 가깝다.

<aside>알람의 개념과 목적</aside>

**[[알람(Alarm)|알람]]**은 사전에 정의된 임계값을 데이터가 벗어나거나 이상 상태가 감지되었을 때 운영자에게 통보하는 기능이다. 핵심은 **"신속한 인지와 대응 유도"**이지, 알람 자체가 문제를 진단하거나 자동으로 해결하는 기능이 아니다 — 실제 대응 조치(정지, 재시작 등)는 여전히 운영자의 판단이나 별도의 제어 로직이 수행한다.

<aside>알람 우선순위/등급</aside>

| 등급 | 예시 | 대응 시급성 |
|---|---|---|
| Critical | [[E-stop(비상정지)\|E-stop]] 작동, 안전 회로 차단 | 즉시 대응 필요 |
| Warning | 배터리 잔량 저하, 온도 상승 추세 | 단기간 내 확인 필요 |
| Info | 정기 점검 시점 도래, 소프트웨어 업데이트 알림 | 즉시 대응 불필요 |

<aside>알람 폭주(Alarm Flooding)와 대응</aside>

하나의 근본 원인(예: 특정 로봇 셀의 전원 이상)이 여러 연쇄적인 알람(통신 두절, 배터리 경고, 위치 갱신 중단 등)을 동시에 발생시켜 운영자가 정작 중요한 원인을 놓치는 현상을 **알람 폭주([[알람 폭주(Alarm Flooding)|Alarm Flooding]])**라 한다. 실무에서는 아래와 같은 방식으로 완화한다.

- **알람 그룹화**: 연관된 알람들을 하나의 카드/그룹으로 묶어 표시
- **우선순위 필터링**: Critical 등급을 화면 상단에 고정하고, Info성 알람은 별도 로그로 분리
- **근본 원인 알람(Root Cause Alarm)만 강조**: 파생된 알람들은 축소 표시하고, 최초 원인이 된 알람만 부각

<aside>예시 — 로봇 셀 HMI 화면 구성</aside>

**예시 — 용접 로봇 셀 관제 화면**: 배터리 잔량은 게이지로, 관절 전류값은 최근 5분간의 트렌드 그래프로, 가동/정지/에러 상태는 색상 인디케이터로, 비상정지 발생 시에는 화면 상단에 Critical 등급 알람 배너가 고정 표시되는 구성이 전형적이다. 이때 통신 두절로 파생된 여러 알람은 "전원 이상"이라는 근본 원인 알람 하나로 묶여 표시된다.

---

<aside>핵심 정리</aside>

- HMI는 SCADA의 최상위 계층으로, 데이터를 게이지·트렌드 그래프·상태 인디케이터 등 그래픽 요소로 변환해 보여주고 운영자의 명령 입력 창구 역할도 한다
- 원시 로그를 그대로 나열하는 것은 시각화로서 부적합 — 로그 기록/분석은 별도 영역([[5. 데이터 로깅과 이상치 탐지]])
- 알람의 목적은 **신속한 인지·대응 유도**이지 자동 문제 해결이 아니며, Critical/Warning/Info 등 등급화가 필요
- 알람 폭주는 근본 원인 알람 강조, 그룹화, 우선순위 필터링으로 완화

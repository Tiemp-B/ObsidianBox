# Summary

**데이터 로깅(Data Logging)**은 로봇의 상태 데이터를 시계열로 기록해 두어 **사후적으로** 원인 추적·감사·성능 분석의 근거로 삼는 기능이다. 실시간 폐루프 제어에 직접 쓰이는 기능이 아니라는 점이 중요하다. **이상치 탐지(Outlier Detection)**는 이렇게 쌓인(혹은 실시간으로 들어오는) 데이터에서 정상 범위를 벗어난 값을 판별하는 기법으로, 가장 대표적인 방법이 데이터의 **표준편차**를 이용해 평균에서 일정 범위를 벗어난 값을 판정하는 방식이다.

# Notes

<aside>데이터 로깅의 목적</aside>

| 목적 | 설명 |
|---|---|
| 원인 추적(사후 진단) | 오류 발생 시점 전후의 데이터를 되짚어 원인을 분석 |
| 감사 추적(Audit Trail) | 언제 어떤 명령·이벤트가 있었는지 기록으로 남겨 책임 소재 확인 |
| 성능/트렌드 분석 | 장기간 데이터를 모아 성능 저하, 마모 추세 등을 파악 |
| [[2. SCADA 구조와 산업용 모니터링 시스템\|SCADA]] 이력 관리(Historian) 연동 | SCADA의 이력 저장 기능과 동일한 데이터를 공유 |

<aside>데이터 로깅에 대한 오해(오답 함정)</aside>

"데이터 로깅이 로봇의 실시간 제어 피드백에 직접 사용된다"는 서술은 틀렸다. 로깅은 **이미 지나간 데이터를 저장하는 사후적 기록**이며, 실시간 폐루프 제어는 로깅과는 별도의 저지연 센서 피드백 경로를 사용한다([[6. 센서 피드백과 신호처리]] 참고). 로깅 데이터는 조회·분석 시점에는 이미 "과거"의 데이터다.

<aside>로그 레벨</aside>

| 레벨 | 용도 |
|---|---|
| DEBUG | 개발 중 상세 추적용, 운영 환경에서는 보통 비활성화 |
| INFO | 정상적인 주요 이벤트 기록(가동 시작, 모드 전환 등) |
| WARN | 즉각적인 오류는 아니지만 주의가 필요한 상태 |
| ERROR | 기능 실패, 오류 발생 시점 기록 |

<aside>로그 보존 정책(로그 로테이션)</aside>

모든 원본 로그를 무기한 그대로 보관하는 것은 저장 공간 문제로 현실적이지 않다. **[[로그 로테이션(Log Rotation)|로그 로테이션]]**을 통해 일정 크기/기간마다 로그 파일을 분리·압축하고, 보존 기간이 지난 데이터는 요약본만 남기거나 삭제하는 정책이 일반적이다.

<aside>이상치 탐지 개념</aside>

**이상치(Outlier)**는 정상적인 데이터 분포에서 벗어난 값을 말하며, 이상치 탐지는 센서 오작동, 충돌, 예기치 않은 부하 등을 조기에 포착하는 데 쓰인다.

<aside>표준편차 기반 이상치 탐지(Z-score / 3-시그마 규칙)</aside>

데이터의 평균 $\mu$와 표준편차 $\sigma$를 이용해 각 값의 표준점수(**[[Z-score(표준점수)|Z-score]]**)를 다음과 같이 구한다.

$$z = \frac{x - \mu}{\sigma}$$

일반적으로 $|z|$가 2~3을 넘으면 이상치로 판단한다(정규분포 가정 시 평균 ±3$\sigma$ 밖은 전체의 약 0.3%에 불과). "데이터의 표준편차를 이용하여 평균으로부터 일정 범위를 벗어난 값을 이상치로 판단하는 방법"이 바로 이 Z-score/3-시그마 규칙에 해당한다.

<aside>IQR(사분위수 범위) 기반 이상치 탐지</aside>

정규분포를 가정하기 어려운 데이터에는 **[[IQR(사분위수 범위)|IQR]]** 방법이 더 안정적이다.

- 1사분위수 $Q_1$, 3사분위수 $Q_3$에 대해 $IQR = Q_3 - Q_1$
- $Q_1 - 1.5 \times IQR$ 미만이거나 $Q_3 + 1.5 \times IQR$ 초과인 값을 이상치로 판정

<aside>이상치 탐지와 필터링의 관계</aside>

이상치 탐지는 "판별"에 초점이 있고, [[이동평균 필터(Moving Average Filter)|이동평균 필터]]나 [[칼만 필터(Kalman Filter)|칼만 필터]]([[6. 센서 피드백과 신호처리]] 참고)는 잡음을 "완화"하는 데 초점이 있다는 점에서 목적이 다르다. 실무에서는 두 가지를 함께 사용해, 필터링으로 잡음을 줄인 뒤 남은 급격한 이탈값을 이상치로 판정하는 경우가 많다.

<aside>예시 — 로봇 관절 전류 이상치 탐지</aside>

**예시**: 정상 작업 중 로봇 관절 모터 전류가 평균 2A, 표준편차 0.3A로 유지되다가 특정 순간 4.5A로 튀었다면 $z = (4.5-2)/0.3 \approx 8.3$으로 임계치를 크게 초과해 이상치로 판정되고, 충돌 또는 기구적 걸림(jamming) 가능성에 대한 알람([[3. 데이터 시각화와 알람(HMI)]] 참고)으로 이어질 수 있다.

<aside>핵심 정리</aside>

- 데이터 로깅의 목적은 **사후 원인추적·감사·성능분석**이며, 실시간 폐루프 제어에 직접 쓰이지 않는다
- 원본을 무기한 보관하지 않고 **로그 로테이션**으로 보존 기간을 관리한다
- "표준편차를 이용해 평균에서 일정 범위를 벗어난 값을 이상치로 판단"하는 방법은 **Z-score(3-시그마 규칙)**
- 정규분포 가정이 어려우면 **IQR 방법**이 대안이 된다
- 이상치 탐지(판별)와 필터링(완화)은 목적이 다르며 함께 쓰이는 경우가 많다

# Summary

**[[스트림 처리(Stream Processing)|스트림 처리]]**는 데이터를 일정량 모아서 한꺼번에 처리하는 [[배치 처리(Batch Processing)|배치 처리]]와 달리, **데이터가 발생하는 즉시 순차적으로 처리**해 지연 시간을 최소화하는 방식이다. 로봇 모니터링에서는 다수 로봇으로부터 끊임없이 유입되는 센서 데이터를 실시간으로 집계·이상치 판정하는 데 사용되며, 이렇게 처리된 결과가 곧바로 알람이나 대시보드 갱신으로 이어진다.

# Notes

<aside>스트림 처리 개념</aside>

스트림 처리는 끝이 정해지지 않은(unbounded) 데이터 흐름을 데이터가 도착하는 순서대로 즉시 처리하는 방식이다. 하나의 이벤트(예: 센서 값 하나)가 들어오면 그 즉시 연산을 수행하고 다음 이벤트를 기다린다.

<aside>스트림 처리 vs 배치 처리 비교</aside>

| 항목 | [[배치 처리(Batch Processing)\|배치 처리]] | 스트림 처리 |
|---|---|---|
| 처리 단위 | 일정 기간 축적된 데이터 묶음 | 개별 이벤트(또는 작은 윈도우) |
| 지연(Latency) | 큼 (다음 배치 주기까지 대기) | 작음 (도착 즉시 처리) |
| 데이터 범위 | 유한(bounded) 데이터셋 | 무한(unbounded) 데이터 흐름 |
| 적합한 용도 | 일 단위 통계 리포트 등 | 실시간 알람, 실시간 대시보드 갱신 |

"실시간 데이터 처리를 위한 스트림 처리의 특징"을 묻는 문제에서는 **"데이터가 도착하는 즉시 순차적으로 처리하여 지연을 최소화한다"**는 서술이 옳은 특징이며, 반대로 "일정 기간 데이터를 모아 한 번에 처리한다"는 서술은 배치 처리의 특징이므로 오답이다.

<aside>윈도우 연산(Windowing)</aside>

스트림은 끝이 없으므로 평균·합계 같은 집계 연산은 "최근 얼마간의 데이터"라는 범위, 즉 **[[윈도우 연산(Windowing)|윈도우]]**를 지정해서 수행한다.

- **텀블링 윈도우(Tumbling Window)**: 겹치지 않는 고정 구간(예: 매 5초마다 그 5초간의 평균)
- **슬라이딩 윈도우(Sliding Window)**: 구간이 겹치도록 이동하며 계산(예: 최근 5초를 1초마다 갱신)

<aside>로봇 모니터링 파이프라인 구조</aside>

1. **수집/통신**: 로봇 센서 데이터가 [[2. MQTT·WebSocket과 실시간 모니터링 통신|MQTT]] 등으로 유입
2. **스트림 처리**: 윈도우 단위로 평균·표준편차 등을 실시간 계산, [[5. 데이터 로깅과 이상치 탐지|이상치 탐지]] 로직 적용
3. **후속 처리**: 정상 데이터는 저장(로깅)으로, 이상 판정된 데이터는 즉시 [[4. 데이터 시각화와 알람(HMI)|알람]]으로 분기

이처럼 스트림 처리는 통신 계층에서 들어온 원시 데이터를 로깅·알람 계층으로 넘기기 전에 실시간 가공을 담당하는 중간 계층 역할을 한다.

<aside>예시 — 로봇 플릿의 실시간 이상 감지 파이프라인</aside>

**예시**: 수십 대의 이동로봇이 1초 주기로 배터리 전압을 MQTT로 발행하면, 스트림 처리 엔진이 로봇별로 최근 5초 슬라이딩 윈도우의 평균·표준편차를 계속 갱신한다. 특정 로봇의 전압이 이 윈도우 기준 표준편차를 크게 벗어나면(Z-score 이상치 판정, [[5. 데이터 로깅과 이상치 탐지]] 참고) 배치 처리로 다음 날 리포트를 기다릴 필요 없이 그 즉시 Critical 알람이 발생한다.

---

<aside>핵심 정리</aside>

- 스트림 처리는 데이터가 **도착하는 즉시 순차적으로 처리**해 지연을 최소화하며, 무한(unbounded) 데이터 흐름을 다룬다는 점에서 축적 후 일괄 처리하는 배치 처리와 대조된다
- 무한 데이터의 집계는 텀블링/슬라이딩 **윈도우** 단위로 수행한다
- 로봇 모니터링에서는 통신 계층(MQTT 등)과 로깅/알람 계층 사이에서 **실시간 이상치 판정·집계**를 담당하는 중간 계층 역할을 한다

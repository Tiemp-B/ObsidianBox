# Summary

로봇 제어기의 저수준 제어 계층은 여러 태스크(서보 루프, 센서 읽기, 통신 처리 등)가 공유 자원(레지스터, 버퍼, 공유 메모리)에 동시에 접근한다. 이때 동기화 없이 접근하면 **경쟁 조건(Race Condition)**이 발생해 데이터가 손상될 수 있다. [[뮤텍스(Mutex)|뮤텍스]]와 [[세마포어(Semaphore)|세마포어]]는 이를 막기 위한 대표적인 동기화 메커니즘이며, 동기화를 잘못 설계하면 오히려 태스크들이 서로를 무한정 기다리는 **[[데드락(Deadlock)|데드락]]**에 빠질 수 있다. 이 페이지는 임계영역·뮤텍스·세마포어의 차이와 데드락의 발생 조건·예방 기법을 다룬다.

# Notes

<aside>왜 동기화가 필요한가</aside>

여러 태스크(스레드/프로세스)가 동시에 같은 자원에 접근하면 접근 순서에 따라 결과가 달라지는 **경쟁 조건(Race Condition)**이 발생한다.

**예시 — 동기화가 없을 때의 문제**

서보 제어 스레드와 모니터링 스레드가 공유 변수 `total_cycles`(총 제어 사이클 수)를 함께 사용한다고 하자.

- 서보 제어 스레드: 매 제어 주기마다 `total_cycles = total_cycles + 1` 실행
- 모니터링 스레드: 주기적으로 `total_cycles` 값을 읽어 화면에 표시

`total_cycles = total_cycles + 1`은 한 줄로 보이지만 실제로는 **① 현재 값을 읽고 → ② 1을 더하고 → ③ 결과를 저장**하는 3단계로 실행된다. 서보 제어 스레드가 ①~② 사이에서 문맥 전환(context switch)되어 다른 스레드가 같은 변수를 먼저 갱신해버리면, 서보 제어 스레드는 자신이 앞서 읽어둔(이미 낡은) 값에 1을 더해 덮어쓰게 된다. 그 결과 실제로는 두 번 증가해야 할 값이 한 번만 증가한 것처럼 **갱신이 유실**된다 — 이것이 경쟁 조건이다.

**해결**: `total_cycles`에 접근하는 구간을 임계영역으로 지정하고 뮤텍스로 감싸, 한 번에 하나의 스레드만 읽기-더하기-저장을 마치도록 강제한다.

```
lock(mutex)
total_cycles = total_cycles + 1
unlock(mutex)
```

이렇게 하면 어떤 스레드가 이 구간에 진입해 있는 동안 다른 스레드는 `lock(mutex)`에서 대기하므로, 값 유실 없이 정확하게 누적된다.

<aside>임계영역(Critical Section)</aside>

[[임계영역(Critical Section)|임계영역]]은 **공유 자원에 접근하는 코드 부분**으로, 동시에 여러 스레드가 실행하면 데이터 일관성 문제가 발생할 수 있어 **한 번에 하나의 스레드만 실행**되어야 하는 영역이다. 위 예시에서 `lock(mutex)`와 `unlock(mutex)` 사이의 세 줄이 바로 임계영역이다.

- 임계영역은 "메모리 할당을 위한 코드 영역"이나 "네트워크 통신을 위한 코드 영역"을 뜻하는 것이 아니라, **공유 자원 접근 코드 자체**를 가리키는 개념이다 — 혼동 주의

<aside>뮤텍스(Mutex) vs 세마포어(Semaphore)</aside>

| 구분 | 뮤텍스(Mutex) | 세마포어(Semaphore) |
|---|---|---|
| 값의 범위 | 0/1 (이진, Lock/Unlock) | **정수 카운터** — 이진 세마포어뿐 아니라 **카운팅 세마포어**도 존재 |
| 소유권(Ownership) | **있음** — 잠금을 획득한 스레드만 해제 가능 | **없음** — 신호를 받은 임의의 스레드가 해제(signal) 가능 |
| 용도 | 하나의 자원에 대한 **상호배제**(한 번에 1개 스레드만 접근) | 여러 개의 동일 자원에 대한 **동시 접근 개수 제어**(공유 자원 접근 제어) |
| 사용 범위 | 주로 단일 프로세스 내 스레드 간 | 프로세스 간 동기화에도 사용 가능 |

- **세마포어는 소유권 개념이 없어** 신호를 받은 어떤 스레드든 세마포어를 해제할 수 있지만, **뮤텍스는 잠금을 획득한 스레드만이** 잠금을 해제할 수 있다 — 이 소유권 차이가 가장 핵심적인 구분 기준이다.
- 세마포어는 **반드시 이진수(0 또는 1)만 갖는 것이 아니라**, 0 이상의 정수값을 갖는 **카운팅 세마포어**도 존재하며, 이 값으로 동시에 접근 가능한 자원의 개수를 관리한다.

<aside>데드락(Deadlock)</aside>

[[데드락(Deadlock)|데드락]]은 둘 이상의 태스크가 서로 상대방이 점유한 자원을 무한정 기다리며 아무도 진행하지 못하는 상태다. 아래 **4가지 조건이 모두 성립**해야 발생한다.

- **상호 배제(Mutual Exclusion)**: 자원을 한 번에 한 태스크만 사용 가능
- **점유와 대기(Hold and Wait)**: 자원을 점유한 채로 다른 자원을 추가로 요청
- **비선점(No Preemption)**: 다른 태스크가 점유 중인 자원을 강제로 빼앗을 수 없음
- **순환 대기(Circular Wait)**: 태스크들이 원형으로 서로의 자원을 기다림

**예시 — 로봇 제어기에서의 데드락 상황**

두 스레드가 서로 다른 두 개의 뮤텍스를 **반대 순서로** 잠그려고 할 때 전형적으로 발생한다.

- **모션 제어 스레드**: 뮤텍스 A(관절 상태 버퍼)를 먼저 잠그고, 이어서 뮤텍스 B(통신 버퍼)를 잠그려고 시도
- **통신 처리 스레드**: 뮤텍스 B(통신 버퍼)를 먼저 잠그고, 이어서 뮤텍스 A(관절 상태 버퍼)를 잠그려고 시도

두 스레드가 거의 동시에 실행되면:

1. 모션 제어 스레드가 뮤텍스 A를 획득
2. 통신 처리 스레드가 뮤텍스 B를 획득
3. 모션 제어 스레드는 뮤텍스 B를 기다림(통신 처리 스레드가 점유 중) / 통신 처리 스레드는 뮤텍스 A를 기다림(모션 제어 스레드가 점유 중)
4. 서로가 서로를 영원히 기다리며 둘 다 진행 불가 → **데드락**

이 상황은 4가지 조건을 모두 만족한다: 각 뮤텍스는 한 스레드만 보유(상호배제), 하나를 쥔 채 다른 것을 요청(점유와 대기), 강제로 빼앗을 수 없음(비선점), 두 스레드가 서로의 자원을 원형으로 기다림(순환 대기).

**데드락과 혼동되는 개념 — 우선순위 역전**
[[우선순위 역전(Priority Inversion)|우선순위 역전(Priority Inversion)]]은 데드락의 발생 조건이 아니라 별개의 스케줄링 문제다. 낮은 우선순위 태스크가 자원을 점유한 상태에서 높은 우선순위 태스크가 그 자원을 기다리게 되어, 결과적으로 높은 우선순위 태스크가 지연되는 현상을 말한다. 해결책인 우선순위 상속 프로토콜은 [[2. 실시간 운영체제와 스케줄링]] 참고.

<aside>데드락 예방</aside>

데드락 예방은 4가지 필요조건(상호배제·점유와대기·비선점·순환대기) 중 **하나를 깨뜨리는 방식**으로 이루어진다.

- **상호 배제 자체를 없애는 것은 예방책이 될 수 없다.** 상호 배제를 제거하면 여러 태스크가 동시에 자원에 접근하게 되어 동기화의 근본 목적(데이터 일관성 보장)이 무너지고 오히려 데이터가 손상된다.
- 실질적인 예방은 **점유와 대기 / 비선점 / 순환 대기** 중 하나를 깨뜨리는 방식으로 이루어진다.

**전부 할당 방식(All-or-Nothing)** — "점유와 대기" 조건을 제거
프로세스가 **실행되기 전에 필요한 모든 자원을 한꺼번에 할당**받고 시작하는 방식이다. 실행 중 추가 자원 요청이 없으므로 "점유와 대기" 조건을 원천적으로 제거해 데드락을 방지한다.

**잠금 순서 통일** — "순환 대기" 조건을 제거
모든 스레드가 자원을 항상 같은 순서(예: A → B)로 잠그도록 강제하면, 위 예시처럼 서로 반대 순서로 자원을 요청하는 상황 자체가 생기지 않아 순환 대기 조건이 성립하지 않는다.

<aside>핵심 정리</aside>

- 동기화가 없으면 **경쟁 조건**(예: 카운터 갱신 유실)이 발생 → 임계영역 + 잠금으로 해결
- 임계영역 = **공유 자원에 접근하는 코드 구간**, 한 번에 하나의 스레드만 진입 가능
- 뮤텍스 = 소유권 O, 이진(Lock/Unlock) / 세마포어 = 소유권 X, 이진+카운팅 모두 가능
- 데드락 4조건: **상호배제·점유대기·비선점·순환대기** (전부 성립해야 발생)
- 데드락 예시: 두 스레드가 두 자원을 반대 순서로 잠그면 서로를 기다리며 정지
- 데드락 예방: 상호배제를 없애는 게 아니라 **점유대기·비선점·순환대기 중 하나를 깨는 것** (전부 할당 방식, 잠금 순서 통일 등)
- 우선순위 역전은 데드락의 조건이 아니라 **별개의 스케줄링 문제**

# 조사 자료 — 로봇 제어기 구성과 실시간 처리

세세항목 "1. 로봇 제어기 특성"의 자료조사 Phase 1 초안. `robot-note-conventions.md` §2 절차에 따라 웹 조사 결과를 정리한다. 아직 NCS 원문·문제은행과 대조하지 않은 1차 초안이며, Phase 2(자체 검토)에서 근거 보강이 필요한 항목을 표시해 둔다.

---

## 1. 로봇 제어기의 계층 구조

산업용 로봇 제어기는 실시간(real-time) 모듈과 비실시간(non-real-time) 모듈을 함께 갖춘 특수한 아키텍처를 요구한다. 최근 구조는 흔히 **RTOS 기반의 실시간 파티션**과 **범용 OS 기반의 비실시간 파티션**을 함께 두는 이중 구조를 취한다.

제어 계층은 실시간 요구 수준에 따라 나뉜다.
- **디바이스 레벨**: 가장 엄격한 실시간 요구(액추에이터/센서 직접 제어)
- **제어 레벨**: 디바이스 레벨보다 대략 10배 낮은 샘플링 주기의 hard real-time 요구
- **애플리케이션 레벨**: soft real-time (경로계획, 모니터링, UI 등)

최신 연구·업계 동향은 서브밀리초(sub-millisecond) 응답시간과 안정성·안전성 준수를 목표로 하며, 산업제어 통신에서는 OPC-UA·ROS-Industrial 같은 상호운용성 표준이 널리 쓰인다. IEC 62443 등 사이버보안 규정도 최근 제어기 아키텍처 요구사항에 영향을 주고 있다.

**로봇 제어 시스템의 기능적 구성**(경로 생성부 → 로봇 기구학 해석부 → 특이형상(특이점) 해석부 → 서보 제어 및 추종부 → 모니터링/출력부)은 국내 특허 문헌에서도 공통적으로 언급되는 전형적 파이프라인이다. 서보 제어기는 매 제어주기마다 계산된 목표 궤적을 추종하도록 위치·속도·토크를 정밀 제어한다.

> [출처] [Comparing Industrial Robot Controller Architectures](https://eureka.patsnap.com/report-comparing-industrial-robot-controller-architectures), [An Overview of Industrial Robots Control and Programming Approaches (MDPI)](https://www.mdpi.com/2076-3417/13/4/2582), 국내 로봇 제어장치 특허 문헌(KR101411503B1 등)

**⚠ Phase 2 확인 필요**: "제어 레벨이 디바이스 레벨보다 약 10배 낮은 샘플링 주기"라는 수치는 단일 리포트(patsnap 리포트, 1차 출처 불명확) 기반이라 다른 출처로 교차 확인 필요. 확인 안 되면 정성적 서술("디바이스 레벨 > 제어 레벨 > 애플리케이션 레벨 순으로 실시간성이 완화된다")로 대체.

## 2. RTOS와 스케줄링

로봇 제어기의 실시간 계층은 대부분 RTOS 위에서 동작한다. RTOS 스케줄러는 정적 우선순위 방식(Rate Monotonic Scheduling, RMS)이나 동적 우선순위 방식(Earliest Deadline First, EDF)을 사용해 태스크 실행 순서를 결정한다.

- **RMS(Rate Monotonic Scheduling)**: 주기가 짧은 태스크일수록 높은 우선순위를 정적으로 부여. Liu & Layland의 고전적 스케줄링 가능성 상한은 **ln(2) ≈ 69.3%**로, 이 이하의 CPU 이용률에서는 모든 태스크의 데드라인 준수가 이론적으로 보장된다(이는 여러 RTOS 교재에서 공통적으로 인용되는 확립된 정리로, 이번 조사에서 추가 확인이 필요 없는 수준의 정설로 판단).
- **EDF(Earliest Deadline First)**: 데드라인이 가장 임박한 태스크에 동적으로 최고 우선순위를 부여. 이론적으로 **이용률 100%까지 스케줄링 가능**(RMS보다 이론적 상한이 높음)하지만, 우선순위 재계산 등 런타임 오버헤드가 RMS보다 크다.

**⚠ Phase 2 확인 필요 — 수치 폐기 후보**: 웹 검색 중 "EDF가 92% 이용률까지, 데드라인 미스율 2% 미만 달성"이라는 구체적 수치가 발견됐으나, 출처가 2025년 12월 arXiv 프리프린트(특정 시뮬레이션 조건 한정)로 확인되어 **일반화된 정설이 아님**. 로봇제어기 필기 노트에는 이 수치를 사용하지 않고, EDF의 고전적 이론 상한(100%)과 RMS의 ln(2)≈69.3% 상한만 정성적으로 대비한다.

**로봇 제어와의 연결**: RTOS는 로봇공학·산업제어에서 신뢰성 있는 고성능 솔루션을 제공하는 핵심 기반으로 널리 언급된다. 로봇 제어기에서는 모션 제어 태스크(가장 짧은 주기·최고 우선순위), 센서 폴링 태스크, 통신 태스크, UI/로깅 태스크(가장 낮은 우선순위) 등이 전형적인 우선순위 배치 사례다.

## 3. 동기화 메커니즘 (뮤텍스·세마포어·데드락·우선순위 역전)

- **뮤텍스(Mutex)**: 상호배제 전용 이진 세마포어. 한 시점에 하나의 태스크만 보유 가능, "소유권" 개념이 있어 뮤텍스를 획득한 태스크만 해제할 수 있다.
- **세마포어(Semaphore)**: 카운팅 세마포어(N개 자원 동시 접근 허용)와 이진 세마포어(이벤트 신호용)로 구분. 뮤텍스와 달리 소유권 개념이 없어 다른 태스크가 대신 해제(signal)할 수도 있다 — 태스크 간 이벤트 신호(inter-task signaling) 용도에 적합.
- **우선순위 역전(Priority Inversion)**: 고우선순위 태스크가 저우선순위 태스크가 보유한 자원(뮤텍스)을 기다리는 동안, 중간 우선순위 태스크가 저우선순위 태스크를 선점해버려 결과적으로 고우선순위 태스크가 무한정 대기하게 되는 현상. **1997년 NASA 화성탐사선 Mars Pathfinder**가 VxWorks RTOS에서 우선순위 상속(priority inheritance) 없이 뮤텍스를 이진 세마포어처럼 설정해 이 문제로 시스템 리셋을 반복한 유명한 실제 사례.
- **우선순위 상속(Priority Inheritance)**: 고우선순위 태스크가 저우선순위 태스크 소유의 뮤텍스를 기다리면, 그 저우선순위 태스크의 우선순위를 일시적으로 대기 중인 고우선순위 수준까지 끌어올려 중간 우선순위 태스크의 선점을 차단하는 해결 기법. FreeRTOS 등 다수 RTOS가 뮤텍스에 기본 적용.
- **데드락(Deadlock)**: 복수의 뮤텍스를 서로 다른 순서로 획득할 때 순환 대기가 발생하는 상황. 예방책은 모든 태스크가 자원을 **일관된 전역 순서**로 획득하도록 강제하는 것.

**로봇 제어기 예시**: 모션 제어 스레드가 엔코더 버퍼(자원 A)와 통신 버퍼(자원 B)를 이 순서로 잠그고, 통신 처리 스레드가 반대로 B→A 순서로 잠그면 두 스레드가 서로의 자원을 기다리며 데드락에 빠질 수 있다 — 자원 획득 순서를 통일해 예방한다.

> [출처] [Mutexes and Semaphores Demystified — Barr Group](https://barrgroup.com/blog/mutexes-and-semaphores-demystified), [Priority inversion — Mars Pathfinder 사례](https://medium.com/@skaiuijing/lets-write-a-real-time-operating-system-rtos-part7-semaphore-and-mutex-35723658a282), [STM32 FreeRTOS Mutex: Priority Inheritance](https://controllerstech.com/stm32-freertos-mutex/)

**Box 용어 확인 필요**: `뮤텍스(Mutex)`, `세마포어(Semaphore)`, `우선순위 역전(Priority Inversion)`, `데드락(Deadlock)`은 지식창고/Box에 이미 존재(기존 프로젝트에서 생성됨) — 재사용, 신규 생성 불필요.

# 조사 - HMI 설계와 로봇 프로그래밍 방식 (Phase 1~3, 2026-08-07)

## Phase 1 — 초기 조사

### E-stop(비상정지) — ISO 13850
- ISO 13850:2015 "Safety of machinery — Emergency stop function — Principles for design"가 기계류 비상정지 기능의 요구사항·설계원칙을 규정
- **접근성**: 항상 조작자의 손이 닿는 범위에, 각 고정 조작 스테이션(제어반)마다, 그리고 위험성평가로 식별된 다른 위치에도 설치
- **형태**: 대형 빨간 버섯머리형 버튼 + 노란 배경이 전형(직접적인 물리적 동작 요구 — 누름/당김. 풀코드·압력스트립·풋페달 등도 가능)
- **동작 원칙**: 단일 동작으로 활성화되며 항상 즉시 사용 가능해야 함. **활성화 후 자동으로 재시작되지 않으며, 위험 요인이 해소되었음을 확인한 뒤 수동으로 리셋해야만 정상 운전 재개**
- **중요한 위치**: 비상정지는 안전장치(가드 등)나 본질적으로 안전한 설계를 "대체"하는 수단이 아니라 **보완적 보호수단**이라는 점을 표준이 명시
- 출처: [ISO 13850:2015 공식페이지](https://www.iso.org/standard/59970.html), [ISO 13850 Emergency Stop Requirements Explained](https://machinerysafety101.com/2026/05/18/iso-13850-emergency-stop-requirements/)

### HMI 설계 — ISO 9241-110 (2020) 상호작용 7원칙
1. 사용자 작업 적합성(Suitability for the user's tasks)
2. 자기 기술성(Self-descriptiveness)
3. 사용자 기대 부합(Conformity with user expectations)
4. 학습 용이성(Learnability)
5. 제어 가능성(Controllability)
6. 사용 오류 강건성(Use error robustness)
7. 사용자 참여(User engagement)
- 이 표준은 대화형 시스템 전반에 적용되는 일반 원칙이며, 안전 필수(safety-critical) 시스템의 구체적 요구사항까지 다루지는 않음 — 로봇 원격제어 HMI처럼 안전이 중요한 경우 이 일반원칙 위에 E-stop 등 산업안전표준(ISO 13850 등)을 추가로 적용해야 함
- 제어 가능성(사용자가 프로세스를 통제할 수 있어야 함)·오류 강건성(실수해도 심각한 결과로 이어지지 않아야 함) 원칙이 "위험한 명령에 확인 절차를 둔다"는 기존 페이지 서술의 표준적 근거가 됨
- 출처: [ISO 9241-110:2020 공식페이지](https://www.iso.org/obp/ui/#iso:std:iso:9241:-110:ed-2:v1:en), [ISO's dialogue principles (2020) – DialogDesign](https://www.dialogdesign.dk/isos-dialogue-principles-2019/)

### NCS 학습2 "외부 툴과의 동기화 소프트웨어 개발하기" 필요지식 원문 확인 (LM1903080311/312 §2-1, footer p.16~22)
- 로봇은 프로그래밍 방식이 여러 가지이며, 그중 **교시형 프로그래밍**의 역사는 1960년대 초로 거슬러 올라감(컴�터 제어 이전부터 쓰이던 기본 방법이 오늘날까지 이어짐)
- **동력 이용 교시(Powered Teaching)**: 로봇 팔 관절의 움직임을 제어하는 토글 스위치·버튼이 있는 **티치 펜던트**로, 로봇 자체의 동력을 이용해 팔을 원하는 위치까지 순서대로 이동시킨 뒤 그 위치를 메모리에 기록. **점간 제어**(관절별 목표 위치를 순서대로 지정)하는 로봇에 흔히 사용
- **수동 교시(Lead-through Teaching)**: 작업자가 로봇 팔(또는 로봇과 같은 관절 배치의 별도 교시 장치)을 손으로 직접 잡고 동작 순서대로 움직이며, 그 경로를 촘촘한 점의 연속으로 기록. **스프레이 도장처럼 불규칙 경로의 연속경로 제어**에 편리
- **동작 프로그래밍(월드좌표계/공구좌표계)**: 관절별 개별 조작은 불편하므로, 손목 끝을 직선 경로로 움직이도록 제어하는 두 좌표계 방법을 추가 제공 — **월드좌표계**(기준 원점·좌표축이 로봇 베이스에 대해 고정된 위치로 정의), **공구좌표계**(손목 면판=엔드이펙터 부착부의 자세에 대해 상대적으로 정의). 두 좌표계 모두 직교좌표계. 직선운동은 직교 로봇에는 자연스럽지만 회전관절 조합 로봇에는 부자연스러워 **직선 보간** 과정이 필요(관절 보간은 이미 다른 페이지에서 다룸 — 여기서는 반복하지 않음)
- **교시 방법 장단점**: 장점 — 전문 프로그래밍 지식 없이 직관적으로 로봇을 학습시킴(사람에게 작업을 가르치는 방식과 유사). 단점 — ① 교시 중 정규 생산이 반드시 중지(뱃치가 작은 작업에 부적절) ② 티치 펜던트·교시 장치는 의사결정 논리(조건 분기 등)를 프로그램에 넣기 어려움 ③ 컴퓨터 제어 이전에 개발된 방법이라 CAD/CAM·생산DB·지역통신망 같은 최신 컴퓨터 통합 시스템과 호환이 어려움
- **오프라인 프로그래밍**: 로봇 프로그램을 **원격지 컴�터 터미널에서 준비한 뒤 로봇 제어기로 다운로드**해 실행. 그래픽 컴퓨터 시뮬레이션으로 프로그램을 사전 검증(NC 파트 프로그래밍의 오프라인 과정과 유사). **핵심 장점: 생산을 중단하지 않고 새 프로그램을 준비·다운로드 가능**. 3D 컴퓨터 모델과 실제 물리적 셀 사이에 형상 차이가 있을 수 있어, 실제 위치 데이터로 3D 모델을 보정하는 과정이 필요(단, 이 보정에 시간이 소요된다는 단점 있음)
- 출처: LM1903080311,+LM1903080312_로봇+운영+및+통합+소프트웨어+개발.pdf §2-1 필요지식(footer p.16~22), NCS 원문 직접 인용이므로 별도 웹검증 불요

### 교시/오프라인 프로그래밍 — 웹 보충 확인
- 월드프레임(WORLD): 로봇 베이스 중심 고정 좌표계, 직관적 조깅(오른손법칙 적용이 쉬움). 툴프레임(TOOL): TCP(Tool Center Point) 기준 좌표계, 티치펜던트의 좌표계 전환 버튼으로 WORLD↔TOOL 순환 전환
- 이 웹 출처는 NCS 원문과 정확히 일치하는 통상적 산업로봇 실무 용어임을 재확인하는 용도로만 사용(NCS 원문이 1차 근거)
- 출처: [Understanding Robot Coordinate Frames and Points](https://www.solisplc.com/tutorials/robot-coordinate-frames-and-points), [Jogging the Robot: FANUC](https://motioncontrolsrobotics.com/resources/tech-talk-articles/jogging-the-robot/)

## Phase 2 — 자체 검토

- 기존 페이지(6번)에는 "동작 프로그래밍(월드좌표계/공구좌표계 조깅 모드)"이 누락돼 있었음(NCS 원문에 명시된 필요지식) → 재작성 시 신규 반영 필요(단, 관절보간/직선보간 자체는 이미 다른 페이지에서 다뤘으므로 반복하지 않고 링크)
- ISO 13850/9241-110 표준 번호와 핵심 원칙은 국제표준 공식페이지로 직접 확인해 신뢰도 높음 — 추가조사 불필요

# Summary

**[[ROS(Robot Operating System)|ROS]]**는 로봇 소프트웨어의 여러 구성요소(노드) 간 통신을 위한 미들웨어로, 대표적인 통신 방식이 **Topic 기반 Publisher-Subscriber(발행-구독) 모델**이다. 이 방식은 비동기적으로 데이터를 주고받으며, 즉각적인 응답이 필요한 **[[ROS Service|Service]]**(동기 요청-응답)나 장시간 작업에 적합한 **[[ROS Action|Action]]**과는 성격이 다르다.

# Notes

<aside>ROS(Robot Operating System) 개념</aside>

로봇 소프트웨어의 여러 노드(프로세스)가 서로 통신할 수 있게 해주는 미들웨어/프레임워크다. 하나의 로봇 시스템도 보통 여러 개의 독립된 노드(센서 처리, 모션 계획, 통신 등)로 나뉘어 동작하며, ROS가 이들 사이의 통신을 중개한다.

<aside>Publisher-Subscriber(Topic) 모델</aside>

**Topic**이라는 이름의 채널에 **Publisher**가 메시지를 발행(publish)하면, 그 Topic을 구독(subscribe)한 여러 **Subscriber**가 비동기적으로 메시지를 수신한다. Publisher와 Subscriber는 서로의 존재를 직접 알 필요가 없는 **[[발행-구독 모델(Publish-Subscribe)|느슨한 결합]]** 구조다 — [[1. MQTT·WebSocket과 실시간 모니터링 통신|MQTT]]에서 다룬 발행-구독 개념과 동일한 원리다.

<aside>Service(동기 요청-응답) 모델</aside>

하나의 노드가 다른 노드에 요청(Request)을 보내고, 응답(Response)이 올 때까지 대기하는 **동기적** 통신 방식이다. "현재 로봇의 위치를 알려줘"처럼 즉각적인 응답이 필요한 일회성 요청에 적합하다.

<aside>Action 모델</aside>

"저 위치까지 이동해"처럼 완료까지 시간이 걸리는 작업을 요청하고, 그 진행 상황(Feedback)을 주기적으로 받다가 최종 결과(Result)를 받는 방식이다. 작업 중 취소(Cancel)도 가능해, Service와 달리 즉시 끝나지 않는 장시간 작업에 적합하다.

<aside>세 통신 방식 비교</aside>

| 방식 | 통신 성격 | 관계 | 적합한 용도 |
|---|---|---|---|
| Topic(Pub/Sub) | 비동기 | 다대다 | 센서값 등 지속적인 데이터 스트림 |
| Service | 동기(요청-응답) | 일대일 | 즉각 응답이 필요한 단발성 요청 |
| Action | 비동기 + 피드백 | 일대일 | 진행 상황 확인이 필요한 장시간 작업 |

<aside>Publisher-Subscriber 모델에 대한 올바른 설명</aside>

"Publisher와 Subscriber는 서로 직접 연결을 맺고 응답을 주고받는다"는 서술은 옳지 않다 — 실제로는 **Topic을 매개로 느슨하게 결합**되며, Subscriber는 받은 메시지에 대해 별도로 응답을 돌려주지 않는 **단방향 비동기** 통신이다. 이 "느슨한 결합·단방향·비동기"라는 성격이 Publisher-Subscriber 모델을 올바르게 설명하는 핵심이다.

<aside>예시 — 로봇 원격제어기에서의 활용</aside>

**예시**: 로봇의 배터리 상태나 센서값은 Topic으로 지속적으로 발행되어 원격제어기(Subscriber)가 실시간으로 구독하고, "정지"처럼 즉각적인 명령은 Service로 요청하며, "특정 위치로 이동"처럼 시간이 걸리는 작업은 Action으로 요청해 진행률을 계속 받아본다.

---

<aside>핵심 정리</aside>

- ROS의 Publisher-Subscriber(Topic) 모델은 **비동기·다대다·느슨한 결합**이 핵심이며, Publisher와 Subscriber가 직접 응답을 주고받지 않는다
- Service는 동기적 요청-응답(일대일), Action은 진행 상황 피드백이 있는 장시간 작업(일대일)에 적합해 Topic과 성격이 다르다
- 세 방식은 데이터의 성격(지속적 스트림 vs 단발성 요청 vs 장시간 작업)에 따라 선택한다

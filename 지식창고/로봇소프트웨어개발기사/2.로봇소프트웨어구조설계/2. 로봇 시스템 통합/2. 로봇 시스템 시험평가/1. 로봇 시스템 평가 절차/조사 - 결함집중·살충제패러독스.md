# 조사 - 결함집중·살충제패러독스 (2026-08-07)

NCS 대응 모듈 있음(LM1903080310 "로봇 소프트웨어 시험평가" 학습1·2). 개요(허브) 링크 정상. 문제은행(과목2 "2. 로봇 시스템 시험평가" 슬롯, 세세항목 미분리) 8문항 중 3건(단위테스트/블랙박스/통합테스트전략)이 이 세세항목 소관이며 전부 기존 페이지 커버 확인, 나머지 5건은 형제 세세항목("2. 로봇 시스템 시험평가" — 신뢰성/BIBO/부하테스트) 또는 과목1(로그 시스템) 소관.

## Phase 1 — 조사

### ISTQB 소프트웨어 테스팅 7원칙 중 결함 집중·살충제 패러독스 (신규)
- 기존 페이지3은 "좋은 테스트 케이스 작성 원칙"(1기능/positive·negative/명확성/재사용성)만 다루는데, 정보처리 시험평가에서 고전적으로 함께 다뤄지는 **테스팅 원칙**(결함 집중, 살충제 패러독스, 완벽한 테스팅은 불가능)이 빠져 있었음
- **결함 집중(Defect Clustering)**: 실제 결함은 전체 모듈에 고르게 분포하지 않고, 소수의 모듈에 몰려서 발견되는 경향이 있음(파레토 법칙과 유사 — 전체 결함의 약 80%가 20%의 모듈에서 발견되는 경향) — 결함이 발견된 모듈 주변을 더 집중적으로 시험하는 근거가 됨
- **살충제 패러독스(Pesticide Paradox)**: 같은 테스트 케이스를 반복해서 실행하면, 그 테스트로는 더 이상 새로운 결함을 찾아낼 수 없게 됨(해충이 같은 살충제에 내성이 생기는 것에 비유) — 새로운 결함을 찾으려면 테스트 케이스 자체를 주기적으로 검토·추가해야 함
- **완벽한(전수) 테스팅은 불가능(Exhaustive Testing is Impossible)**: 가능한 모든 입력·조건 조합을 다 시험하는 것은 사소한 경우를 빼면 현실적으로 불가능 — 위험 분석·우선순위에 따라 시험 노력을 집중해야 함(등가 분할·경계값 분석 같은 기법이 바로 이 원칙 때문에 필요)
- 출처: [7 Principles of Software Testing - Guru99](https://www.guru99.com/software-testing-seven-principles.html), [ISTQB Foundation Level - Seven Testing Principles](https://astqb.org/istqb-foundation-level-seven-testing-principles/)

## Phase 2 — 자체 검토

- ISTQB 7원칙 전부(테스팅은 결함 존재를 보여줄 뿐/조기 테스팅/테스팅은 상황 의존적/오류 부재의 궤변)를 다 넣기보다, 기존 페이지의 등가분할·경계값분석·테스트케이스 작성 원칙과 직접 연결되는 3가지(결함집중·살충제패러독스·전수테스팅불가)만 선별해 반영 — 나머지는 이 세세항목의 다른 페이지(V-모델, 통합시험기법)와 연결점이 약해 과다 반영 방지
- 파레토 법칙의 "80/20" 수치는 참고용 경향치이며 절대 법칙이 아니므로, 페이지 본문에는 "소수 모듈에 몰리는 경향" 정도로 반영(§2 원칙)

## Phase 3 — 결론

1개 페이지(3. 시험 절차서와 테스트 케이스 작성)에 신규 개념 3건 반영. Box 용어는 `결함 집중(Defect Clustering)`, `살충제 패러독스(Pesticide Paradox)` 신규 생성(전수 테스팅 불가는 등가분할·경계값분석 Box 용어에 이미 함축된 개념이라 별도 생성 안 함).

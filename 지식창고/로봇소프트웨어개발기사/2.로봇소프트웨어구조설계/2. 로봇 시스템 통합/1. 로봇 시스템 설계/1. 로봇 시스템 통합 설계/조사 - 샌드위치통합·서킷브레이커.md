# 조사 - 샌드위치통합·서킷브레이커 (2026-08-07)

NCS 대응 모듈 확인 없음(§1-2, 시스템 통합 일반 소프트웨어공학 지식). 문제은행 확인 결과 이 세세항목 관련 문항은 "로봇 시스템 통합 설계에서 고려해야 할 주요 요소" 1건(호환성/인터페이스명세/성능/안전성/확장성으로 이미 커버, 신규 조사 불필요), 나머지 3건은 형제 세세항목 "2. 로봇 시스템 최적화"(CPU/전력 최적화) 관련이라 이 세세항목 범위 밖. 개요(허브) 링크 정상.

## Phase 1 — 조사

### 샌드위치(Sandwich) 통합 — 빅뱅/하향식/상향식에 이은 4번째 전략 (신규)
- 기존 페이지3의 통합 전략 표는 빅뱅·하향식·상향식 3가지만 다루는데, 정보처리 소프트웨어공학에서 고전적으로 함께 다뤄지는 **샌드위치(혼합) 통합**이 빠져 있었음
- **샌드위치 통합**: 중간 계층을 기준으로, **상위로는 하향식**, **하위로는 상향식**을 동시에 진행해 양쪽에서 동시에 결합해 나가는 방식 — 두 팀이 각자 다른 계층을 병렬로 개발·통합할 수 있어, 인터페이스 결함을 상대적으로 일찍 발견할 수 있음
- 출처: [Sandwich Testing - GeeksforGeeks](https://www.geeksforgeeks.org/software-testing/sandwich-testing-software-testing/), [Integration Testing Strategies: Top-Down, Bottom-Up, and Sandwich](https://www.leadwithskills.com/blogs/integration-testing-strategies-top-down-bottom-up-sandwich)

### 서킷 브레이커(Circuit Breaker) 패턴 — 안전성(장애 격리)의 구체적 구현 (신규)
- 기존 페이지2는 "안전성: 한 모듈의 오류가 전체 시스템에 연쇄적으로 전파되지 않도록 격리"라고만 서술하고, 구체적으로 어떻게 격리하는지는 다루지 않았음
- **서킷 브레이커**: 특정 서브시스템(모듈·서비스) 호출이 반복적으로 실패하면, 회로 차단기처럼 그 호출을 일시적으로 **차단**해 실패한 모듈에 더 이상 부하를 주지 않고 다른 모듈로 장애가 전파(연쇄 장애)되는 것을 막는 패턴
- 일정 시간 후 상태를 다시 확인(probe)해 정상화되면 자동으로 호출을 재개 — 장애 격리+자동 복구를 함께 제공
- 출처: [Circuit Breaker Pattern in Microservices - GeeksforGeeks](https://www.geeksforgeeks.org/system-design/what-is-circuit-breaker-pattern-in-microservices/)

## Phase 2 — 자체 검토

- 샌드위치 통합의 세부 시험 절차(스텁/드라이버 조합)까지는 넣지 않고, 하향식+상향식을 동시에 쓴다는 핵심 개념만 반영
- Hystrix/Resilience4J 같은 구체적 구현 라이브러리명은 로봇 소프트웨어 시험 범위를 벗어나는 세부사항이라 조사md에만 참고로 남기고 페이지에는 반영하지 않음

## Phase 3 — 결론

2개 페이지(2. 시스템 통합의 개념과 고려 요소 — 서킷 브레이커 1건, 3. 인터페이스 설계와 통합 전략 — 샌드위치 통합 1건)에 신규 개념 2건 반영. Box 용어는 `샌드위치 통합(Sandwich Integration)`, `서킷 브레이커(Circuit Breaker)` 신규 생성.

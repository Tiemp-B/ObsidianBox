# 조사 - 계층적상태기계·워치독교차링크 (2026-08-07)

개요(허브) 링크 정상. 문제은행 3문항(상태다이어그램목적/상태기계장점/예외처리불필요상황) 전부 기존 페이지 커버 확인.

## Phase 1 — 조사

### 계층적 상태 기계(Hierarchical State Machine, HSM) — 상태 폭발 문제의 해결책 (신규)
- 기존 페이지2는 "새로운 상태·전이를 추가할 때 기존 로직을 크게 건드리지 않아도 된다"는 유지보수 장점만 서술하는데, 상태 개수가 많아질 때 실제로 생기는 **상태 폭발(state explosion)** 문제와 그 해결책은 다루지 않았음
- **상태 폭발**: 상태 기계가 복잡해질수록 상태 수가 기하급수적으로 늘고, 여러 상태에서 똑같은 예외 처리 로직(DRY 원칙 위반)이 중복되어 관리가 어려워지는 현상
- **계층적 상태 기계(HSM)**: 상태를 **중첩(nested)** 구조로 조직화해, 여러 하위 상태가 공통으로 처리해야 하는 로직(예: "통신 두절" 예외 처리)을 상위(부모) 상태에 한 번만 정의하고 하위 상태들이 이를 물려받게(행위적 상속) 함 — 각 하위 상태는 자신만의 차이점만 추가로 정의하면 됨
- 예: "이동 중"이라는 부모 상태 아래 "전진"·"회전"·"정지 대기" 같은 하위 상태를 두면, "긴급 정지" 이벤트 처리는 부모 상태에 한 번만 정의해도 모든 하위 상태에서 공통으로 작동함
- 출처: [Introduction to Hierarchical State Machines - Barr Group](https://barrgroup.com/blog/introduction-hierarchical-state-machines), [Hierarchical State Machine - EventHelix](https://www.eventhelix.com/design-patterns/hierarchical-state-machine/)

### 워치독 타이머(Watchdog Timer) — 이미 다른 세세항목에서 다룬 예외 복구 메커니즘 (교차 링크)
- 기존 페이지2의 예외 처리 필요 상황 목록(센서 이상, 통신 두절, 액추에이터 고장 등)과 자연스럽게 연결되는 **워치독 타이머**가 이 vault의 다른 세세항목("3. 워치독 타이머", 로봇 액추에이터 제어)에 이미 상세히 다뤄져 있음을 확인
- 소프트웨어가 무한루프·데드락에 빠져 스스로 복구하지 못할 때 하드웨어 차원에서 자동 재시작시키는 마지막 안전장치로, 이 페이지의 예외 처리 논의와 연결할 가치가 있음 — 중복 작성하지 않고 교차 링크만 추가

## Phase 2 — 자체 검토

- HSM의 UML statechart 세부 표기법(중첩 상태 그리는 법 등)까지는 넣지 않고, "왜 필요한가(상태 폭발)"와 "핵심 아이디어(공통 로직을 부모 상태에 한 번만 정의)"만 반영
- 워치독은 소프트웨어 자체 복구가 안 될 때의 최후 수단이라는 위치를 명확히 해, 기존 페이지의 예외 처리(소프트웨어 차원 대응)와 역할이 다르다는 점을 서술

## Phase 3 — 결론

1개 페이지(2. 상태 기계와 예외 처리)에 신규 개념 1건(HSM) + 교차 링크 1건(워치독 타이머) 반영. Box 용어는 `계층적 상태 기계(Hierarchical State Machine)` 신규 생성.

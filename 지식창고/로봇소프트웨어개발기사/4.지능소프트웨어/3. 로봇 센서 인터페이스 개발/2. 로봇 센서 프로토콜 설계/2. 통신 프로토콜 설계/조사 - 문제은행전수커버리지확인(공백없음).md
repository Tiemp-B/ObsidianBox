# 조사 - 문제은행전수커버리지확인(공백없음)

**대상 세세항목**: 과목4 지능소프트웨어 / 3. 로봇 센서 인터페이스 개발 / 2. 로봇 센서 프로토콜 설계 / 2. 통신 프로토콜 설계

**문제은행 확인**: 전용 슬롯(4문항: CAN 특징, 센서 시간동기화 고려요소, 보안 고려사항, 실시간성 보장 방법) + 형제 세세항목("1. 로봇센서 인터페이스")에서 이월된 부모 슬롯 4문항(TCP/IP 실시간성, QoS, CAN×2)을 전수 대조한 결과, **모두 기존 페이지에 이미 커버되어 있어 새로운 문제은행 공백이 없음**을 확인.

| 문항 | 커버 위치 |
|---|---|
| CAN 특징이 아닌 것 / CAN 중재 방식 | 과목1 "7. 로봇 제어기 통신 프로토콜 심화" — 멀티마스터, 메시지ID 기반 무손실 중재, 실시간성 재확인 |
| QoS 보장 가장 중요한 요소 | 이 세세항목 기존 페이지 "3. 통신 프로토콜 설계의 고려사항" — 우선순위 차등 부여 |
| 센서 데이터 시간동기화 고려요소 | 같은 페이지 — 타임스탬프·샘플링주기보정·클록동기화(NTP/PTP) |
| 보안 고려사항이 아닌 것 | 같은 페이지 — 기밀성·무결성·인증이 핵심이며 압축률은 보안 요소와 무관 |
| 실시간성 보장 방법이 아닌 것 | 같은 페이지 — 우선순위 스케줄링·TDMA·인터럽트가 실시간성 보장 방법이며 폴링만 사용하는 방식은 해당하지 않음 |
| TCP/IP 실시간 제어 데이터에 적합한 프로토콜 | 같은 페이지에서 과목1 "원격제어 통신 프로토콜 개요"로 교차링크 — UDP가 TCP보다 적합 |

## Phase 1 — 확인용 검색(1라운드로 충분— 신규 공백 없음을 확인하는 목적)

검색어: "로봇 센서 데이터 시간 동기화 PTP NTP 통신 프로토콜 보안 실시간성 확인"

- NTP는 인터넷 환경 1~50ms, LAN 내 0.1ms 수준 정확도, 동기화까지 10분 이상 소요. PTP(IEEE 1588)는 ms~ns 단위의 훨씬 높은 정확도를 제공하며 잦은 폴링 없이도 대역폭·CPU를 절약.
- 이 수치는 기존 페이지의 "클록 동기화 프로토콜(NTP, PTP)" 언급을 뒷받침하는 배경 지식일 뿐, 문제은행 문항("시간동기화에서 고려해야 할 요소가 **아닌** 것")에 답하는 데는 기존 서술(타임스탬프·샘플링주기보정·클록동기화)만으로 충분 — 새로운 반영 사항 없음.

## Phase 2 — 결론

- 이 세세항목은 기존 페이지 3건(개요·통신버퍼구조·설계고려사항)이 이미 문제은행 전체(전용 4문항 + 이월 4문항)를 정확히 커버하고 있어, **신규 콘텐츠 반영 없이 완료 처리**한다.
- NCS 자료 대조 aside 없음(이미 클린), 한자·위키링크 등 기존 검증도 이전 배치에서 이미 통과된 상태 — 이번 배치는 내용 변경이 없으므로 재검증 생략.

# 조사 - 가반하중 (2026-08-10)

개요(허브) 링크 정상, NCS 자료 대조 aside 없음(이미 클린). 문제은행(세부항목 슬롯 11문항 중 이 세세항목 소관 "작업지능SW 목표사양 설정시 고려요소 아닌것" 1문항) 기존 페이지가 정확히 커버 확인. ALFUS 관련 서술(임무·환경 복잡도 비례, HRI 정도 반비례)도 NIST ALFUS의 3축(Mission Complexity·Environmental Complexity·Human Independence) 프레임워크와 일치함을 재확인(기존 서술에 오류 없음). 3라운드 웹검색 반복 적용.

## Phase 1 — 3라운드 반복 검색

### 1라운드 — 후보 개념 탐색
- "robot payload definition maximum rated load capacity specification" 검색 → 가반하중은 엔드이펙터(그리퍼 등)와 실제 작업물의 무게를 모두 포함해 로봇이 안전하게 다룰 수 있는 최대 무게라는 정의 확인 — 기존 페이지의 "목표사양 4요소" 표에 "가반 하중"이 언급만 되고 정의가 없음(신규 공백)
- "robot payload vs actual carrying capacity reach speed tradeoff effect" 검색 → 가반하중은 작업반경(reach)이 커질수록(무게중심에서 멀어질수록) 감소하는 경향이 있다는 트레이드오프 확인

### 2라운드 — 파생 심화 검색
- "가반하중 정의 정격가반하중 최대가반하중 차이 로봇" 검색 → 한국어 자료로 가반하중이 엔드이펙터 무게까지 포함한다는 정의 재확인. "정격가반하중 vs 최대가반하중"의 명확한 구분은 한국어 자료에서 직접 확인하지 못해 이번 반영에서는 제외(§2 원칙, 불확실한 세부 구분 서술 지양 — feedback_verify_domain_knowledge)
- "로봇 가반하중 작업반경 반비례 트레이드오프 그래프" 검색 → 한국어 자료로 동일 하중 등급의 로봇에서 하중이 클수록 안정성을 위해 작업반경이 제한되는 반비례 경향 재확인

### 3라운드 — 반영 후보 구체화 검증
- "\"정격 가반하중\" 로봇 스펙 정의" 검색 → "정격 가반하중"이 한국어 로봇 스펙 문서에서 실제로 쓰이는 표준 용어임을 확인(로봇이 안전하게 다룰 수 있는 최대 하중), 6축 로봇의 가반하중이 1kg 미만~200kg 이상까지 다양하다는 예시로 스펙 범위의 폭을 확인

## Phase 2 — 자체 검토

- 가반하중은 기존 표에 이름만 있고 정의가 없던 용어라 Box 용어로 신규 생성해 보강
- 정격/최대 가반하중의 세부 구분은 한국어 자료로 명확히 확인하지 못해 반영하지 않고, 정의(엔드이펙터+작업물 포함)와 작업반경과의 반비례 관계까지만 반영(§2 원칙 및 도메인지식 검증 원칙)
- ALFUS 관련 기존 서술은 NIST 원 표준의 3축 프레임워크와 일치함을 재확인했을 뿐 별도 반영 사항 없음

## Phase 3 — 결론

기존 페이지의 "목표사양 4요소" 표에 가반하중 정의를 보강하는 교차 참조 추가. 신규 Box 용어 `가반하중(Payload)` 생성.

# 조사 - 요구사항명세서품질·프로토타이핑 (2026-08-10)

개요(허브) 링크 정상, NCS 자료 대조 aside 없음(이미 클린). 문제은행(세부항목 슬롯 11문항) 확인 결과, 기존 2개 페이지(제조공정 4대 작업분야, 로봇 타입 분류)는 도메인 특화 내용(작업분야별 로봇 요구사항)만 다루고, 정작 문제은행에 있는 **일반 소프트웨어 요구사항공학 방법론**(요구사항명세서 품질특성, 요구사항 도출 기법으로서의 프로토타이핑) 문항 4건("요구사항명세서 품질특성"·"프로토타이핑 단점"·"작업요구사항분석 고려사항 아닌것"·"작업요구사항분석 우선고려요소")이 vault 전체에 전혀 반영되어 있지 않음을 발견 — **문제은행 공백**으로 판단해 우선 보강(feedback_syllabus_over_examquestions 원칙에 따라 최우선 처리). "UML 정적구조 다이어그램"(클래스 다이어그램) 1건은 과목2 "UML 구조적 다이어그램"에 이미 커버되어 교차 링크 처리, "SIL 최고등급"은 이미 존재하는 SIL Box 용어로 커버, 나머지는 형제 세세항목("2. 로봇 성능 분석", "3. 작업지능 소프트웨어 목표사양") 소관으로 확인. 3라운드 웹검색 반복 적용.

## Phase 1 — 3라운드 반복 검색

### 1라운드 — 후보 개념 탐색
- "software requirements specification SRS quality characteristics completeness consistency verifiability IEEE 830" 검색 → IEEE 830 기준 좋은 요구사항명세서(SRS)는 정확성(correct)·명확성(unambiguous)·완전성(complete)·일관성(consistent)·중요도별 순위화·검증가능성(verifiable)·수정용이성(modifiable)·추적가능성(traceable) 등의 품질 특성을 가져야 한다는 표준 확인
- "prototyping requirements elicitation technique advantages disadvantages software engineering" 검색 → 프로토타이핑은 요구사항 도출(사용자가 직접 평가·피드백)에 효과적이지만, 비용이 많이 들고 사용자가 프로토타입 경험 후 변경에 저항하는 경향이 있다는 장단점 확인

### 2라운드 — 파생 심화 검색
- "요구사항 명세서 품질 특성 완전성 일관성 명확성 검증가능성" 검색 → 한국어 자료로 명확성(모호하지 않음)·완전성(기능/비기능 요구사항 누락 없음)·일관성(상충 요구사항 없음)·검증가능성(객관적으로 검증 가능)이라는 4대 핵심 품질 특성 확인, 이 특성들이 부족하면 재작업 비용이 커진다는 실무적 이유 확인
- "프로토타이핑 기법 장점 단점 요구사항 도출 비용 사용자 저항" 검색 → 한국어 자료로 프로토타이핑이 요구사항 도출·개발 타당성 확보·개발자-사용자 의사소통에 효과적이라는 장점, 사용자가 초기 모델을 반복 평가하며 요구사항을 구체화한다는 절차 확인

### 3라운드 — 반영 후보 구체화 검증
- "프로토타이핑 모델 단점 한계 비용 증가 문서화 부족" 검색 → 프로토타이핑의 구체적 단점(비경제적일 수 있는 비용, 문서화 축소·생략으로 인한 유지보수 어려움, **프로토타입 결과물을 최종 완제품으로 오인**하는 위험, 과도한 기대심리 유발) 확정 — "프로토타입을 완제품으로 오인"은 명확한 오답 포인트 소재로 확정

## Phase 2 — 자체 검토

- 요구사항 명세서 품질 특성과 프로토타이핑은 기존 두 페이지(도메인 특화 요구사항 내용)와는 별개의, 일반 소프트웨어 요구사항공학 방법론 축이라 신규 페이지로 분리해 반영
- IEEE 830의 8개 특성을 모두 나열하기보다 문제은행이 실제로 묻는 핵심 4개(명확성·완전성·일관성·검증가능성) 중심으로 반영하고, 나머지(수정용이성·추적가능성 등)는 간단히 언급만 함(§2 원칙)
- 프로토타이핑은 폭포수 모델과의 비교나 프로토타입 유형(throwaway/evolutionary) 세부 분류까지는 넣지 않고, 핵심 장단점과 완제품 오인 오답 포인트까지만 반영
- 두 개념 모두 일반 소프트웨어공학 방법론으로 범용성이 높아 각각 Box 용어로 생성

## Phase 3 — 결론

신규 페이지 1개(4. 요구사항 명세서 품질과 프로토타이핑) 작성, 개요 페이지의 구성·핵심정리·관련노트 갱신. 신규 Box 용어 2건: `요구사항 명세서의 품질 특성`, `프로토타이핑(Prototyping)`.

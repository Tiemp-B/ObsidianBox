# 조사 - NLP파이프라인·제스처인식알고리즘고려사항

**대상 세세항목**: 과목4 지능소프트웨어 / 2. 인지지능 소프트웨어 개발 / 2. HRI 소프트웨어 개발 / 2. HRI 인터페이스

**문제은행 확인**: 전용 1문항("HRI 인터페이스의 종류가 아닌 것은?")은 기존 페이지의 "HRI 인터페이스의 종류" 표(음성·제스처·햅틱·시각)로 이미 커버됨. 형제 세세항목("1. HRI 소프트웨어 설계") 재작업 시 이월했던 3문항 중, 햅틱 인터페이스 특징은 기존 페이지에 이미 존재 확인. 남은 2건을 이번 배치에서 처리:

| 문항 | 처리 |
|---|---|
| 음성 인터페이스 NLP 파이프라인 순서 | **공백** — 과목4/2 배치②("2. 인지지능 알고리즘 설계")에서 범위 밖으로 이월했던 "형태소 분석기의 주요 기능" 문항과 직결. 이번 배치에서 함께 보강 |
| 제스처 인식 알고리즘 설계 시 가장 중요한 고려사항 | **공백** — 형제 세세항목에서 이미 다룬 "제스처 인식 처리 단계(4단계 파이프라인)"와는 다른 각도(알고리즘 선택 기준)이므로 중복 아님 |

## Phase 1 — 3라운드 반복 검색

### 1라운드 (한국어 우선 — NLP는 한국어 형태소 특성이 중요)
검색어: "자연어처리 파이프라인 순서 형태소분석 구문분석 의미분석 음성인식 대화시스템", "gesture recognition algorithm design considerations real-time accuracy computational cost robot"

- NLP 파이프라인 4단계: **형태소분석(최소 의미 단위 분리) → 구문분석(문장 구조·위계관계) → 의미분석(문장의 뜻 파악) → 담화분석(전체 문맥 연결)**.
- 형태소분석기의 기능은 어절 분리 + 품사 태깅(체언·용언·조사·어미 등 분류)임을 확인.
- 제스처 인식 알고리즘 설계에서는 **정확도와 연산량(실시간성)의 트레이드오프**가 핵심 고려사항 — 복잡한 3D CNN·주파수 변환은 정확도는 높지만 연산 비용이 크고, 경량 모델(MobileNet 등)은 정확도를 다소 희생하되 임베디드 환경에서 실시간 처리가 가능.

### 2라운드 (한국어, 재확인 및 구체 수치)
검색어: "제스처 인식 알고리즘 설계 실시간성 정확도 연산량 트레이드오프", "형태소분석기 주요 기능 어절 분리 품사 태깅"

- 국내 논문에서도 CNN·RNN 등 알고리즘을 실시간 분류에 적용하며, 채널 수(정보량)를 늘릴수록 정확도가 개선(단일채널 94.5% → 3채널 99.88%)되지만 그만큼 연산량이 늘어나는 트레이드오프가 재확인됨.
- 형태소분석기 기능(어절 분리·품사 태깅)이 한국어 자료로 재확인됨. 예: "가방에 들어가신다" → 가방/NNG + 에/JKM + 들어가/VV + 시/EPH + ㄴ다/EFN.

### 3라운드 (심화 — 음성 인터페이스 전체 파이프라인에서의 위치 확정)
검색어: "음성 인터페이스 파이프라인 STT 형태소분석 의도파악 대화관리 TTS 순서"

- 음성 인터페이스는 큰 틀에서 **음성인식(STT) → 자연어처리(형태소분석 포함 NLP 4단계) → 의도파악/대화관리 → 음성합성(TTS)** 순으로 구성됨을 확인 — NLP 4단계가 STT와 TTS 사이의 중간 처리 블록임을 명확히 함.

## Phase 2 — 자체 검토

- NLP 4단계(형태소→구문→의미→담화)는 국내 표준 교재·자료에서 일관되게 확인되어 신뢰도 높음.
- 제스처 인식 "처리 단계"(형제 세세항목에서 이미 다룸: 데이터수집→전처리→특징추출→분류)와 이번 "알고리즘 설계 고려사항"(정확도-연산량 트레이드오프, 경량모델 vs 고정확도모델 선택)은 **파이프라인 구조 vs 설계 시 트레이드오프 판단**이라는 다른 층위의 내용이므로 중복이 아님 — 페이지에도 이 구분을 명시.

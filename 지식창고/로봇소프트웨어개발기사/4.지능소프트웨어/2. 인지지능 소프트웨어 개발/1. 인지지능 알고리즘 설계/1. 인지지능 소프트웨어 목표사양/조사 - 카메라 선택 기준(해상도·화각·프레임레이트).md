# 조사 - 카메라 선택 기준(해상도·화각·프레임레이트)

**대상 세세항목**: 과목4 지능소프트웨어 / 2. 인지지능 소프트웨어 개발 / 1. 인지지능 알고리즘 설계 / 1. 인지지능 소프트웨어 목표사양

**문제은행 확인**: 이 세세항목 전용 1문항("인지지능 소프트웨어의 목표사양에 포함되어야 할 항목이 아닌 것은?")은 기존 페이지에서 제조단가가 목표사양에 해당하지 않는다는 설명으로 이미 커버됨. 정밀도/재현율/F1은 형제 세세항목(2. 인지지능 알고리즘 설계/3. 이미지 인식 성능 지표와 상황 인식)에 이미 존재해 중복 금지.

**공백 발견**: 기존 페이지("2. 목표사양 선정 절차와 항목")는 "인지 대상별 카메라·알고리즘 선택" 아side에서 SIFT/SURF 알고리즘 선택 기준만 다루고, 정작 **카메라 자체의 스펙 선택 기준(해상도·화각·프레임레이트)** 이 빠져 있음. 목표사양 수립 단계에서 카메라 스펙을 어떻게 정하는지는 인지지능 소프트웨어 목표사양의 핵심 내용이므로 보완 대상.

## Phase 1 — 3라운드 반복 검색

### 1라운드 (영문, 개념 확인)
검색어: "robot vision camera selection criteria resolution field of view frame rate task requirements", "machine vision camera spec resolution vs frame rate tradeoff robot object detection speed accuracy"

- 해상도 규칙: 인식하려는 최소 특징(feature) 크기 대비 최소 2픽셀 이상 확보가 기본 공식.
- 프레임레이트: 라인 속도에 따라 통상 30~200 FPS 범위에서 결정.
- 화각(FOV): 대상 물체의 실제 크기보다 여유(약 2A×2B 마진)를 두고 커버해야 함.
- 해상도-프레임레이트 상충 관계: 인터페이스 대역폭 한계로 고해상도일수록 달성 가능한 최대 프레임레이트가 낮아짐 (예: 1.6MP 카메라는 USB3 Vision에서 200fps 가능하지만, 20MP 센서는 최대 프레임레이트가 크게 낮아짐).
- 다운샘플링 실험: 1000×1000px → 200×200px로 낮춰도 위치 추정 오차는 약 0.2px만 증가하는 반면 연산량은 16배 절감 — "요구 성능을 만족하는 가장 낮은 해상도를 쓴다"는 설계 원칙의 근거.

### 2라운드 (한국어, 재확인)
검색어: "로봇 비전 카메라 선택 기준 해상도 화각 프레임레이트"

- 해상도가 카메라 선택 시 가장 먼저 고려할 요소이며, **화각(FOV) 크기와 식별해야 할 최소 특징 크기**를 기준으로 산출한다는 점을 한국어 자료에서도 동일하게 확인.
- 화각은 fps·해상도뿐 아니라 "센서 크기 + 렌즈 조합"으로 결정되며, 센서가 작을수록 같은 렌즈에서도 화각이 좁아지고 배율이 커짐.
- 데이터 대역폭 때문에 해상도와 프레임레이트 사이에 상충 관계가 발생한다는 점을 한국어 산업용 비전 카메라 가이드에서도 동일하게 명시 — 1라운드 영문 자료와 일치.
- 최적 카메라는 "디테일·커버리지·속도·데이터 처리 간 균형"을 맞추는 카메라라는 결론.

### 3라운드 (심화 — 해상도 산출 공식 구체화)
검색어: "machine vision pixel per feature rule of thumb resolution calculation industrial camera"

- 1라운드의 "최소 2픽셀" 공식을 더 구체화: 전통적 검사는 특징당 3~5픽셀, AI 기반 인식은 5~10픽셀 이상 권장. OCR 판독은 최소 10픽셀.
- 공식: 센서 해상도 = (FOV / 최소 특징 크기) × 2 (배율 2는 안정적 검출을 위한 여유분).
- 공차 기반 규칙: 픽셀 크기가 측정 공차의 약 1/10 이하여야 정밀 측정 가능.
- 설계 원칙 재확인: "요구를 만족하는 가장 낮은 해상도를 사용한다" — 1라운드 다운샘플링 실험 결과와 일치.

## Phase 2 — 자체 검토

- 3라운드 모두 동일한 핵심 원칙(해상도는 최소 특징 크기 기준 산출, 화각은 대상보다 여유 있게, 해상도-프레임레이트는 상충 관계, 필요 이상 고해상도는 비효율)에 수렴 — 신뢰도 높음.
- "몇 픽셀이 필요한가"의 구체 수치(2배 vs 3~5배 vs 5~10배)는 출처·용도(전통 검사 vs AI vs OCR)에 따라 다르므로, 본문에는 하나의 확정 수치로 단정하지 않고 **"최소 특징 크기 대비 일정 배수의 픽셀 확보가 원칙이며 용도에 따라 배수가 커진다"**는 형태로 서술.
- 기존 페이지의 SIFT/SURF 알고리즘 선택 서술과 자연스럽게 이어지도록, "카메라 스펙 선택 → 알고리즘 선택"의 순서로 아side를 확장.

## Phase 3 — 결론

- 기존 "인지 대상별 카메라·알고리즘 선택" 아side에 **카메라 스펙(해상도·화각·프레임레이트) 선택 기준과 해상도-프레임레이트 상충 관계**를 추가한다.
- 개념 비중이 있어 Box 용어 "카메라 선택 기준(해상도·화각·프레임레이트)"을 신설한다.

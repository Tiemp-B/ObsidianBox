# Summary

산업 현장에서 로봇 제어기와 모터 드라이버·센서·상위 PC를 연결하는 통신은 일반 이더넷/Wi-Fi가 아니라, 정해진 시간 안에 반드시 데이터가 도착함을 보장하는 **[[필드버스(Fieldbus)|필드버스]]** 프로토콜을 사용하는 경우가 많다. [[1. 로봇제어기]] 개요 페이지에서 필드버스의 존재만 간단히 언급했다면, 이 페이지에서는 대표 프로토콜인 **[[CAN(Controller Area Network)|CAN]]**의 동작 원리를 중심으로 [[EtherCAT]], [[Modbus]], [[Profinet]]과 비교한다.

# Notes

<aside>필드버스가 필요한 이유</aside>

일반 이더넷/TCP-IP는 트래픽 상황에 따라 지연시간이 들쭉날쭉해 **결정적(deterministic)이지 않다**. 반면 로봇 제어기의 서보 루프는 매 주기(수백 μs ~ 수 ms)마다 반드시 데이터를 주고받아야 하므로, **지연시간이 예측 가능한 통신**이 필요하다. 이를 만족하도록 설계된 산업용 통신 규격이 필드버스다.

<aside>CAN(Controller Area Network) 심화</aside>

- **멀티마스터(Multi-master) 구조**: 특정 노드만 통신을 주도하는 것이 아니라, **버스에 연결된 모든 노드가 메시지를 전송**할 수 있다.
- **충돌 중재(Arbitration)**: 여러 노드가 동시에 송신을 시도해 충돌이 발생하면, **메시지 ID(우선순위)가 낮은 값을 가진(=우선순위가 높은) 메시지가 먼저 전송**되고 나머지 노드는 자동으로 송신을 양보한다. 이 과정에서 데이터가 파괴되지 않는 무손실 중재 방식을 사용한다.
- **최대 전송 속도**: 통상 최대 1Mbps 수준(단거리 기준)으로, 다른 필드버스에 비해 상대적으로 느린 편이지만 회로가 단순하고 노이즈에 강해 산업 현장에서 널리 쓰인다.
- 단일 마스터 구조가 아니라는 점, 우선순위 방식이 라운드로빈이나 토큰 방식이 아니라 **메시지 ID 기반 중재**라는 점이 핵심 포인트다.

<aside>주요 필드버스 비교</aside>

| 프로토콜 | 구조 | 최대 속도 | 결정성 | 특징 |
|---|---|---|---|---|
| [[CAN(Controller Area Network)\|CAN]] | 멀티마스터, 버스형 | ~1Mbps | 중간(우선순위 중재) | 단순·저가·강인함, 자동차/로봇 관절 통신에 널리 사용 |
| [[EtherCAT]] | 마스터-슬레이브, 링/데이지체인 | ~100Mbps(이더넷 기반) | 매우 높음(수 μs 단위 동기) | 프레임이 슬레이브를 통과하며 실시간으로 데이터를 읽고 씀([[PDO(Process Data Object)\|PDO]] 사용), 다축 서보 제어에 널리 사용 |
| [[Modbus]] | 마스터-슬레이브, 폴링 방식 | ~115kbps(RTU 기준) | 낮음~중간 | 구조가 매우 단순해 계측·감시(SCADA)용으로 널리 사용, 실시간 서보 제어에는 부적합 |
| [[Profinet]] | 마스터-슬레이브, 이더넷 기반 | ~100Mbps | 높음 | 지멘스 계열 산업 자동화에서 널리 사용, EtherCAT과 유사하게 실시간 클래스 지원 |

**정리하면**: CAN은 저속·저비용·멀티마스터, EtherCAT/Profinet은 고속·고정밀 실시간 제어(다축 서보), Modbus는 저속·단순 계측/감시용으로 역할이 나뉜다. 로봇 제어기 내부의 관절 간 통신에는 CAN이나 EtherCAT이, 상위 SCADA/모니터링 연동에는 Modbus나 TCP/IP 계열이 흔히 사용된다.

---

<aside>핵심 정리</aside>

- CAN = **멀티마스터** + **메시지 ID 기반 우선순위 중재**, 최대 약 1Mbps
- EtherCAT/Profinet = 이더넷 기반, 고속·고정밀 실시간(다축 서보 제어용)
- Modbus = 단순·저속, 계측/감시(SCADA)용, 실시간 서보 제어엔 부적합

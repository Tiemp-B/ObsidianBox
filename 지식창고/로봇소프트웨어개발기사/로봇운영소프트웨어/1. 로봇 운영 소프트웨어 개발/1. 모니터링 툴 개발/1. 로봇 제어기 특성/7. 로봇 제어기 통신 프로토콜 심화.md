# Summary

산업 현장에서 로봇 제어기와 모터 드라이버·센서·상위 PC를 연결하는 통신은 일반 이더넷/Wi-Fi가 아니라, 정해진 시간 안에 반드시 데이터가 도착함을 보장하는 **[[필드버스(Fieldbus)|필드버스]]** 프로토콜을 사용하는 경우가 많다. [[1. 로봇제어기]] 개요 페이지에서 필드버스의 존재만 간단히 언급했다면, 이 페이지에서는 대표 프로토콜인 **[[CAN(Controller Area Network)|CAN]]**의 동작 원리를 중심으로 다양한 필드버스·시리얼·무선 통신 프로토콜을 비교하고, 상위 감시 시스템인 **[[SCADA]]**까지 정리한다.

# Notes

<aside>필드버스가 필요한 이유</aside>

일반 이더넷/TCP-IP는 트래픽 상황에 따라 지연시간이 들쭉날쭉해 **결정적(deterministic)이지 않다**. 반면 로봇 제어기의 서보 루프는 매 주기(수백 μs ~ 수 ms)마다 반드시 데이터를 주고받아야 하므로, **지연시간이 예측 가능한 통신**이 필요하다. 이를 만족하도록 설계된 산업용 통신 규격이 필드버스다.

<aside>CAN(Controller Area Network) 심화</aside>

- **멀티마스터(Multi-master) 구조**: 특정 노드만 통신을 주도하는 것이 아니라, **버스에 연결된 모든 노드가 메시지를 전송**할 수 있다.
- **충돌 중재(Arbitration)**: 여러 노드가 동시에 송신을 시도해 충돌이 발생하면, **메시지 ID(우선순위)가 낮은 값을 가진(=우선순위가 높은) 메시지가 먼저 전송**되고 나머지 노드는 자동으로 송신을 양보한다. 이 과정에서 데이터가 파괴되지 않는 무손실 중재 방식을 사용한다.
- **최대 전송 속도**: 통상 최대 1Mbps 수준(단거리 기준)으로, 다른 필드버스에 비해 상대적으로 느린 편이지만 회로가 단순하고 노이즈에 강해 산업 현장에서 널리 쓰인다.
- 단일 마스터 구조가 아니라는 점, 우선순위 방식이 라운드로빈이나 토큰 방식이 아니라 **메시지 ID 기반 중재**라는 점이 핵심 포인트다.

<aside>주요 필드버스/산업 이더넷 비교</aside>

| 프로토콜 | 구조 | 최대 속도 | 결정성 | 특징 |
|---|---|---|---|---|
| [[CAN(Controller Area Network)\|CAN]] | 멀티마스터, 버스형 | ~1Mbps | 중간(우선순위 중재) | 단순·저가·강인함, 자동차/로봇 관절 통신에 널리 사용 |
| [[EtherCAT]] | 마스터-슬레이브, 링/데이지체인 | ~100Mbps(이더넷 기반) | 매우 높음(수 μs 단위 동기) | 프레임이 슬레이브를 통과하며 실시간으로 데이터를 읽고 씀([[PDO(Process Data Object)\|PDO]] 사용), 다축 서보 제어에 널리 사용 |
| [[Modbus]] | 마스터-슬레이브, 폴링 방식 | ~115kbps(RTU 기준) | 낮음~중간 | 구조가 매우 단순해 계측·감시([[SCADA]])용으로 널리 사용, 실시간 서보 제어에는 부적합 |
| [[Profinet]] | 마스터-슬레이브, 이더넷 기반 | ~100Mbps | 높음 | 지멘스 계열 산업 자동화에서 널리 사용, EtherCAT과 유사하게 실시간 클래스 지원 |
| [[PROFIBUS]] | 마스터-슬레이브, 토큰패싱(멀티마스터간) | ~12Mbps | 중간~높음 | Profinet의 전신, 여전히 기존 설비에서 널리 사용되는 시리얼 기반 필드버스 |
| [[CANopen]] | CAN 기반 상위 프로토콜 | CAN과 동일(~1Mbps) | 중간 | CAN 위에 표준화된 장치 프로파일(PDO/SDO 등)을 얹어 장비 간 상호운용성을 높임 |
| [[DeviceNet]] | CAN 기반, 마스터-슬레이브/피어투피어 | ~500kbps | 중간 | CAN을 물리계층으로 사용하는 산업용 프로토콜, 주로 로크웰(Allen-Bradley) 계열 |
| [[SERCOS]] | 링형, 광섬유/이더넷 기반 | ~100Mbps 이상 | 매우 높음 | 서보 드라이브 동기 제어 전용으로 설계된 실시간 프로토콜(SERCOS III는 이더넷 기반) |
| [[POWERLINK]] | 마스터-슬레이브, 이더넷 기반 | ~100Mbps | 매우 높음 | 오픈소스 실시간 이더넷 프로토콜, 시분할(Time-slicing) 방식으로 결정성 확보 |
| [[CC-Link]] | 마스터-슬레이브 | ~10Mbps | 높음 | 미쓰비시 계열 산업 자동화에서 주로 사용 |
| [[ControlNet]] | 생산자-소비자(Producer-Consumer) | ~5Mbps | 높음 | 로크웰 계열, 실시간 제어와 정보 전송을 함께 처리 |
| [[AS-Interface(ASi)\|AS-Interface (ASi)]] | 마스터-슬레이브, 2선식 | ~167kbps | 중간 | 리밋 스위치·근접 센서 등 단순 이진(on/off) 신호를 저비용으로 배선하는 하위 레벨 버스 |
| [[IO-Link]] | 점대점(Point-to-Point) | ~230kbps | 중간 | 필드버스라기보다 "스마트 센서/액추에이터"와의 표준 점대점 통신, 상위 필드버스에 게이트웨이로 연결 |

**정리하면**: CAN·CANopen·DeviceNet은 저속·저비용·멀티마스터 계열, EtherCAT·Profinet·SERCOS·POWERLINK는 이더넷 기반 고속·고정밀 실시간 제어(다축 서보) 계열, Modbus·PROFIBUS·CC-Link·ControlNet은 각 산업 진영(지멘스/로크웰/미쓰비시 등)에서 널리 쓰이는 범용 계측·제어용, AS-Interface·IO-Link는 센서/액추에이터 단의 최하위 배선을 단순화하는 용도로 역할이 나뉜다.

<aside>시리얼 통신 프로토콜</aside>

필드버스보다 더 기본적인, 근거리·점대점 또는 짧은 버스 구간에서 쓰이는 시리얼 통신들이다. 로봇 제어기 내부 보드 간, 혹은 센서 모듈과의 통신에 흔히 쓰인다.

| 프로토콜 | 방식 | 특징 |
|---|---|---|
| [[RS-232]] | 조정신호 포함 시리얼, 1:1 | 구형 표준, 짧은 거리(~15m), 단일 장치 연결용 |
| [[RS-422]] | 차동 신호, 1:N(단방향) | RS-232보다 장거리·고속, 노이즈에 강함 |
| [[RS-485]] | 차동 신호, 멀티드롭 | 장거리(~1.2km), 다수 장치를 하나의 버스에 연결 가능, Modbus RTU의 물리 계층으로도 사용 |
| [[I2C]] | 2선식(SDA/SCL), 동기식 | 보드 내부의 단거리 저속 센서 통신에 널리 사용, 여러 슬레이브를 주소로 구분 |
| [[SPI]] | 4선식, 동기식, 전이중 | I2C보다 빠르지만 배선이 더 필요, 짧은 거리의 고속 센서/메모리 통신에 사용 |
| [[USB]] | 직렬 버스, 플러그 앤 플레이 | PC와의 연결(펌웨어 업로드, 디버깅, 로봇 티칭 펜던트 등)에 흔히 사용 |

<aside>무선 통신 프로토콜</aside>

이동로봇이나 원격 모니터링처럼 배선이 어려운 경우 사용하는 무선 통신이다. 실시간 서보 제어처럼 결정성이 중요한 구간에는 잘 쓰이지 않고, 주로 상위 모니터링·데이터 수집·원격 조작에 사용된다.

| 프로토콜 | 특징 |
|---|---|
| [[Wi-Fi]] | 고속 대역폭, 이동로봇의 영상 스트리밍·원격 모니터링에 사용, 지연시간이 가변적 |
| [[Bluetooth]] | 근거리 저전력, 소형 로봇·주변기기 페어링에 사용 |
| [[Zigbee]] | 초저전력 메시(Mesh) 네트워크, 다수의 센서 노드를 낮은 전력으로 연결(스마트팩토리 센서망 등) |
| [[LoRaWAN]] | 초저전력 장거리(수 km), 저속 데이터를 넓은 범위에서 수집하는 IoT 센서망에 사용 |

<aside>상위 감시 시스템 — SCADA</aside>

**[[SCADA]]**(Supervisory Control And Data Acquisition)는 필드버스로 수집한 현장 데이터를 상위 레벨에서 통합적으로 감시·제어하는 소프트웨어 계층이다.

- 필드버스/PLC/로봇 제어기로부터 데이터를 모아 **HMI 화면**에 시각화하고, 이상 상황 시 알람을 발생시킨다.
- Modbus·PROFIBUS처럼 상대적으로 느리지만 표준화되고 폭넓게 지원되는 프로토콜이 SCADA 연동에 자주 쓰이는데, 이는 SCADA 자체가 서보 루프처럼 초고속 실시간성을 요구하지 않고 초 단위 주기의 감시·기록이 목적이기 때문이다.
- 로봇 제어기 관점에서는, 관절 서보 통신(CAN/EtherCAT 등)과 상위 SCADA 연동 통신(Modbus/TCP-IP 등)이 **서로 다른 계층·다른 프로토콜**로 분리되는 것이 일반적이다.

<aside>핵심 정리</aside>

- CAN = **멀티마스터** + **메시지 ID 기반 우선순위 중재**, 최대 약 1Mbps
- EtherCAT/Profinet/SERCOS/POWERLINK = 이더넷 기반, 고속·고정밀 실시간(다축 서보 제어용)
- Modbus/PROFIBUS/CC-Link/ControlNet = 범용 계측·제어용, SCADA 연동에 흔히 사용
- AS-Interface/IO-Link = 센서·액추에이터 최하위 배선 단순화용
- 시리얼(RS-232/422/485, I2C, SPI, USB)은 근거리·보드 내부 통신에 사용
- 무선(Wi-Fi/Bluetooth/Zigbee/LoRaWAN)은 결정성보다 이동성·저전력·저비용이 중요한 구간에 사용
- **SCADA**는 필드버스 데이터를 모아 감시·기록하는 상위 계층 — 서보 통신과는 별개의 느린 주기로 동작

# Summary

[[RTOS]]의 본질은 "빠름"이 아니라 **정해진 시간(데드라인) 안에 반드시 응답을 완료하는 결정성(Determinism)** 이다. 로봇 제어기의 OS 계층은 이 결정성을 보장하기 위해 우선순위 기반 스케줄링과 인터럽트 우선순위 처리 체계를 사용하며, 대표적인 정적 스케줄링 기법이 **Rate Monotonic Scheduling(RMS)** 이다. 시험에서는 "RTOS = 처리량이 높다/UI가 화려하다"는 오답 함정이 반복 출제되므로, RTOS의 핵심 가치가 **예측 가능성**이라는 점을 축으로 이해해야 한다.

# Notes

<aside>RTOS란 무엇인가</aside>

RTOS(Real-Time Operating System)는 태스크가 **정해진 시간 제약(데드라인) 내에 반드시 실행을 완료**하도록 보장하는 운영체제이다.

- 일반 OS(Windows/일반 Linux)의 목표: **평균 처리량(Throughput) 극대화**
- RTOS의 목표: **최악의 경우에도 데드라인을 지키는 결정적 응답시간(Deterministic Response Time)**

즉 RTOS가 반드시 "빠른" 것은 아니며, "느리더라도 항상 같은 시간 안에 끝난다"는 **예측 가능성**이 핵심이다.

<aside>RTOS의 핵심 특성 (기출 포인트)</aside>

| 특성 | 설명 | 시험 함정 |
|---|---|---|
| 결정적 응답시간 | 최악의 경우에도 정해진 시간 내 응답 보장 | — |
| 우선순위 기반 스케줄링 | 태스크마다 우선순위를 부여해 스케줄링 | — |
| 인터럽트 지연 최소화 | 인터럽트 발생 시 빠르게 처리 루틴 진입 | — |
| ~~높은 처리량~~ | RTOS의 목표가 아님 (일반 OS의 목표) | "RTOS 특징이 아닌 것은?" 문제의 정답으로 자주 등장 |
| ~~화려한 사용자 인터페이스~~ | 로봇 제어기 OS는 기능적·효율적 UI를 지향 | 동일하게 오답 함정 |

> 기출: *"로봇 제어기에서 사용되는 운영체제의 특징으로 옳지 않은 것은?"* → 정답: **④ 사용자 인터페이스가 화려하다**
> 기출: *"로봇 소프트웨어에서 실시간 운영체제(RTOS)의 주요 특징이 아닌 것은?"* → 정답: **③ 높은 처리량**

<aside>실시간 처리(Real-time Processing)의 정의</aside>

실시간 처리는 **"빠른 처리"가 아니라 "정해진 데드라인 내 작업 완료"** 를 의미한다.

- 로봇 제어에서 센서 데이터 처리·모터 제어가 정확한 시간 내에 이루어져야 안전하고 정확한 동작이 가능
- 데드라인을 못 지키면, 처리 결과가 아무리 정확해도 실시간 시스템 관점에서는 **실패**로 간주

> 기출: *"실시간 처리(Real-time Processing)에 대한 설명으로 옳은 것은?"* → 정답: **정해진 시간 내에 작업을 완료해야 한다**

<aside>실시간 제약 조건 3요소</aside>

로봇 제어 소프트웨어에서 다루는 실시간 제약 조건은 다음 3가지로 요약된다.

- **데드라인(Deadline)** : 태스크가 완료되어야 하는 시점
- **주기성(Periodicity)** : 태스크가 반복 실행되는 주기
- **우선순위(Priority)** : 여러 태스크 중 무엇을 먼저 실행할지 결정하는 기준

- **코드 복잡도(Code Complexity)** 는 소프트웨어 품질 지표(유지보수성 등)이지 실시간 제약 조건이 아니다 — 혼동 주의

> 기출: *"로봇 소프트웨어에서 실시간 제약 조건이 아닌 것은?"* → 정답: **④ 코드 복잡도**

<aside>Rate Monotonic Scheduling (RMS)</aside>

RMS는 대표적인 **고정 우선순위(Fixed-Priority) 정적 스케줄링** 알고리즘이다.

- 규칙: **주기(Period)가 짧은 태스크일수록 높은 우선순위**를 부여
- 전제: 각 태스크는 독립적이고, 주기마다 고정된 실행시간을 가짐(주기적 태스크 모델)
- 대비 개념: **EDF(Earliest Deadline First)** — 마감이 가장 임박한 태스크에 동적으로 우선순위를 부여하는 동적 스케줄링(RMS보다 이론적 CPU 활용률이 높음)

> 기출: *"RTOS의 스케줄링 방식 중 Rate Monotonic Scheduling의 특징은?"* → 정답: **주기가 짧은 태스크에 높은 우선순위를 부여한다**

<aside>인터럽트 우선순위 결정 방식</aside>

인터럽트는 긴급성(우선순위)에 따라 처리 순서가 결정되며, 대표적인 방식은 다음과 같다.

- **고정 우선순위 방식** : 인터럽트 소스마다 미리 정해진 우선순위 사용
- **동적 우선순위 방식** : 상황에 따라 우선순위가 변경(우선순위 역전 방지 등)
- **중첩 인터럽트(Nested Interrupt) 방식** : 처리 중인 인터럽트보다 우선순위가 높은 인터럽트가 발생하면 현재 처리를 중단하고 새 인터럽트를 먼저 처리

- **라운드 로빈(Round Robin)** 은 **프로세스/태스크 스케줄링 기법**이지 인터럽트 우선순위 결정 방식이 아니다 — 혼동 주의

> 기출: *"인터럽트(Interrupt) 처리의 우선순위를 결정하는 방식으로 옳지 않은 것은?"* → 정답: **③ 라운드 로빈 방식**

---

<aside>핵심 정리</aside>

- RTOS의 본질은 처리 속도가 아니라 **결정적 응답시간(예측 가능성)**
- 실시간 처리 = **데드라인 준수**, 처리 속도와는 별개 개념
- 실시간 제약 조건 = **데드라인·주기성·우선순위** (코드 복잡도는 해당 없음)
- **RMS**: 주기가 짧을수록 우선순위 高 (고정 우선순위 방식)
- 인터럽트 우선순위 = 고정/동적/중첩 방식 (라운드 로빈은 아님)

# Summary

로봇 제어기의 저수준 제어 계층은 여러 태스크(서보 루프, 센서 읽기, 통신 처리 등)가 공유 자원(레지스터, 버퍼, 공유 메모리)에 동시에 접근한다. 이때 동기화 없이 접근하면 **경쟁 조건(Race Condition)**이 발생해 데이터가 손상될 수 있다. [[뮤텍스(Mutex)|뮤텍스]]와 [[세마포어(Semaphore)|세마포어]]는 이를 막기 위한 대표적인 동기화 메커니즘이며, 동기화를 잘못 설계하면 오히려 태스크들이 서로를 무한정 기다리는 **[[데드락(Deadlock)|데드락]]**에 빠질 수 있다. 이 페이지는 임계영역·뮤텍스·세마포어의 차이와 데드락의 발생 조건·예방 기법을 다룬다.

# Notes

<aside>왜 동기화가 필요한가</aside>

여러 태스크(스레드/프로세스)가 동시에 같은 자원에 접근하면 접근 순서에 따라 결과가 달라지는 **경쟁 조건(Race Condition)**이 발생한다.

- 예: 두 태스크가 동시에 같은 공유 변수를 증가시키면, 한쪽의 갱신이 유실될 수 있다.
- 해결책: 공유 자원에 접근하는 코드 구간을 **임계영역**으로 지정하고, 한 번에 하나의 태스크만 들어가도록 **잠금(Lock)** 메커니즘을 적용한다.

<aside>임계영역(Critical Section)</aside>

[[임계영역(Critical Section)|임계영역]]은 **공유 자원에 접근하는 코드 부분**으로, 동시에 여러 스레드가 실행하면 데이터 일관성 문제가 발생할 수 있어 **한 번에 하나의 스레드만 실행**되어야 하는 영역이다.

- 임계영역은 "메모리 할당을 위한 코드 영역"이나 "네트워크 통신을 위한 코드 영역"을 뜻하는 것이 아니라, **공유 자원 접근 코드 자체**를 가리키는 개념이다 — 혼동 주의

> 기출: *"멀티스레딩에서 임계영역(Critical Section)에 대한 설명으로 옳은 것은?"* → 정답: **한 번에 하나의 스레드만 실행할 수 있는 코드 영역**

<aside>뮤텍스(Mutex) vs 세마포어(Semaphore)</aside>

| 구분 | 뮤텍스(Mutex) | 세마포어(Semaphore) |
|---|---|---|
| 값의 범위 | 0/1 (이진, Lock/Unlock) | **정수 카운터** — 이진 세마포어뿐 아니라 **카운팅 세마포어**도 존재 |
| 소유권(Ownership) | **있음** — 잠금을 획득한 스레드만 해제 가능 | **없음** — 신호를 받은 임의의 스레드가 해제(signal) 가능 |
| 용도 | 하나의 자원에 대한 **상호배제**(한 번에 1개 스레드만 접근) | 여러 개의 동일 자원에 대한 **동시 접근 개수 제어**(공유 자원 접근 제어) |
| 사용 범위 | 주로 단일 프로세스 내 스레드 간 | 프로세스 간 동기화에도 사용 가능 |

- **세마포어는 소유권 개념이 없어** 신호를 받은 어떤 스레드든 세마포어를 해제할 수 있지만, **뮤텍스는 잠금을 획득한 스레드만이** 잠금을 해제할 수 있다 — 이 소유권 차이가 가장 자주 출제되는 포인트다.
- 세마포어는 **반드시 이진수(0 또는 1)만 갖는 것이 아니라**, 0 이상의 정수값을 갖는 **카운팅 세마포어**도 존재한다.

> 기출: *"멀티스레드 환경에서 동기화를 위한 세마포어와 뮤텍스의 차이점으로 가장 올바른 것은?"* → 정답: **세마포어는 소유권이 없지만, 뮤텍스는 잠금을 획득한 스레드만이 잠금을 해제할 수 있다**
> 기출: *"세마포어(Semaphore)에 대한 설명으로 올바르지 않은 것은?"* → 정답: **반드시 이진수(0 또는 1)의 값만 가질 수 있다** (틀린 설명 — 카운팅 세마포어 존재)
> 기출: *"뮤텍스(Mutex)와 세마포어의 차이점은?"* → 정답: **뮤텍스는 하나, 세마포어는 여러 개의 자원을 관리**
> 기출: *"세마포어(Semaphore)의 주요 기능은?"* → 정답: **공유 자원에 대한 접근 제어**

<aside>데드락(Deadlock)</aside>

[[데드락(Deadlock)|데드락]]은 둘 이상의 태스크가 서로 상대방이 점유한 자원을 무한정 기다리며 아무도 진행하지 못하는 상태다. 아래 **4가지 조건이 모두 성립**해야 발생한다.

- **상호 배제(Mutual Exclusion)**: 자원을 한 번에 한 태스크만 사용 가능
- **점유와 대기(Hold and Wait)**: 자원을 점유한 채로 다른 자원을 추가로 요청
- **비선점(No Preemption)**: 다른 태스크가 점유 중인 자원을 강제로 빼앗을 수 없음
- **순환 대기(Circular Wait)**: 태스크들이 원형으로 서로의 자원을 기다림

> **⚠ 오답 함정**: "자원의 상호 배제를 완전히 제거한다"는 데드락 예방 조건이 **아니다**. 상호 배제 자체를 없애면 동기화의 기본 목적(데이터 일관성 보장)에 위배되어 오히려 데이터가 깨진다. 데드락 예방은 상호배제를 없애는 것이 아니라, **점유와 대기 / 비선점 / 순환대기** 중 하나를 깨뜨리는 방식으로 접근한다.
> **⚠ 오답 함정**: "우선순위 역전([[우선순위 역전(Priority Inversion)|Priority Inversion]])"은 데드락의 발생 조건이 아니다. 이는 데드락과는 별개의 동기화 문제(낮은 우선순위 태스크가 자원을 점유해 높은 우선순위 태스크가 지연되는 현상)다. 해결책은 [[2. 실시간 운영체제와 스케줄링]]의 **우선순위 상속 프로토콜** 참고.

**데드락 예방 기법 — 전부 할당 방식(All-or-Nothing)**
프로세스가 **실행되기 전에 필요한 모든 자원을 한꺼번에 할당**받고 시작하는 방식. 실행 중 추가 자원 요청이 없으므로 "점유와 대기" 조건을 원천적으로 제거해 데드락을 방지한다.

> 기출: *"멀티스레드 환경에서 공유 자원에 대한 동기화를 구현할 때 데드락이 발생하지 않도록 하기 위한 조건으로 올바르지 않은 것은?"* → 정답: **자원의 상호 배제를 완전히 제거한다**
> 기출: *"교착상태(Deadlock)를 예방하기 위한 방법 중, 프로세스가 실행되기 전에 필요한 모든 자원을 할당받고 시작하는 방식은?"* → 정답: **전부 할당 방식**
> 기출: *"멀티스레딩 환경에서 데드락(Deadlock) 발생 조건이 아닌 것은?"* → 정답: **우선순위 역전(Priority Inversion)**

---

<aside>핵심 정리</aside>

- 임계영역 = **공유 자원에 접근하는 코드 구간**, 한 번에 하나의 스레드만 진입 가능
- 뮤텍스 = 소유권 O, 이진(Lock/Unlock) / 세마포어 = 소유권 X, 이진+카운팅 모두 가능
- 데드락 4조건: **상호배제·점유대기·비선점·순환대기** (전부 성립해야 발생)
- 데드락 예방: 상호배제를 없애는 게 아니라 **점유대기·비선점·순환대기 중 하나를 깨는 것** (예: 전부 할당 방식)
- 우선순위 역전은 데드락의 조건이 아니라 **별개의 스케줄링 문제**

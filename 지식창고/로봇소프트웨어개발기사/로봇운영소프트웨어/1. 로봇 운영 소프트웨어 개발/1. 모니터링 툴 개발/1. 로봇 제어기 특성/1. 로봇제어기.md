# Summary

로봇 제어기는 **HW(연산 보드·모터 드라이버·센서 인터페이스·통신 모듈·전원/안전 회로·I/O 보드)** 와 **SW(OS 계층-저수준 제어 계층-미들웨어/통신 계층-응용/관리 계층)** 가 결합된 시스템이다. 모니터링 툴은 저수준 제어 계층에서 생성되는 실시간 상태 데이터를 응용 계층에서 주기적으로 수집·표시하는 역할을 하며, 이를 위해서는 제어기의 구조(중앙집중형/분산형/계층형), 실시간성(RT/Non-RT), 통신 방식(필드버스/네트워크/시리얼)에 따른 특성 차이를 정확히 파악해야 한다.

# Notes

<aside>HW부</aside>

로봇 제어기의 하드웨어는 연산부, 구동부, 감지부, 인터페이스부로 구성된다.

- **연산 보드**: 제어 알고리즘을 실행하는 핵심 프로세서. 산업용 PC(IPC), ARM Cortex-M/A 계열 MCU, FPGA 등
- **모터 드라이버(서보 앰프)**: 상위 명령을 받아 모터에 실제 전류/전압 인가. 서보 드라이버, BLDC 드라이버
- **센서 인터페이스 회로**: 엔코더, 전류센서, IMU 등 아날로그/디지털 신호 처리. ADC, 엔코더 카운터 회로
- **통신 모듈**: 상위 제어기·PC·서버와 데이터 송수신. EtherCAT/CAN 트랜시버, 이더넷 PHY, RS-485
- **전원/안전 회로**: 전력 공급, 과전류/과열 보호, 비상정지(E-stop) 회로. SMPS, 안전 릴레이
- **I/O 보드**: 디지털/아날로그 입출력, 리밋 스위치, 버튼 신호 처리. DI/DO 모듈

구성 방식은 **단일 보드형(All-in-one)** 과 **분리형**(연산부-드라이버부 별도)으로 나뉘며, 이는 모니터링 데이터를 어느 지점(상위 PC 레벨 vs 드라이버 레벨)에서 수집할지에 직접 영향을 준다.

---

<aside>SW부</aside>

로봇 제어기의 소프트웨어는 계층 구조를 가진다.

- **OS 계층**: 실시간성 보장, 태스크 스케줄링. RTOS(VxWorks, QNX, RT-Linux/Xenomai) 또는 일반 Linux/Windows
- **저수준 제어 계층**: 위치/속도/전류 제어 연산(PID, FOC 등)을 수 ms~수백 μs 주기로 실행하는 서보 루프. **하드 리얼타임(hard real-time)** 성격
- **미들웨어/통신 계층**: 상위 응용과 하드웨어 사이 데이터 교환, 프로토콜 스택 처리. ROS/ROS2 노드, EtherCAT 마스터 스택
- **응용/관리 계층**: 모니터링, 로깅, 진단, UI 제공. 모니터링 GUI, 상태 관리 프로그램

저수준 제어 계층에서 생성된 상태 데이터(위치/속도/토크/에러 등)를 응용/관리 계층의 모니터링 프로그램이 주기적으로 읽어오는 구조가 일반적이며, 이 **HW-SW 계층 간 데이터 흐름**을 이해하는 것이 모니터링 툴 설계의 출발점이 된다.

---

<aside>분류 방식</aside>

- **구조에 따른 분류**: 중앙집중형(단일 컨트롤러가 전체 관절 제어, 예: 산업용 매니퓰레이터) / 분산형(관절별 로컬 제어기 + 상위 통합 관리, 예: 협동로봇) / 계층형(상위 작업계획-중위 궤적생성-하위 서보제어, 예: 대부분의 산업·서비스 로봇)
- **실시간성에 따른 분류**: 실시간(RT) 제어기(정해진 주기(예 1ms) 내 반드시 응답, RTOS·EtherCAT 기반) / 비실시간(Non-RT) 제어기(모니터링·UI·로깅 등, 일반 OS)
- **통신 방식에 따른 분류**: 필드버스형(EtherCAT, CAN, Modbus) / 네트워크형(TCP/IP, ROS 토픽·서비스, MQTT) / 시리얼형(RS-232/485, USB)

---

<aside>모니터링 관점 분석</aside>

모니터링 툴 개발 시 반드시 파악해야 하는 항목:

1. **제어 주기(Control Cycle)**: 몇 ms 단위로 데이터를 갱신하는지 → 모니터링 폴링 주기 설계에 영향
2. **상태 데이터 종류**: 관절 각도/속도/토크, 엔코더 값, 전류, 온도, 에러 코드, I/O 상태
3. **통신 프로토콜 및 API**: 벤더별 SDK(UR RTDE, ABB RWS, KUKA KRL, ROS `sensor_msgs/JointState`)
4. **에러/알람 체계**: 에러 코드 규격, Fault vs Warning 구분, 안전 정지(E-stop) 신호
5. **제어 모드**: Position/Velocity/Torque control 등 어떤 모드로 동작 중인지

<aside>실무 사례</aside>

**사례 1 — ROS 기반 제어기 모니터링**
ROS를 사용하는 이동로봇의 경우 제어기는 `/joint_states`, `/diagnostics` 토픽으로 상태를 publish 한다. 모니터링 툴은 이를 subscribe 하여 실시간 시각화한다.

```python
import rospy
from sensor_msgs.msg import JointState

def joint_state_callback(msg):
    for name, pos, vel, eff in zip(msg.name, msg.position, msg.velocity, msg.effort):
        print(f"관절: {name}, 각도: {pos:.3f} rad, 속도: {vel:.3f}, 토크: {eff:.3f}")

rospy.init_node('robot_monitor')
rospy.Subscriber('/joint_states', JointState, joint_state_callback)
rospy.spin()
```

**사례 2 — 산업용 제어기(EtherCAT) 모니터링**
EtherCAT 기반 제어기는 PDO(Process Data Object)를 통해 수 ms 단위로 상태를 갱신한다. 모니터링 프로그램은 마스터(예: SOEM, TwinCAT)에서 PDO 데이터를 읽어 슬레이브(모터 드라이버)별 상태를 파악한다.

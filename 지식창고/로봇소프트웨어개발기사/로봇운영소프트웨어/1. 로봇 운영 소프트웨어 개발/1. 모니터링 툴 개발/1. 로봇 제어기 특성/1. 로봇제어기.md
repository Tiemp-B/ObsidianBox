# Summary

로봇 제어기는 **HW(연산 보드·모터 드라이버·센서 인터페이스·통신 모듈·전원/안전 회로·I/O 보드)** 와 **SW(OS 계층-저수준 제어 계층-미들웨어/통신 계층-응용/관리 계층)** 가 결합된 시스템이다. 모니터링 툴은 저수준 제어 계층에서 생성되는 실시간 상태 데이터를 응용 계층에서 주기적으로 수집·표시하는 역할을 하며, 이를 위해서는 제어기의 구조(중앙집중형/분산형/계층형), 실시간성(RT/Non-RT), 통신 방식(필드버스/네트워크/시리얼)에 따른 특성 차이를 정확히 파악해야 한다. 이 노트는 "로봇 제어기 특성" 세세항목의 **개요(MOC)** 역할을 하며, PID·RTOS 스케줄링·동기화·모션·센서·통신·안전·제어기 유형 비교 등 세부 주제는 하단 [[#관련 세부 노트]]의 개별 페이지에서 다룬다.

# Notes

<aside>HW부</aside>

로봇 제어기의 하드웨어는 연산부, 구동부, 감지부, 인터페이스부로 구성된다.

- **연산 보드** : 제어 알고리즘을 실행하는 핵심 프로세서
    - 산업용 PC(IPC), ARM Cortex-M/A 계열 MCU, FPGA 등

- **모터 드라이버(서보 앰프)** : 상위 명령을 받아 모터에 실제 전류/전압을 인가하여 구동
    - 서보 드라이버, [[BLDC 모터|BLDC]] 드라이버

- **센서 인터페이스 회로** : [[엔코더(Encoder)|엔코더]]·전류센서·IMU 등에서 들어오는 아날로그/디지털 신호를 증폭·변환·필터링하여 연산 보드가 처리 가능한 디지털 값으로 전달하는 역할. 위치·속도·전류 등 제어 루프의 피드백 신호 경로를 담당
    - ADC, 엔코더 카운터 회로
    - ※ 서보 위치 피드백에 실제로 사용되는 대표 센서(엔코더)와 신호 필터링(이동평균 필터 등) 세부 내용은 [[6. 센서 피드백과 신호처리]] 참고

- **통신 모듈** : 상위 제어기·PC·서버와 데이터를 송수신
    - [[EtherCAT]]/[[CAN(Controller Area Network)|CAN]] 트랜시버, 이더넷 PHY, [[RS-485]]

- **전원/안전 회로** : 전력을 공급하고 과전류/과열을 보호하며 비상정지([[E-stop(비상정지)|E-stop]]) 신호를 처리
    - SMPS, 안전 릴레이
    - ※ E-stop 로직, Fault/Warning 체계, 안전 등급은 [[8. 안전 회로와 기능안전]] 참고

- **I/O 보드** : 디지털/아날로그 입출력, 리밋 스위치, 버튼 신호를 처리
    - DI/DO 모듈

구성 방식은 **단일 보드형(All-in-one)** 과 **분리형**(연산부-드라이버부 별도)으로 나뉘며, 이는 모니터링 데이터를 어느 지점(상위 PC 레벨 vs 드라이버 레벨)에서 수집할지에 직접 영향을 준다.

<aside>SW부</aside>

로봇 제어기의 소프트웨어는 계층 구조를 가진다.

- **OS 계층** : 실시간성을 보장하고 태스크 스케줄링을 담당
    - [[RTOS]](VxWorks, QNX, RT-Linux/Xenomai) 또는 일반 Linux/Windows
    - ※ RTOS의 핵심 특성은 "화려한 UI"나 "높은 처리량"이 아니라 **결정적 응답시간(Deterministic Response Time)**이다. [[Rate Monotonic Scheduling]] 등 스케줄링 방식과 인터럽트 우선순위 처리는 [[2. 실시간 운영체제와 스케줄링]] 참고

- **저수준 제어 계층** : 위치/속도/전류 제어 연산([[PID 제어|PID]], [[FOC(Field-Oriented Control)|FOC]] 등)을 수 ms~수백 μs 주기로 실행하는 서보 루프. **하드 리얼타임(hard real-time)** 성격
    - 서보 제어 펌웨어
    - ※ PID 게인(P/I/D)의 개별 역할, 피드백/피드포워드 제어의 차이, [[시정수(Time Constant)|시정수]] 등 응답 지표는 [[4. 제어 응답 특성 지표 전반]] 참고
    - ※ 다중 태스크가 이 계층의 공유 자원(레지스터, 버퍼 등)에 접근할 때 발생하는 경쟁 조건은 [[뮤텍스(Mutex)|뮤텍스]]/[[세마포어(Semaphore)|세마포어]]/[[임계영역(Critical Section)|임계영역]]으로 제어하며, 자세한 내용은 [[3. 동기화 메커니즘(세마포어·뮤텍스·데드락)]] 참고

- **미들웨어/통신 계층** : 상위 응용과 하드웨어 사이의 데이터 교환 및 프로토콜 스택 처리
    - [[ROS(Robot Operating System)|ROS]]/ROS2 노드, EtherCAT 마스터 스택
    - ※ 필드버스별(CAN 등) 세부 프로토콜 특성은 [[7. 로봇 제어기 통신 프로토콜 심화]] 참고

- **응용/관리 계층** : 모니터링, 로깅, 진단, 사용자 인터페이스 제공
    - 모니터링 GUI, 상태 관리 프로그램

저수준 제어 계층에서 생성된 상태 데이터(위치/속도/토크/에러 등)를 응용/관리 계층의 모니터링 프로그램이 주기적으로 읽어오는 구조가 일반적이며, 이 **HW-SW 계층 간 데이터 흐름**을 이해하는 것이 모니터링 툴 설계의 출발점이 된다.

<aside>분류 방식</aside>

**구조에 따른 분류**
- **중앙집중형** : 단일 컨트롤러가 전체 관절을 직접 제어
    - 예: 산업용 매니퓰레이터 컨트롤러
- **분산형** : 관절/모듈별 로컬 제어기 + 상위 통합 관리
    - 예: 협동로봇, 모듈형 로봇팔
- **계층형** : 상위(작업 계획) - 중위(궤적 생성) - 하위(서보 제어)로 계층화
    - 예: 대부분의 산업·서비스 로봇
    - ※ 산업용/협동로봇/이동로봇 제어기의 제어 방식(위치 vs 힘·토크 vs 속도·조향) 비교는 [[9. 제어기 유형별 비교(산업용·협동·이동로봇)]] 참고

**실시간성에 따른 분류**
- **실시간(RT) 제어기** : 정해진 주기(예: 1ms) 내 반드시 연산·응답을 완료하는 것이 핵심이며, 처리 속도 자체가 빠른 것과는 다른 개념이다(정해진 데드라인 준수 여부가 기준)
    - 예: RTOS, EtherCAT 기반 제어기
- **비실시간(Non-RT) 제어기** : 모니터링·UI·로깅 등 시간 제약이 상대적으로 느슨한 영역
    - 예: 일반 OS(Linux/Windows) 기반 응용 프로그램

**통신 방식에 따른 분류**
- **필드버스형** : 산업 현장에서 결정론적 저지연 통신에 사용
    - 예: [[EtherCAT]], [[CAN(Controller Area Network)|CAN]], [[Modbus]]
    - **CAN(Controller Area Network) 핵심 특성**: 특정 노드가 아닌 **모든 노드가 메시지를 보낼 수 있는 멀티마스터(Multi-master) 구조**이며, 여러 노드가 동시에 송신을 시도해 충돌이 발생하면 **메시지 ID(우선순위)가 높은 메시지가 버스 중재(Arbitration)를 통해 우선 전송**된다. 최대 전송 속도는 통상 1Mbps 수준이다. (단일 마스터 구조가 아님에 주의)
- **네트워크형** : 상위 시스템·서버와의 유연한 데이터 교환에 사용
    - 예: [[TCP_IP|TCP/IP]], ROS 토픽/서비스, [[MQTT]]
- **시리얼형** : 근거리 포인트-투-포인트 통신에 사용
    - 예: RS-232/[[RS-485]], USB

<aside>모니터링 관점 분석</aside>

모니터링 툴 개발 시 반드시 파악해야 하는 항목:

1. **제어 주기(Control Cycle)**: 몇 ms 단위로 데이터를 갱신하는지 → 모니터링 폴링 주기 설계에 영향
2. **상태 데이터 종류**: 관절 각도/속도/토크, 엔코더 값, 전류, 온도, 에러 코드, I/O 상태
3. **통신 프로토콜 및 API**: 벤더별 SDK(UR RTDE, ABB RWS, KUKA KRL, ROS `sensor_msgs/JointState`)
4. **에러/알람 체계**: 에러 코드 규격, Fault vs Warning 구분, 안전 정지(E-stop) 신호
5. **제어 모드**: Position/Velocity/Torque control 등 어떤 모드로 동작 중인지

<aside>실무 사례</aside>

**사례 1 — ROS 기반 제어기 모니터링**
ROS를 사용하는 이동로봇의 경우 제어기는 `/joint_states`, `/diagnostics` 토픽으로 상태를 publish 한다. 모니터링 툴은 이를 subscribe 하여 실시간 시각화한다.

```python
import rospy
from sensor_msgs.msg import JointState

def joint_state_callback(msg):
    for name, pos, vel, eff in zip(msg.name, msg.position, msg.velocity, msg.effort):
        print(f"관절: {name}, 각도: {pos:.3f} rad, 속도: {vel:.3f}, 토크: {eff:.3f}")

rospy.init_node('robot_monitor')
rospy.Subscriber('/joint_states', JointState, joint_state_callback)
rospy.spin()
```

**사례 2 — 산업용 제어기(EtherCAT) 모니터링**
EtherCAT 기반 제어기는 [[PDO(Process Data Object)|PDO]](Process Data Object)를 통해 수 ms 단위로 상태를 갱신한다. 모니터링 프로그램은 마스터(예: SOEM, TwinCAT)에서 PDO 데이터를 읽어 슬레이브(모터 드라이버)별 상태를 파악한다.

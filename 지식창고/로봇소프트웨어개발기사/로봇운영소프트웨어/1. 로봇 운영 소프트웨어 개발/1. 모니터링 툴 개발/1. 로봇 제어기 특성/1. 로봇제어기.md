# 로봇 제어기 특성

## Cues (핵심 질문/키워드) | Notes (상세 내용)

| Cues | Notes |
|---|---|
| 로봇 제어기란? | 센서 입력을 받아 목표 동작을 계산하고, 액추에이터에 제어 명령을 출력하는 **하드웨어·소프트웨어 통합 시스템**. 모니터링 툴 개발의 전제로서 제어기의 HW 구성, SW 구조, 통신 특성을 이해해야 함 |
| HW부 - 연산 보드 | 제어 알고리즘을 실행하는 핵심 프로세서. 산업용 PC(IPC), ARM Cortex-M/A 계열 MCU, FPGA 등 |
| HW부 - 모터 드라이버(서보 앰프) | 상위 명령을 받아 모터에 실제 전류/전압 인가. 서보 드라이버, BLDC 드라이버 |
| HW부 - 센서 인터페이스 회로 | 엔코더, 전류센서, IMU 등 아날로그/디지털 신호 처리. ADC, 엔코더 카운터 회로 |
| HW부 - 통신 모듈 | 상위 제어기·PC·서버와 데이터 송수신. EtherCAT/CAN 트랜시버, 이더넷 PHY, RS-485 |
| HW부 - 전원/안전 회로 | 전력 공급, 과전류/과열 보호, 비상정지(E-stop) 회로. SMPS, 안전 릴레이 |
| HW부 - I/O 보드 | 디지털/아날로그 입출력, 리밋 스위치, 버튼 신호 처리. DI/DO 모듈 |
| HW 구성 방식 | **단일 보드형(All-in-one)** vs **분리형**(연산부-드라이버부 별도) → 모니터링 데이터 수집 지점(상위 PC 레벨 vs 드라이버 레벨)에 직접 영향 |
| SW부 - OS 계층 | 실시간성 보장, 태스크 스케줄링. RTOS(VxWorks, QNX, RT-Linux/Xenomai) 또는 일반 Linux/Windows |
| SW부 - 저수준 제어 계층 | 위치/속도/전류 제어 연산(PID, FOC 등)을 수 ms~수백 μs 주기로 실행하는 서보 루프. **하드 리얼타임(hard real-time)** 성격 |
| SW부 - 미들웨어/통신 계층 | 상위 응용과 하드웨어 사이 데이터 교환, 프로토콜 스택 처리. ROS/ROS2 노드, EtherCAT 마스터 스택 |
| SW부 - 응용/관리 계층 | 모니터링, 로깅, 진단, UI 제공. 모니터링 GUI, 상태 관리 프로그램 |
| HW-SW 데이터 흐름 | 저수준 제어 계층에서 생성된 상태 데이터(위치/속도/토크/에러 등)를 응용/관리 계층의 모니터링 프로그램이 주기적으로 읽어옴 → **모니터링 툴 설계의 출발점** |
| 구조에 따른 분류 | 중앙집중형(단일 컨트롤러가 전체 관절 제어, 예: 산업용 매니퓰레이터) / 분산형(관절별 로컬 제어기 + 상위 통합 관리, 예: 협동로봇) / 계층형(상위 작업계획-중위 궤적생성-하위 서보제어, 예: 대부분의 산업·서비스 로봇) |
| 실시간성에 따른 분류 | 실시간(RT) 제어기: 정해진 주기(예 1ms) 내 반드시 응답, RTOS·EtherCAT 기반 / 비실시간(Non-RT) 제어기: 모니터링·UI·로깅 등, 일반 OS |
| 통신 방식에 따른 분류 | 필드버스형(EtherCAT, CAN, Modbus) / 네트워크형(TCP/IP, ROS 토픽·서비스, MQTT) / 시리얼형(RS-232/485, USB) |
| 모니터링 시 파악할 핵심 특성 | ① 제어 주기(폴링 주기 설계에 영향) ② 상태 데이터 종류(각도/속도/토크/엔코더/전류/온도/에러/I·O) ③ 통신 프로토콜·API(UR RTDE, ABB RWS, KUKA KRL, ROS JointState) ④ 에러/알람 체계(Fault vs Warning, E-stop) ⑤ 제어 모드(Position/Velocity/Torque) |
| 실무 사례 1 | ROS 기반 이동로봇: 제어기가 `/joint_states`, `/diagnostics` 토픽으로 상태 publish → 모니터링 툴이 subscribe하여 실시간 시각화 |
| 실무 사례 2 | 산업용 EtherCAT 제어기: PDO(Process Data Object)로 수 ms 단위 상태 갱신 → 마스터(SOEM, TwinCAT)가 슬레이브별 상태 파악 |

## 코드 예제

```python
import rospy
from sensor_msgs.msg import JointState

def joint_state_callback(msg):
    for name, pos, vel, eff in zip(msg.name, msg.position, msg.velocity, msg.effort):
        print(f"관절: {name}, 각도: {pos:.3f} rad, 속도: {vel:.3f}, 토크: {eff:.3f}")

rospy.init_node('robot_monitor')
rospy.Subscriber('/joint_states', JointState, joint_state_callback)
rospy.spin()
```

## Summary (요약)

로봇 제어기는 **HW(연산 보드·모터 드라이버·센서 인터페이스·통신 모듈·전원/안전 회로·I/O 보드)** 와 **SW(OS 계층-저수준 제어 계층-미들웨어/통신 계층-응용/관리 계층)** 가 결합된 시스템이다. 모니터링 툴은 저수준 제어 계층에서 생성되는 실시간 상태 데이터를 응용 계층에서 주기적으로 수집·표시하는 역할을 하며, 이를 위해서는 제어기의 구조(중앙집중형/분산형/계층형), 실시간성(RT/Non-RT), 통신 방식(필드버스/네트워크/시리얼)에 따른 특성 차이를 정확히 파악해야 한다.

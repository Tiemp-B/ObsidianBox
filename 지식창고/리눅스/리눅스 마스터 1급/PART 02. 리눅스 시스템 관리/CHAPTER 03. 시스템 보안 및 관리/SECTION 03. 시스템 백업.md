# 1. 백업의 개요
## 필요성
- 비즈니스 연속성
- 데이터의 중요성
- 시스템 장애 복구

## 백업의 요건
- 다양한 데이터 손실 요인으로부터 복구
- 정상 상태로의 복구
- 최소한의 노력, 비용, 데이터 손실만을 허용하는 백업 전략
- 초기 백업 구축 이후 관리를 최소로 하는 자동화/반자동화된 백업 전략 및 시스템
## 백업 전략의 고려사항
- 백업의 대상
	- 데이터
	- 시스템
	- 프로그램
	- 등
- 백업의 위치
	- 로컬 백업
		- 보조 저장 장치에 데이터를 저장하여 보관
	- 오프사이트 백업
		- 클라우드, 원격 시스템 등 지리적으로 떨어진 곳에 보관
- 백업의 주기
	- OS의 경우 OS의 업그레이드 시
	- 애플리케이션의 경우 실행 빈도에 따른 데이터 변경 주기
	- 사용자 데이터의 경우 해당 데이터의 라이프 사이클 반영
- 적용할 백업의 유형
	- 전체 백업
		- 시스템, 디스크 등의 모든 대상을 모두 백업
		- 간단하고 확실함
		- 기존과 동일한 데이터도 백업하므로 공간적 비효율 발생
	- 증분 백업
		- 변경된 데이터만 백업 : a1, a2, a3
		- 공간 효율적
		- 전체 백업과 변경 데이터 모두가 있어야 복원 가능
	- 차등 백업
		- 변경된 데이터만 백업을 이전 백업 데이터이 포함시킨다
		- a = a + new
- 백업의 압축과 암호화
	- 전송여부
	- 민감 정보에 대한 암호화
- 백업의 검증
	- 모의 복원, 백업 유틸리티 등
- 백업 유틸리티 및 서비스
	- 휴먼 에러에 대한 예방으로 백업 유틸리티를 이용하여 자동화된 백업 서비스 구축

# 4. 네트워크 백업
## rsync
[[rsync]]는 네트워크로 연결된 컴퓨터의 파일들을 동기화하는 도구
### 특징
- 속도가 빠름
- 로컬 컴퓨터와 다른 원격의 호스트, 원격 셸, rsync 데몬 간의 파일 복사 가능
- 파일 지정의 유연한 방식
- 델타 전송 알고리즘을 적용하여 네트워크 전송 속도 향상
	- [[델타 전송]] 알고리즘: 파일간 차이점 계산하여 전송
- 반복되는 백업 및 미러링 등의 작업에 사용

### 기능
- 다양한 속성 복사 : 파일 링크, 장치, 소유자, 그룹, 권한
- 제외 기능 : GNU tar와 유사한 제외 기능 제공
- 예외 기능 : CVS(Concurrent Versions System, 중앙 집중식 버전 관리 )무시기능 과 
- 원격 셸
- 사용자 권한
- 파이프라인 전송
- 익명 및 사용자 인증
